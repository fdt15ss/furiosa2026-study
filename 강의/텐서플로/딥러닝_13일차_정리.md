# Keras CNN 학습 정리

업로드한 실습 코드(`keras36~39`)를 기반으로 CNN 구현 시 알아야 할 핵심 개념을 정리했습니다.

---

## 1. Conv2D 기본 파라미터

```python
Conv2D(filters, kernel_size, strides=1, padding="valid", activation=None, input_shape=(h,w,c))
```

| 파라미터 | 의미 | 비고 |
|---|---|---|
| `filters` | 다음 레이어로 넘길 특성맵(채널) 개수 | 첫 번째 위치 인자 |
| `kernel_size` | 필터(커널) 크기, 예: `(2,2)`, `(3,3)` | 두 번째 위치 인자 |
| `strides` | 필터가 이동하는 보폭 | 기본값 1, `(2,1)`처럼 세로/가로 다르게 지정 가능 |
| `padding` | `"valid"`(기본, 패딩 없음) / `"same"`(출력 크기를 입력과 동일하게 0으로 패딩) | |
| `input_shape` | `(height, width, channels)` — **모델의 첫 레이어에서만** 지정 | `keras37` 파일처럼 `input_shape`를 잘못된 위치(`Sequential(keras.Input())`)에 넣으면 에러남 → `Conv2D(..., input_shape=(5,5,1))` 형태로 첫 Conv2D에 넣는 게 정석 |

### 출력 크기 계산 공식
```
output = floor((input + 2*padding - kernel_size) / strides) + 1
```
- `keras38_padding_stride0.py` 예시
  - `input_shape=(10,10,1)`, `kernel=(2,2)`, `padding="same"`, `strides=(2,1)` → 출력 `(5,10,10)`
  - 그다음 `kernel=(3,3)`, `padding="valid"`(기본값), `strides=1` → 출력 `(8,8,9)`
- `keras36_cnn3_mnist.py`
  - `input_shape=(28,28,1)` → `Conv2D(64,(3,3))` → `(26,26,64)`
  - → `Conv2D(32,(3,3))` → `(24,24,32)`
  - → `Conv2D(32,(2,2))` → `(23,23,32)` (Dropout은 shape에 영향 없음)
  - 이런 식으로 커널 사이즈가 커지거나 padding이 없으면 매 층마다 가로/세로가 줄어듦

## 2. MaxPooling2D
```python
model.add(MaxPooling2D((2,2)))
```
- Conv2D 다음에 넣어서 특성맵의 가로/세로 크기를 줄이고(다운샘플링) 연산량 감소 + 과적합 방지
- `(2,2)`면 가로/세로를 각각 절반으로 줄임 (`keras39_Maxpooling.py` 참고)

## 3. 데이터 전처리 (스케일링)

두 가지 방식 중 하나를 선택해서 사용 (동시에 쓰면 안 됨):

| 방법 | 코드 | 결과 범위 |
|---|---|---|
| MinMax | `x = x / 255.` | 0 ~ 1 |
| MaxAbs (직접 구현) | `x = (x - 127.5) / 127.5` | -1 ~ 1 |

- `keras36_cnn3_mnist.py`는 MinMax(0~1)를, 나머지(`fashion`, `cifar10`, `cifar100`)는 MaxAbs(-1~1)를 사용 — 둘 다 유효한 정규화 방식이며 상황에 따라 선택

### 흑백 이미지는 채널 차원 reshape 필요
```python
x_train = x_train.reshape(-1,28,28,1)  # mnist, fashion_mnist (원본이 (N,28,28)이라 채널 차원 없음)
```
- 반면 cifar10/cifar100은 원본이 이미 `(N,32,32,3)`이라 reshape 불필요

## 5. 모델 구성 패턴 (4개 데이터셋 공통)

```
Conv2D → (Dropout) → Conv2D → (Dropout) → ... → Flatten → Dense → (Dropout) → ... → Dense(softmax)
```
- Conv2D를 여러 층 쌓고 중간중간 `Dropout(0.2~0.3)`으로 과적합 억제
- `Flatten()`으로 1차원 벡터로 변환 후 Dense 레이어 연결
- 출력층은 클래스 개수만큼 `Dense(units, activation="softmax")`
  - mnist/fashion/cifar10 → 10개 클래스
  - cifar100 → 100개 클래스

## 6. 컴파일 & 학습

```python
model.compile(loss="categorical_crossentropy", optimizer="adam", metrics=["acc"])

es = EarlyStopping(monitor="val_loss", mode="min", patience=50, restore_best_weights=True)

history = model.fit(x_train, y_train, verbose=2, epochs=2000, batch_size=256,
                     validation_split=0.2, callbacks=[es])
```
- `EarlyStopping`
  - `monitor="val_loss"`: 검증 손실 기준
  - `mode="min"`: 낮을수록 좋은 지표이므로 최소값 기준
  - `patience`: 개선 없이 버틸 에폭 수
  - `restore_best_weights=True`: 학습 종료 시 가장 좋았던 시점의 가중치로 복원
- `epochs`는 크게 잡고(2000) EarlyStopping이 실제 종료 시점을 결정하도록 하는 패턴

## 9. reshape 동작 원리 (상세)

### 9-1. reshape는 "재배열"이 아니라 "재해석"
reshape은 메모리에 저장된 숫자들의 순서를 그대로 두고, 그걸 몇 차원으로 묶어서 읽을지만 바꾸는 연산. 데이터 값 자체는 하나도 안 바뀜.

```python
a = np.array([1,2,3,4,5,6])   # shape: (6,)

a.reshape(2,3)   # [[1,2,3],[4,5,6]]
a.reshape(3,2)   # [[1,2],[3,4],[5,6]]
a.reshape(6,1)   # [[1],[2],[3],[4],[5],[6]]
```
같은 6개의 숫자를 "몇 개씩 끊어서 몇 줄로 볼 것인가"만 다르게 한 것. 값 순서만 지켜지면 어떤 shape으로든 바꿀 수 있지만, **전체 원소 개수는 반드시 동일**해야 함(6개짜리를 8칸으로 바꾸면 에러).

### 9-2. mnist에서 `reshape(-1,28,28,1)`이 필요한 이유
```python
x_train.shape                          # (60000, 28, 28)
x_train = x_train.reshape(-1,28,28,1)
x_train.shape                          # (60000, 28, 28, 1)
```
- mnist 원본은 흑백이라 `(이미지 개수, 세로, 가로)`뿐이고 채널 차원이 아예 없음
- `Conv2D`는 무조건 `(batch, height, width, channels)`인 4차원을 요구
- 흑백이니 채널 수 1개를 맨 뒤에 끼워 넣는 것 (784 = 28×28×1이라 개수가 같아서 가능)
- cifar10/cifar100은 원본부터 `(N,32,32,3)`으로 채널이 이미 있어서 reshape 불필요

### 9-3. `-1`의 의미
`-1`은 "이 자리 숫자는 알아서 계산해"라는 뜻.
```python
x_train.reshape(-1, 28, 28, 1)
```
전체 원소 개수는 `60000×28×28`로 정해져 있고, 뒤의 `28,28,1`을 지정했으니 앞자리는 자동으로 `60000`이 됨. 데이터 개수가 바뀌어도 코드를 안 고쳐도 되는 장점. **`-1`은 한 자리에만 사용 가능** (두 곳에 쓰면 계산 불가로 에러).

### 9-4. reshape ≠ transpose
reshape은 값의 "순서"를 유지한 채 shape 껍데기만 바꾸는 것이지, 축을 서로 바꾸는(transpose) 것이 아님.
```
원본 2x3: [[1,2,3],[4,5,6]]   → 메모리 순서: 1,2,3,4,5,6
reshape(2,3,1): [[[1],[2],[3]],[[4],[5],[6]]]   ← 순서 그대로, 각 값이 [값] 하나짜리로 감싸짐
```
`(height, width)` → `(width, height)`처럼 축 자체를 바꾸고 싶다면 reshape이 아니라 `transpose`/`permute`를 써야 함(reshape으로 하면 값이 원래와 다르게 섞임).

### 9-5. 한 줄 요약
- reshape = 같은 숫자들을 다른 "상자 크기"로 다시 담는 것 (값 순서 유지, 총 개수 동일해야 함)
- `-1` = 나머지 계산은 numpy에게 맡긴다는 뜻
- CNN에서 reshape이 필요한 이유 = Conv2D가 요구하는 4차원 `(batch, h, w, channel)`을 맞추기 위해
- reshape ≠ transpose : 축을 바꾸는 게 아니라 차원 경계만 바꾸는 것

## 10. 주의할 점 / 다음에 확인해볼 것
- `keras37_cnn_기냥.py`의 `Sequential(keras.Input())` 사용법은 비정상적 — `keras.Input(shape=...)`를 첫 레이어로 넣거나, 첫 `Conv2D`에 `input_shape`를 주는 방식이 일반적
- padding `"same"` vs `"valid"` 차이, stride 값에 따른 출력 크기 계산은 시험/면접에서 자주 나오는 개념이므로 공식 암기 권장
- MinMax vs MaxAbs 스케일링은 activation 함수(특히 tanh 계열)와의 궁합에 따라 선택 기준이 달라질 수 있음
