## 1. Softmax 함수 심화 — 왜 지수(exponential)를 쓰는가

### 기본 원리 복습

- 출력값 세 개(예: 1, 2, 7)가 있을 때, 단순히 **각 값을 전체 합으로 나누는 방식**도 생각해볼 수 있다.

$$
\frac{1}{1+2+7} = 0.1,\quad \frac{2}{1+2+7} = 0.2,\quad \frac{7}{1+2+7} = 0.7
$$

- 이렇게만 해도 합이 1이 되긴 하지만, **변별력이 약하다** — 값들 사이의 격차가 비율 그대로만 반영돼서 크게 벌어지지 않는다.

### 왜 거듭제곱(지수)을 쓰는가

- 소프트맥스는 실제로는 각 값을 **밑(보통 자연상수 e, 이해를 위해 2로 예시)의 거듭제곱**으로 바꾼 다음 정규화한다.

$$
softmax(z_i) = \frac{e^{z_i}}{\sum_j e^{z_j}}
$$

- 값을 지수에 넣으면:
  - **큰 값은 기하급수적으로 더 커진다** (2¹, 2², 2⁷ → 2, 4, 128)
  - **작은 값은 상대적으로 소멸에 가깝게 작아진다**
- 예: 1, 2, 7을 그대로 나눌 때보다, 2¹, 2², 2⁷로 바꿔서 나누면(2/134, 4/134, 128/134) **가장 큰 값 쪽으로 훨씬 더 확실하게 쏠린다** — 변별력이 커진다.
- 부가 효과: 지수 함수는 **항상 양수**를 반환하므로, 음수 값이 있어도 전부 양수로 자동 변환된다는 장점도 있다.
- 결론적으로 "다 더한 값으로 나눈다"는 원리는 같지만, **거듭제곱을 거쳐서 큰 값을 더 크게, 작은 값을 더 작게 만든 뒤** 정규화한다는 게 핵심.

### 소프트맥스 → argmax의 흐름 (복습 + 구체화)

1. 신경망 마지막 층에서 나온 원값(logit)이 예: `[1, 2, 7]`
2. Softmax를 통과하면 `[0.1, 0.2, 0.7]`처럼 **합이 항상 1인 확률 분포**로 변환
3. 원-핫 인코딩된 정답(`[0, 1, 0]` 등)과 비교하려면, 예측값에서 **가장 큰 값의 위치**를 찾아 1로, 나머지는 0으로 처리해야 함 → 이게 `np.argmax()`
4. `argmax`로 비교했을 때 맞았는지 틀렸는지 판정 → loss 계산 → 역전파로 가중치 갱신

## 2. Cross Entropy(크로스 엔트로피) — 이름의 유래

### 핵심 아이디어

- Binary/Categorical Cross Entropy의 수식에는 target(정답, T 또는 Y)이 **0 또는 1**로 들어간다.
- T=0이면 수식의 한쪽 항이 통째로 사라지고, T=1이면 반대쪽 항이 사라진다 — 마치 **"엇갈려서(cross) 한쪽만 살아남는"** 구조.
- 이런 "정답값에 따라 한쪽이 죽고 한쪽만 사는" 특징 때문에 **Cross Entropy(교차 엔트로피)**라는 이름이 붙었다.
- 지금 단계에서는 수식을 완벽히 암기할 필요는 없고, **"왜 크로스라는 이름이 붙었는지" 정도의 직관**만 가지고 있으면 충분하다.
- **결론(암기 사항)**: 이진분류는 무조건 `binary_crossentropy`, 다중분류는 무조건 `categorical_crossentropy`.

## 3. 이진분류 데이터를 다중분류로 풀 수도 있다 (실전 유연성)

- 라벨이 2개뿐인 데이터라도, **굳이 이진분류 방식(sigmoid + binary_crossentropy)을 쓰지 않고 다중분류 방식(softmax + categorical_crossentropy)으로도 풀 수 있다.**
- 물론 일반적으로는 이진분류가 연산량이 적어 더 효율적이므로 시그모이드를 쓰는 게 정석이지만, **"2개짜리는 무조건 이진분류여야 한다"는 고정관념에 갇히면 안 된다.**
- 실무에서도 "2개짜리인데 어떻게 다중분류가 되냐"며 모르는 선임들이 실제로 존재한다 — 유연하게 사고하는 것이 실력 차이를 만든다.

## 4. `XW + B` vs `WX + B` — 행렬 연산에서 순서는 절대적으로 중요하다

### 핵심 결론

> **딥러닝의 실제 연산은 `y = wx + b`가 아니라 `y = xw + b`다.** (관용적으로 `wx+b`라고 말하고 쓰지만, 엄밀히는 틀린 표현)

### 왜 그런가 — 행렬 곱셈의 순서 규칙

- 스칼라(1개 값)끼리의 곱셈은 순서를 바꿔도 결과가 같다(`3×5 = 5×3`).
- 하지만 **행렬(Matrix) 곱셈은 순서가 바뀌면 완전히 다른 결과가 나오거나 아예 계산이 불가능**하다.
- 실제 신경망 연산에서 **입력(X)이 먼저 들어가고, 그 다음 가중치(W)와 곱해지는 구조**로 진행된다 — 데이터 흐름상 X → W 순서.
- 만약 X가 매우 큰 차원(예: 100차원)이라면, W의 shape도 그에 맞춰 정교하게 맞춰져 있어야 한다. 순서를 거꾸로 하면(`W × X`) shape이 맞지 않아 **에러가 발생**한다.
- 그래서 정확한 표기는 `y = XW + B`. 다만 강의·설명에서는 이해하기 쉽게 관용적으로 `WX+B`라고 계속 말하게 된다 — **이해의 편의를 위한 "선의의 거짓말"**이고, 실제 코드/연산 내부에서는 `XW`가 맞다.

## 5. `model.summary()` — 파라미터 개수 계산의 원리

### 왜 확인하는가

- 모델의 파라미터(가중치+편향) 총 개수를 알면:
  - 모델이 너무 크면(느리면) → 레이어/노드 수를 줄여야 한다는 판단 근거
  - 모델이 너무 작으면(성능이 안 나오면) → 레이어/노드 수를 늘려야 한다는 판단 근거
- 파이토치에서도 동일한 개념(파라미터 총합 확인)이 존재한다.

### 파라미터 개수 계산 공식 (반드시 암기)

> **파라미터 개수 = (이전 레이어의 노드 수 + 1) × 현재 레이어의 노드 수**

- `+1`을 bias 자리로 미리 넣어준 다음 통째로 곱하는 방식이다. 왜 `+1`을 먼저 해주고 곱하는지, 그리고 왜 "3이 아니라 4"가 되는지를 아래에서 하나씩 풀어본다.

### 왜 이런 공식이 나오는가 — bias를 "입력값이 항상 1인 가상의 노드"로 생각하기

- 노드 하나의 연산은 `y = w1x1 + w2x2 + ... + b` 형태다. 여기서 bias(b)는 X와 곱해지지 않고 **그냥 더해지는 항**처럼 보이지만, 사실은 **"입력값이 항상 1로 고정된 가상의 입력 노드 하나"**가 더 있고, 거기에 곱해지는 가중치가 bias라고 생각하면 정확히 맞아떨어진다.

$$
y = w_1x_1 + w_2x_2 + b = w_1x_1 + w_2x_2 + (w_{bias} \times 1)
$$

- 즉 이전 레이어의 노드가 2개(x1, x2)라면, 실제로는 **"항상 1을 출력하는 bias 노드"까지 포함해서 3개의 입력**이 다음 레이어 노드 하나와 연결되는 셈이다. 그래서 이전 노드 수에 `+1`을 해주는 것이다.
- 이 `(이전 노드 수 + 1)`짜리 입력 묶음이, 다음 레이어의 노드 각각과 **전부(Fully Connected) 하나씩 새로 연결**된다. 그래서 마지막에 **현재 레이어의 노드 수**를 곱한다.

### 예시로 "왜 3이 아니라 4인가" 확인하기

`Dense(3) → Dense(1)` 구간, 즉 이전 레이어 노드가 3개, 다음 레이어 노드가 1개인 경우:

- 이전 노드 3개(x1, x2, x3) + bias 노드 1개 = **입력 4개**
- 이 4개가 다음 레이어의 노드 1개에 각각 가중치 하나씩으로 연결됨: `y = w1x1 + w2x2 + w3x3 + w4(×1)`
- 그래서 파라미터는 `w1, w2, w3, w4` 총 **4개** — bias 하나를 "가중치 취급"해서 자연스럽게 +1이 되는 것이지, 이전 노드 수(3)에 억지로 숫자를 더 얹는 게 아니다.
- 이렇게 만들어진 연결 하나하나가 다음 레이어의 노드 개수만큼 반복되므로 마지막에 노드 개수를 곱해준다.

### `Dense` 레이어 구성 `(1 → 3 → 4 → 3 → 1)` 전체 계산

| 연결 구간 | 이전 노드 수 | +1(bias) | 다음 노드 수 | 계산식 | 파라미터 수 |
|---|---|---|---|---|---|
| Input(1) → Dense(3) | 1 | 2 | 3 | 2 × 3 | 6 |
| Dense(3) → Dense(4) | 3 | 4 | 4 | 4 × 4 | 16 |
| Dense(4) → Dense(3) | 4 | 5 | 3 | 5 × 3 | 15 |
| Dense(3) → Dense(1) | 3 | 4 | 1 | 4 × 1 | 4 |
| **Total** | | | | | **41** |

- `model.summary()`의 `Total params`가 이 계산값(41)과 일치하는지 직접 검증하는 습관을 들이면, 모델 구조를 제대로 이해하고 있는지 스스로 점검할 수 있다.
- 정리하면: **"이전 노드 수 × 다음 노드 수"는 순수 가중치 연결의 개수이고, 거기에 다음 레이어 노드 하나당 bias 1개씩이 추가로 붙는다.** `(이전+1)×다음` 공식은 이 둘을 한 번의 곱셈으로 처리한 것뿐, 원리는 동일하다.

## 6. `input_dim` vs `input_shape` — 언제 무엇을 쓰는가

### `input_dim` — 2차원(벡터/행렬) 데이터 전용

```python
model.add(Dense(64, input_dim=4))   # 컬럼(feature) 개수만 명시
```

- 데이터가 `(N, 4)`처럼 2차원일 때는, 첫 번째 값(행의 개수, N)은 무시하고 **열(컬럼) 개수만** 정수로 넣어주면 된다.

### `input_shape` — 3차원 이상 데이터, 또는 더 명시적인 표현

```python
model.add(Dense(64, input_shape=(4,)))     # 2차원 데이터: (4,) 벡터 형태로 명시
model.add(Dense(64, input_shape=(100, 3))) # 3차원 데이터 (시계열 등)
model.add(Dense(64, input_shape=(100, 100, 3)))  # 4차원 데이터 (이미지 등)
```

- **원칙**: 전체 데이터 shape에서 **맨 앞(전체 개수, 행의 개수)을 제외한 나머지**를 그대로 튜플로 써준다.
- `input_dim=4`와 `input_shape=(4,)`는 **완전히 동일한 의미**다 — 2차원 데이터에서는 둘 다 사용 가능.
- 3차원 이상(시계열 데이터, 이미지 데이터 등)은 **`input_shape`만 사용 가능**하다 (`input_dim`으로는 표현 불가능).

### 차원별 데이터 구조 예시

| 차원 | 예시 | shape 표현 |
|---|---|---|
| 2차원 | 일반 표 형태(행×열) 데이터 | `(N, 4)` → `input_dim=4` 또는 `input_shape=(4,)` |
| 3차원 | 시계열 데이터(주가, 코인 가격 등 — 시간에 따라 값이 변화) | `(N, 100, 3)` → `input_shape=(100, 3)` |
| 4차원 | 이미지 데이터(전체 장수, 세로, 가로, 컬러채널) | `(N, 100, 100, 3)` → `input_shape=(100, 100, 3)` |

- 이미지 데이터의 컬러 채널 3은 **빛의 3원색(RGB: Red, Green, Blue)**을 의미하며, 이 세 가지 조합으로 모든 색을 표현할 수 있다.
- 각 픽셀의 값은 보통 0~255 범위(0=검정, 255=가장 밝음)로 표현된다.
- 지금까지 배운 4차원 이상은(동영상 등 5차원) 실전에서 거의 다루지 않는다는 것이 강사의 경험담.

## 7. 데이터 스케일링(Scaling) — 왜 필요한가

### 오버플로우 문제

- 데이터 값의 스케일이 매우 크면(예: 10억 단위), 신경망 연산(순전파의 곱셈+덧셈 반복, 역전파의 가중치 갱신)을 거치며 값이 기하급수적으로 커져서 **오버플로우(Overflow)**가 발생할 수 있다.
- 컴퓨터가 다룰 수 있는 부동소수점(float) 자릿수에는 한계가 있다 — 이 한계를 넘으면 계산이 깨지거나 비정상적인 값이 나온다.
- 이런 문제를 예방하기 위해 **데이터를 작은 범위(특히 0~1 사이의 소수)로 조정**하는 작업이 스케일링이다.
- 부동소수점 연산은 **곱해도 절대 1을 넘지 않는 소수끼리의 연산**이라 오버플로우 위험이 현저히 낮다.

### 왜 "조작"이 아닌가 — 핵심 원칙

> **X 데이터 전체에 동일한 비율(기준)로 스케일을 적용하면, Y(타겟)와의 대응 관계(패턴)는 전혀 훼손되지 않는다.**

- 원리: X를 100, 1000, 10 등으로 나눠도, "이 값이 이 Y와 짝을 이룬다"는 관계 자체는 유지된다. 모델은 결국 X와 Y의 **관계(패턴)**를 학습하는 것이지, X의 절대적인 숫자 크기를 학습하는 게 아니다.
- **주의**: X 데이터 중 일부만 다른 비율로 나누면(예: 어떤 값은 50으로, 어떤 값은 100으로) 이건 진짜 데이터 조작이자 오염이 된다. **반드시 전체 데이터에 동일한 기준을 적용**해야 한다.

## 8. Min-Max Scaling — 가장 기본적인 스케일링 기법

### 수식

$$
X_{scaled} = \frac{X - X_{min}}{X_{max} - X_{min}}
$$

- 원값에서 **최솟값을 빼고**, 그 결과를 **(최댓값 - 최솟값)으로 나눈다.**
- 이렇게 하면 결과값은 항상 **0(최솟값이었던 자리)에서 1(최댓값이었던 자리) 사이**로 딱 맞게 수렴한다.
- 단순히 최댓값으로만 나누는 방식은 최솟값이 0이 아닐 때 결과가 0부터 시작하지 않는 문제가 있다 — 그래서 최솟값을 먼저 빼주는 보정이 필요하다.

### Sklearn 코드

```python
from sklearn.preprocessing import MinMaxScaler

scaler = MinMaxScaler()
scaler.fit(x)          # 스케일링 기준(min, max)을 계산해서 준비만 함
x = scaler.transform(x)  # 실제로 값을 변환

# 위 두 줄은 fit_transform()으로 합칠 수 있다
x = scaler.fit_transform(x)
```

- `.fit()` = 스케일 기준(최소/최대값)을 파악만 하는 단계, 실제 변환은 일어나지 않는다.
- `.transform()` = 앞서 파악한 기준으로 실제 값을 변환하는 단계.
- 변환 후 확인:

```python
import numpy as np
print(np.min(x), np.max(x))   # 최소값 0.0, 최대값 1.0 근처(부동소수점 오차로 1.0000000002 등으로 보일 수 있음)
```

> 부동소수점 연산 특성상 `0.1 + 0.2`가 정확히 `0.3`이 아니라 `0.30000000000000004`처럼 나오는 것과 같은 원리로, `np.max()` 결과가 정확히 `1.0`이 아니라 아주 미세하게 다르게 나올 수 있다. 이는 오류가 아니라 부동소수점 표현 방식(2진수 기반)의 특성이다.

## 9. 스케일링의 진짜 핵심 함정 — Train/Test 분리 순서

### 잘못된 방식 (흔한 실수)

```python
# 잘못된 순서: 전체 데이터를 한꺼번에 스케일링한 뒤 나눔
scaler = MinMaxScaler()
x = scaler.fit_transform(x)   # 전체 X를 통으로 스케일링

x_train, x_test = train_test_split(x, ...)  # 그 다음에 나눔
```

- 이렇게 하면 겉보기엔 문제없어 보이고 실제로 돌아가기도 하지만, **원칙적으로 틀린 방식**이다.
- 이유: **Test 데이터가 스케일링 기준(min/max)을 정하는 과정에 "간접적으로 참여"**하게 된다. Test는 훈련에 전혀 관여하지 않아야 하는데(모의고사 개념), 스케일링 기준을 정할 때 이미 test의 정보가 섞여 들어간 것 — 이는 **과적합(overfitting)의 한 형태**이자 데이터 유출(data leakage)에 해당한다.

### 올바른 방식

```python
x_train, x_test, y_train, y_test = train_test_split(x, y, ...)

scaler = MinMaxScaler()
scaler.fit(x_train)              # 기준은 반드시 train 데이터로만 잡는다
x_train = scaler.transform(x_train)
x_test = scaler.transform(x_test)  # test는 transform만! fit 하지 않는다
```

> **절대 원칙: `fit()`은 오직 train 데이터에만 적용한다. test(또는 향후 예측할 새 데이터)는 절대 fit 하지 않고, train 기준으로 `transform()`만 적용한다.**

### 그 결과 test 데이터의 값이 0~1 범위를 벗어날 수 있다

- train의 최소/최대값을 기준으로 test를 변환하면, test의 실제 값 범위가 train과 다를 경우 **test 스케일 결과가 0보다 작거나 1보다 클 수 있다.**
- 이건 **정상이며 오히려 바람직한 현상**이다. Test가 train의 범위 안에 완전히 갇혀버리는 것보다, train이 경험하지 못한 값의 영역이 test에 존재하는 편이 **더 현실적인 일반화 성능 검증**이 된다.
- 시험에 빗대면: 모의고사(test)가 본 적 없는 새로운 유형의 문제를 포함하는 게 정상이지, 배운 것만 그대로 나오면 진짜 실력을 검증할 수 없다는 것과 같은 논리.

### 검증(validation) 데이터와 예측(predict)할 새 데이터도 동일 원칙

- `validation_split`으로 분리되는 검증 데이터, 그리고 나중에 실제로 예측하고 싶은 새로운 데이터 모두 **train 기준으로 transform만** 적용해야 한다.
- 여러 단계(train, val, test, predict용 신규 데이터)에 각각 다른 기준으로 스케일링하면 안 되고, **하나의 통일된 기준(train의 min/max)에 전부 맞춘다.**

## 10. 스케일링 효과가 항상 좋은 것은 아니다 — 실전적 태도

- 스케일링을 적용했다고 **반드시 성능이 좋아지는 건 아니다.** 데이터셋에 따라 오히려 나빠질 수도 있다.
- 실전 전략: 여러 데이터셋에 스케일링을 적용해보고, **일부(예: 10개 중 1~2개)에서만 성능이 향상돼도 그건 성공**으로 간주한다. 모든 케이스에서 만능으로 좋아지는 전처리 기법은 없다.
- **원칙적 판단 순서**: ① 스케일링 없이 성능 확인 → ② 전체 데이터를 통으로 스케일링했을 때 성능 확인 → ③ train만 기준으로 제대로 분리해서 스케일링했을 때 성능 확인 → 매번 결과를 기록하고 비교한다.
- 하이퍼파라미터 자동 탐색(AutoML류)도 존재하지만, 모든 조합을 다 시도하는 방식이라 조합 수가 많아지면(예: epoch 3종류 × batch_size 3종류 × scaler 5종류 = 45가지) 그만큼 시간과 자원이 배로 든다 — 결국 사람이 실험하고 기록하는 훈련이 여전히 중요하다.

---

## 11. 실무 팁 · 태도

- **항상 이전 실험 결과를 코드 하단에 주석으로 남겨두는 습관**이 중요하다 — 다음 스케일링 기법을 추가할 때마다 기존 대비 향상 여부를 비교하기 위한 필수 기록.
- 손코딩(면접에서 컴퓨터 없이 직접 모델 구조를 종이에 쓰거나 구두로 설명하는 것) 훈련이 중요 — AI 도구 없이도 구조를 이해하고 있는지가 실력의 진짜 척도.
- 데이터가 지저분(결측치, 이상치, 스케일 문제 등)하다고 가정하고 접근하는 습관 — "좋은 데이터가 올 것"이라는 기대를 버리고 항상 전처리를 우선순위에 둔다.
- 이상치(outlier)가 있는 상태에서 Min-Max 스케일링을 하면, 극단값 하나 때문에 나머지 정상 데이터가 전부 매우 작은 값으로 몰려버릴 수 있다 — 이상치는 스케일링 이전에 별도로 처리해야 하는 문제.

## 부록 — 파라미터 개수 계산 실전 예제

```python
from tensorflow.keras.models import Sequential
from tensorflow.keras.layers import Dense

model = Sequential()
model.add(Dense(3, input_dim=1))   # (1×3)+3 = 6
model.add(Dense(4))                # (3×4)+4 = 16
model.add(Dense(3))                # (4×3)+3 = 15
model.add(Dense(1))                # (3×1)+1 = 4
# Total params = 6+16+15+4 = 41

model.summary()   # Total params가 41인지 직접 검증
```

## 부록 — 올바른 스케일링 전체 코드 템플릿

```python
import numpy as np
from tensorflow.keras.models import Sequential
from tensorflow.keras.layers import Dense
from tensorflow.keras.callbacks import EarlyStopping
from sklearn.model_selection import train_test_split
from sklearn.preprocessing import MinMaxScaler
from sklearn.metrics import r2_score

# ===== #1 데이터 =====
x_train, x_test, y_train, y_test = train_test_split(
    x, y, train_size=0.8, random_state=337
)

# 스케일링: train 기준으로만 fit!
scaler = MinMaxScaler()
scaler.fit(x_train)
x_train = scaler.transform(x_train)
x_test = scaler.transform(x_test)   # test는 transform만

print(np.min(x_train), np.max(x_train))   # 0.0, 1.0 근처
print(np.min(x_test), np.max(x_test))     # 0~1 범위를 벗어날 수 있음 (정상)

# ===== #2 모델 =====
model = Sequential()
model.add(Dense(64, input_dim=x.shape[1], activation='relu'))
model.add(Dense(32, activation='relu'))
model.add(Dense(1))

# ===== #3 컴파일 · 훈련 =====
model.compile(loss='mse', optimizer='adam')
es = EarlyStopping(monitor='val_loss', patience=20, mode='min',
                    restore_best_weights=True)
model.fit(x_train, y_train, epochs=1000, batch_size=32,
          validation_split=0.2, callbacks=[es], verbose=1)

# ===== #4 평가 · 예측 =====
loss = model.evaluate(x_test, y_test)
y_predict = model.predict(x_test)
r2 = r2_score(y_test, y_predict)
print("loss:", loss, "R2:", r2)

model.summary()   # 파라미터 개수 직접 확인 및 검증
```
