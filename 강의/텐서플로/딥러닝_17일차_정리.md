## 1. 데이터 증폭 (Data Augmentation) 복습

### 1-1. `ImageDataGenerator` 기본 흐름 (`keras50_flow2_next.py`)
```python
datagen = ImageDataGenerator(
    rescale=1./255,
    horizontal_flip=True,
    width_shift_range=0.1,
    height_shift_range=0.1,
    rotation_range=20,
    zoom_range=0.1,
    fill_mode="nearest",
)

xy_data = datagen.flow(
    np.tile(x_train[0].reshape(28*28), augment_size).reshape(-1, 28, 28, 1),
    np.zeros(augment_size),
    batch_size=augment_size,
    shuffle=False,
).next()
```
- `np.tile()`로 이미지 1장을 `augment_size`만큼 복제한 뒤 `flow()`에 넣으면, 같은 원본에서 서로 다르게 변형된 이미지 묶음을 얻을 수 있음(증폭 원리 확인용).
- `.next()`를 호출하면 `(x, y)` 튜플이 반환되며 `xy_data[0]`이 이미지 배치.

### 1-2. 실전 증폭 — 랜덤 샘플 기반 (`keras51_augment1_fashion.py`)
```python
randidx = np.random.randint(x_train.shape[0], size=augment_size)
x_augmented = x_train[randidx].copy()
y_augmented = y_train[randidx].copy()

x_augmented = datagen.flow(
    x_augmented.reshape(-1, 28, 28, 1),
    y_augmented,
    batch_size=augment_size,
    shuffle=False,
).next()[0]
```
- 전체 데이터에서 `augment_size`개를 무작위 인덱스로 뽑아 증폭 → 원본과 별도로 관리.
- **주의**: `randidx`는 랜덤 복원 추출이라 중복 인덱스가 나올 수 있음(수업 중 언급). 학습용 데이터라면 문제 없지만, 정확히 "중복 없는 서로 다른 샘플"이 필요하면 `np.random.choice(..., replace=False)`를 고려.
- `.copy()`를 꼭 붙여야 원본 배열이 아닌 복사본을 증폭 처리함(원본 오염 방지).

### 1-3. 증폭 데이터 병합
```python
x_train = x_train.reshape(-1, 28, 28, 1)
x_test = x_test.reshape(-1, 28, 28, 1)

x_train = np.concatenate((x_train/255., x_augmented))
y_train = np.concatenate((y_train, y_augmented))
x_test = x_test/255.
```
- **핵심 원칙**: `x_test`(평가용 원본 데이터)는 증폭하지 않고 그대로 유지 — 성능을 왜곡 없이 평가하기 위함.
- `x_train`만 정규화(`/255.`) 후 증폭분과 합쳐서 최종 학습 데이터셋 구성.

## 1-4. `flow()` 메소드 자세히 보기

`ImageDataGenerator.flow()`는 이미 메모리에 올라와 있는 NumPy 배열 형태의 이미지 데이터를 받아서, 설정된 증강(augmentation) 옵션을 적용하며 배치 단위로 이미지를 계속 생성해주는 제너레이터를 만드는 메소드.

**기본 형태**
```python
datagen.flow(
    x,                  # 이미지 데이터 (numpy array, shape: (샘플수, height, width, channel))
    y=None,             # 라벨 데이터 (선택)
    batch_size=32,       # 한 번에 몇 장씩 묶어서 낼지
    shuffle=True,        # 매 에폭마다 섞을지 여부
)
```
- `x`는 **반드시 4차원**이어야 함: `(N, H, W, C)`. 흑백 이미지라면 채널 차원을 꼭 넣어줘야 함(`reshape(-1, 28, 28, 1)`처럼).
- 반환값은 `NumpyArrayIterator`라는 **제너레이터(이터레이터) 객체**. 리스트처럼 바로 인덱싱해서 쓸 수 없고, `next()`를 호출하거나 `for` 루프로 순회해야 실제 데이터가 나옴.

**`flow_from_directory()`와의 차이**
- `flow()`: 이미 배열로 로드된 데이터를 증강할 때 사용 (오늘 코드처럼 `fashion_mnist.load_data()`로 이미 x_train이 메모리에 있는 경우).
- `flow_from_directory()`: 폴더 구조(클래스별 하위 폴더)에서 이미지 파일을 직접 읽어오면서 증강할 때 사용. 대용량 이미지 데이터셋에서 메모리에 다 올리지 않고 배치 단위로 디스크에서 읽어올 때 씀.

**`.next()`의 동작**
```python
xy_data = datagen.flow(x, y, batch_size=100, shuffle=False).next()
```
- `flow()`는 매번 호출될 때마다 `batch_size`만큼 **랜덤하게 증강된** 이미지 배치를 만들어냄. `.next()`를 호출하는 순간 그 배치 1개가 실제로 생성됨.
- 반환값은 `(x_batch, y_batch)` 튜플. 그래서 `xy_data[0]`이 이미지 배치, `xy_data[1]`이 라벨 배치.
- 같은 `datagen.flow(...)`를 다시 `.next()` 하면 **매번 다르게 변형된** 이미지가 나옴(rotation, shift 등이 매 호출마다 랜덤하게 적용되기 때문). 그래서 오늘 코드에서 `np.tile()`로 같은 이미지를 여러 장 복제해도 `.next()`를 통과하면 전부 다르게 찌그러진 버전이 되는 것.

**`batch_size`와의 관계**
- `flow()`를 만들 때 지정한 `batch_size`가 한 번의 `.next()` 호출에서 나오는 이미지 개수를 결정함.
- 오늘 코드에서는 `augment_size`(4만 개)를 통째로 `batch_size`로 넣어서 `.next()` 한 번으로 4만 장을 한꺼번에 뽑아낸 것 — 원래는 학습 루프에서 `model.fit(datagen.flow(...))`처럼 계속 배치를 흘려보내며 쓰는 게 일반적인 사용법이지만, 여기선 "미리 증강해서 원본과 합쳐두는" 방식으로 응용한 것.

**`shuffle=False`를 쓴 이유**
- 오늘 코드처럼 `x`와 `y`를 같이 넣고 나중에 인덱스 순서를 맞춰서 확인해야 할 때는 `shuffle=False`로 둬서 입력 순서와 출력 순서가 같게 유지함. 학습에 바로 쓸 게 아니라 "증강 결과를 검증하거나 별도로 저장"할 목적이면 순서를 흐트러뜨리지 않는 게 안전함.

## 2. 라벨(Y) 기준 데이터 필터링 — Boolean Indexing

수업에서 다룬 패턴 (예: 특정 라벨 조건에 맞는 X만 추출):
```python
# Y_train이 0보다 큰 데이터만 X_train에서 골라내기
x_selected = x_train[y_train > 0]
y_selected = y_train[y_train > 0]
```
- 조건식 `y_train > 0`이 불리언(Boolean) 배열이 되고, 이를 인덱스로 사용하면 조건에 맞는 행만 골라짐 — NumPy의 **불리언 마스킹(Boolean Masking)** 기법.
- 이후 `np.unique(y_selected, return_counts=True)`로 라벨별 개수를 확인해서 필터링이 의도대로 됐는지 검증하는 흐름이 반복적으로 등장.

## 3. 학습/평가 데이터 분리 원칙

- `train_test_split`으로 나눈 뒤, **테스트 데이터는 이후 어떤 변형(증폭·셔플 등)도 가하지 않음** — 평가 시 실제 성능을 왜곡 없이 확인하기 위한 원칙으로 여러 번 강조됨.
- 증폭은 항상 학습(train) 쪽에만 적용하고, 마지막에 `train`과 `augmented`를 합쳐서 최종 학습셋을 구성.

## 4. 메모리 부족(OOM) 대처 순서

수업에서 정리된 순서:
1. **데이터 크기 축소** (이미지 해상도, 채널, 샘플 수 줄이기)

## 5. 순전파 / 역전파 손계산 예제

간단한 선형 모델 `y_hat = W*x + b`로 순전파·역전파를 손으로 계산하는 연습:

- **조건**: `x=1`, `y=3`(정답), `W=0.1`, `b=0.1`
- **순전파**: `y_hat = W*x + b = 0.1*1 + 0.1 = 0.2`
- **손실함수(MSE)**: `loss = (y - y_hat)^2` (배치 1개 기준, `Σ/N`에서 N=1)
- **역전파(가중치 갱신)**:
  ```
  W_new = W_old - learning_rate * dLoss/dW
  dLoss/dW = 2*(y_hat - y)*x   (체인룰: MSE 미분 → y_hat 미분)
  ```
- 핵심은 **체인룰(Chain Rule)**을 이용해 `Loss → y_hat → W` 순서로 미분을 연쇄적으로 계산한다는 것.

### Loss-Weight 관계 그래프
- 특정 데이터셋에서는 Loss가 최소가 되는 지점이 하나로 정해져 있으며(예제에서는 `W=3`일 때 Loss=0), 이 지점이 **최적의 가중치(Optimal Weight)**.
- 이 관계를 그래프로 그리면 보통 아래로 볼록한 포물선 형태 → **경사하강법(Gradient Descent)**이 이 최저점을 찾아가는 과정.

## 6. Learning Rate와 Local/Global Minima

- **Learning Rate가 너무 작으면**: 학습(에폭)을 아주 많이 돌려도 성능이 계속 천천히 좋아지기만 하고 수렴이 느림.
- **Learning Rate가 너무 크면**: 최적점을 지나쳐 진동하거나 발산할 수 있음.
- **Local Minima vs Global Minima**: 손실 함수가 여러 골짜기(지역 최소값)를 가질 수 있고, 학습이 지역 최소값에 갇혀 전역 최소값을 못 찾는 경우가 있음 — Learning Rate 스케줄링(적절히 줄여가는 방식)이 이를 완화하는 데 도움.
- 결론: Learning Rate는 모델 성능에 큰 영향을 주는 하이퍼파라미터이며, 값에 따라 성능이 좋아질 수도, 나빠질 수도 있음 — 고정된 정답은 없고 실험적으로 조정.

## 7. Fashion-MNIST CNN 모델 구조 정리 (`keras51_augment1_fashion.py`)

```python
model = Sequential()
model.add(Conv2D(32, (3,3), input_shape=x_test[0].shape, activation="relu"))
model.add(Dropout(0.2))
model.add(Conv2D(64, (3,3), activation="relu"))
model.add(Dropout(0.3))
model.add(Conv2D(128, (2,2), activation="relu"))
model.add(MaxPooling2D((2,2)))
model.add(Dropout(0.2))
model.add(Conv2D(64, (2,2), activation="relu"))
model.add(Conv2D(32, (2,2), activation="relu"))
model.add(Dropout(0.2))
model.add(GlobalAveragePooling2D())
model.add(Dense(units=64, activation="relu"))
model.add(Dropout(0.2))
model.add(Dense(units=16, activation="relu"))
model.add(Dense(10, activation="softmax"))
```

- `GlobalAveragePooling2D()`를 `Flatten()` 대신 사용 → 파라미터 수를 크게 줄이면서 특징맵을 압축.
- 여러 층에 `Dropout`을 분산 배치해 과적합 방지.
- 컴파일: `categorical_crossentropy` + `adam` + `metrics=["acc"]` (다중 클래스 분류 표준 조합).

### 콜백 구성
```python
es = EarlyStopping(monitor='val_loss', mode="min", patience=20, restore_best_weights=True)
mcp = ModelCheckpoint(filepath=save_path, monitor='val_loss', mode='auto', save_best_only=True)
```
- `EarlyStopping`과 `ModelCheckpoint`를 함께 써서, 과적합 방지 + 가장 좋은 가중치 자동 저장을 동시에 처리.
- `save_path`에 `datetime.now()`로 타임스탬프를 넣어 학습마다 파일이 겹치지 않도록 함.

## 8. 오늘의 핵심 요약

| 주제 | 핵심 포인트 |
|---|---|
| 데이터 증폭 | train만 증폭, test는 원본 유지 |
| `flow()` | 배열 데이터를 배치 단위로 랜덤 증강해 생성하는 이터레이터, `.next()`로 배치 획득 |
| 라벨 필터링 | `y_train > 0` 같은 불리언 마스킹으로 조건별 데이터 추출 |
| OOM 대처 | 데이터 크기 축소 → 배치 사이즈 축소 순서 |
| 역전파 | Loss → y_hat → W 체인룰로 미분, `W -= lr * dLoss/dW` |
| Learning Rate | 너무 작으면 느림, 너무 크면 발산/진동, Local/Global Minima에 영향 |
| 모델 구조 | GlobalAveragePooling2D + 분산 Dropout으로 과적합 억제 |
