## 3. 시계열 예측: 예측 구간이 길어지면?

- 100일까지의 데이터로 101일 **하나만** 예측하는 것은 비교적 쉬움.
- 101~106일처럼 **여러 스텝을 예측**하면 뒤로 갈수록 오차가 누적되어 성능이 떨어짐.
- 지표 기준 예시: **loss 0.1 이하**를 목표로 잡음.
- RNN 계열의 한계
  - 시간이 지날수록 앞쪽 기억이 **희석(소실)**됨 → 날짜가 늘어날수록 예측이 틀어짐
  - 데이터 양도 부족하면 잘 안 맞음 → **최소 10~100배 정도의 데이터**가 있어야 성능이 좋아짐

## 4. LSTM 여러 층 쌓기 (핵심)

### 4-1. 왜 에러가 나는가

- LSTM 출력은 기본적으로 `(batch, units)` **2차원**.
- 다음 LSTM은 `(batch, timesteps, features)` **3차원** 입력을 원함.
- 그래서 그냥 쌓으면 "3차원을 원했는데 2차원을 줬다"는 shape 에러 발생.

### 4-2. 해결: `return_sequences=True`

- 각 timestep의 출력을 모두 다음 층으로 넘겨서 **timestep 차원을 유지**.
- 출력 shape: `(batch, timesteps, units)` → 다음 LSTM에 그대로 연결 가능.
- 마지막 LSTM 층은 `return_sequences=False`(기본값)로 두거나, `Flatten`을 사용해도 됨.

```python
from tensorflow.keras.models import Sequential
from tensorflow.keras.layers import LSTM, Dense

model = Sequential()
model.add(LSTM(10, return_sequences=True, input_shape=(timesteps, features)))  # 3차원 유지
model.add(LSTM(10, return_sequences=True))                                     # 3차원 유지
model.add(LSTM(10))                                                            # 마지막은 2차원 출력
model.add(Dense(1))
```

### 4-3. Flatten 방식

- LSTM 한 층(또는 마지막 층)에서 `return_sequences=True`로 출력한 뒤 `Flatten`으로 펴서 Dense에 연결하는 방법도 가능.
- 어려우면 한 단, 두 단, 세 단으로 쌓으면서 **성능을 비교**해보는 것이 목표.

```python
from tensorflow.keras.layers import Flatten

model = Sequential()
model.add(LSTM(10, return_sequences=True, input_shape=(timesteps, features)))
model.add(Flatten())
model.add(Dense(1))
```

### 4-4. 층 개수 실험

- 2단 / 3단 / 5단 / 10단 / 20단 등 **개수를 바꿔가며 성능 비교** (선택지가 하나 더 생김).
- 이전 실습(SimpleRNN, LSTM, GRU 등)과 성능을 비교.
- 무조건 층을 많이 쌓는다고 좋은 것은 아님. 좋은 성능은 **예상치 못한 곳에서** 나올 수 있으므로 특정 모델에 종속되지 말고 다양하게 실험.
- SimpleRNN도 성능이 안 좋을 때가 많지만 가끔 좋을 때가 있으므로 LSTM/GRU와 함께 비교해 볼 가치가 있음.

### 4-5. 파라미터 수 계산

- 층 shape, `units` 개수로 파라미터 수를 직접 계산해 볼 수 있어야 함.
- `model.summary()`로 계산값과 대조해 보기.

## 5. Jena 시계열 실습 (10분 간격 데이터)

### 5-1. 데이터 특징

- 독일 Jena 기후 데이터, **10분 간격**, 컬럼 **14개**, 약 42만 행 규모
- 목표: **마지막 하루(2016-12-30 ~ 12-31)의 `wd (deg)`(풍향)**을 예측

### 5-2. timestep 계산

- 10분 간격 → 1시간에 6개 → 24시간이면 **6 × 24 = 144개**
- 즉 하루치 = **144 timesteps**

### 5-3. 데이터 분리 규칙 (중요)

| 구분 | 내용 |
|---|---|
| 제출/테스트 구간 | 마지막 하루(144개)는 **훈련에 절대 포함 X** (넣으면 성능이 비정상적으로 잘 나옴 = 누수) |
| 훈련 데이터 | 뒤에서 144개를 잘라낸 나머지 |
| 입력 X | 144개씩 잘라서 만든 시퀀스 |
| 타겟 y | X 구간 다음의 값(`wd`) |

- 학습 시에는 144개씩 잘라 시퀀스로 만들어 학습.
- 타겟 컬럼은 입력에 넣어도 되고 빼도 됨 (뺀 쪽이 차라리 나을 수 있음).

### 5-4. 시계열 split 함수 개념

```python
import numpy as np

def split_xy(dataset, timesteps, y_column):
    x, y = [], []
    for i in range(len(dataset) - timesteps):
        x.append(dataset[i : i + timesteps])          # 입력: timesteps 길이의 구간
        y.append(dataset[i + timesteps, y_column])    # 정답: 그 다음 시점의 값
    return np.array(x), np.array(y)
```

## 6. 스케일링 시 주의사항 (데이터 누수 방지)

1. 먼저 **train / test 분리**
2. **train으로만 `fit`** 한 스케일러로 train, test 모두 `transform`
3. 시계열 데이터는 3차원 → 스케일링 전 **2차원으로 reshape** 후 스케일링하고, 다시 원래 shape으로 복원

```python
from sklearn.preprocessing import StandardScaler

scaler = StandardScaler()
x_train = scaler.fit_transform(x_train.reshape(-1, features)).reshape(-1, timesteps, features)
x_test  = scaler.transform(x_test.reshape(-1, features)).reshape(-1, timesteps, features)
```

- 데이터 자체를 스케일링하지 않으면 학습이 잘 안 됨.
- 처음부터 전체 데이터에 scaler를 fit하면 누수가 발생.

## 7. 메모리 터짐(OOM) 대처법

### 7-1. 순서대로 시도

1. **메모리 할당 설정**을 먼저 걸어둠 (GPU 메모리 증가 허용 / 메모리 할당기 변경 등)
2. 그래도 터지면 **`batch_size` 줄이기** (64 → 32 → 16 → ...)
3. 배치 1인데도 터지면 → 하드웨어(GPU) 교체 또는 **데이터 자체를 줄이기**

### 7-2. 실전 팁

- 이 설정은 **TensorFlow를 import 하기 전(코드 맨 위)**에 넣어야 적용됨 (환경 변수 방식은 import 후에는 안 먹음).
- 처음에는 일부러 주석 처리해서 **터지는 경험**을 해보는 것도 실력 향상에 도움이 된다고 함.
- 다른 프로그램(음성 인식/Whisper 같은 CPU·메모리를 쓰는 앱)이 돌아가고 있으면 함께 메모리를 차지해서 터질 수 있음 → **종료 후 재시도**.
- `numpy` 배열 생성/저장 중 터지는 것은 **CPU 메모리** 문제일 수 있음 → 재부팅, 다른 앱 종료, 데이터를 나눠서 처리 후 합치기 (예: 분할 → 병합, `split` 후 처리).

```python
import os
# ⚠️ tensorflow import 보다 위에 위치해야 함
os.environ["TF_GPU_ALLOCATOR"] = "cuda_malloc_async"   # 예시: 메모리 할당기 설정

import tensorflow as tf
```

> 녹취에서 정확한 환경 변수 이름이 인식되지 않아(“TFG, CPU, Allocator …”), 대표적인 설정인 `TF_GPU_ALLOCATOR`를 예시로 적었습니다. 실제 수업 자료(코드)의 설정 값을 확인해 주세요.
