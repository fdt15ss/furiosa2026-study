## 1. train/test 분리를 다시 강조하는 이유

- 통데이터(train 전체)로만 훈련하고 그 데이터로 다시 평가하면 **R2 0.99, loss 0.001**처럼 비정상적으로 좋은 값이 나온다. 이건 실력이 아니라 **자기 데이터에 대한 암기(과적합)**.
- 이 상태로 회사에 "완벽한 모델입니다" 하고 납품하면, 실제 데이터에 적용하는 순간 R2가 0.5~0.6으로 뚝 떨어져 계약이 깨질 수 있다.
- 그래서 데이터를 **랜덤하게 25~30% 잘라 test로 분리**한다. 이건 성능을 올리는 작업이 아니라 **객관적 검증**을 위한 작업이다.
- 판단 기준: 통데이터 결과만 보고 "좋다"고 결론 내리지 말고, 반드시 **분리된 test로 확인**해야 한다.

## 2. 경로(Path) 완전정리

### 상대경로 vs 절대경로

| 구분 | 설명 | 예시 |
|---|---|---|
| **상대경로** | 현재 작업 중인 워크스페이스(폴더) 기준 | `./_data/train.csv` |
| **절대경로** | 드라이브 루트부터 전체 경로 명시 | `C:/study/_data/train.csv` |

- `.` = VS Code 기준 현재 워크스페이스(스터디 폴더)
- **팀 작업 시 주의**: 팀원마다 워크스페이스 루트가 다르면 상대경로 코드는 에러가 난다. 협업 시엔 경로 통일이 중요.
- 문제 발생 원인 3대장: **① 오타 → ② 경로 → ③ 버전**

### 슬래시 종류 — 전부 가능하지만 규칙이 있다

```python
path = './_data/따릉이/'      # 슬래시(/) - 가능
path = '.\\_data\\따릉이\\'    # 백슬래시 두 개(\\) - 가능
path = '.\_data\따릉이\'       # 백슬래시 한 개(\) - 위험!
```

- `/`(슬래시), `\\`(백슬래시 두 개)는 항상 안전.
- **백슬래시 한 개(`\`)는 위험** — `\n`(줄바꿈), `\t`(탭) 같은 **예약어**와 겹치면 의도치 않게 해석된다.
- 초보일 때는 **백슬래시 두 개(`\\`)** 로 안전하게 쓰는 걸 권장. 섞어 쓰는 것도 가능은 하지만 가독성이 떨어져 권장하지 않는다.

## 3. 열/컬럼 관련 동의어 — 완전 암기

> **열 = 컬럼(Column) = 특성 = 속성 = 피처(Feature) = 어트리뷰트(Attribute)**

전부 같은 뜻. 데이터의 "특성이 몇 개냐" = "컬럼이 몇 개냐"와 같은 말이다. 이만큼 반복 강조하는 이유: **행(row)의 개수는 모델 구조에 영향을 주지 않지만, 열(column)의 개수는 모델의 input_dim을 결정**하기 때문이다.

- `.shape` 결과에서 행 개수는 `num`으로 뭉뚱그려 표시되고(예: `(1459, 10)`), 실제로 중요한 건 뒤의 열 개수.
- train과 test는 **행 개수가 달라도 문제없다** (990개든 100개든), 단 **열 개수는 반드시 같아야** predict가 가능하다.

## 4. Pandas 결측치 처리 — 삭제 외의 방법들

### 4-1. 결측치 확인하는 여러 방법

```python
train_csv.info()                 # Non-Null Count로 확인
train_csv.isna().sum()           # 컬럼별 결측치 개수 합산
train_csv.isnull().sum()         # isna와 동일 (null = 결측치)
train_csv.describe()             # 통계 요약 (평균, 최대/최소 등으로 이상치도 함께 확인)
```

- `.describe()`로 각 컬럼의 min/max를 보면 **이상치 존재 여부**도 짐작할 수 있다. 예: season 컬럼의 max가 4면 이상치 없음(1~4만 존재).

### 4-2. 결측치를 삭제할 수 없는 경우 — 평균값으로 채우기

**test.csv는 절대 dropna 하면 안 된다.** 이유:
- test.csv와 submission.csv는 **id(순번)가 1:1로 대응**되어 있다.
- test에서 행을 삭제하면 예측값과 submission 순서가 어긋나버린다.
- → **살려야 하는 데이터는 평균값 등으로 채워서 보존**해야 한다.

```python
test_csv = test_csv.fillna(test_csv.mean())
```

| 결측치 처리법 | 용어 |
|---|---|
| 행을 통째로 삭제 | `dropna()` |
| 특정 값으로 채우기 | `fillna()` |
| 평균값 | `test_csv.mean()` |

> 결측치 처리 방법은 10가지 이상 존재하며, 완벽한 처리는 하루를 통째로 써야 할 만큼 깊은 주제다. 지금 단계에서는 **train은 삭제, test는 평균으로 채우기** 정도로 감을 잡으면 된다.

## 5. 인덱스는 데이터가 아니다 (복습 + 비유)

- 학생 40명에게 1~40번을 매겼다고 해서 40번 학생이 1번 학생보다 40배 가치 있는 게 아니다. **번호(인덱스)는 그냥 라벨일 뿐 데이터가 아니다.**
- 반면 실제 자산(지갑에 든 돈)처럼 **의미 있는 수치**는 데이터다.
- 그래서 `index_col=0`으로 인덱스를 데이터에서 제외시켜야 한다.

## 6. Kaggle 컴피티션 실습 — Bike Sharing Demand

### 6-1. train / test 컬럼 차이 이해하기

| 파일 | 컬럼 |
|---|---|
| train.csv | datetime, season, holiday, workingday, weather, temp, atemp, humidity, windspeed, **casual, registered, count** (12개) |
| test.csv | 위에서 casual, registered, count **3개 없음** (9개) |

- `casual`(비회원 대여) + `registered`(회원 대여) = `count` 라는 관계가 있다. 하지만 test에는 이 두 값이 없어 예측에 활용할 수 없다.
- → **train에서도 casual, registered를 함께 drop**해서 test와 컬럼 개수를 맞춰야 한다.

```python
x = train_csv.drop(['casual', 'registered', 'count'], axis=1)   # 리스트로 여러 컬럼 동시 삭제
y = train_csv['count']
```

> **두 개 이상의 컬럼을 drop할 때는 리스트(`[]`)로 묶어서 전달한다.**

### 6-2. 전체 작업 흐름 (복습)

```
1. import (numpy, pandas, keras, sklearn 등)
2. 경로 설정 → train/test/submission 읽기 (index_col=0)
3. shape, info(), describe(), isna().sum()으로 데이터 확인
4. 결측치 처리 (train: dropna / test: fillna(mean))
5. x, y 분리 (casual, registered, count 모두 drop)
6. train_test_split
7. 모델링 → 컴파일(loss='mse') → 훈련
8. 평가: model.evaluate, RMSE 함수
9. model.predict(test_csv) → submission['count']에 대입
10. submission.to_csv(경로, index=False)
11. Kaggle/Dacon에 업로드하여 점수 확인
```

### 6-3. CSV로 저장하기 — `to_csv`

```python
submission_csv['count'] = y_submit
submission_csv.to_csv(path + 'submit/' + 'submission_0904_1141.csv')
```

- 불러올 때는 `read_csv`, 저장할 때는 **`to_csv`**.
- 파일명에 날짜·시간을 넣어두면 나중에 실험 이력을 구분하기 좋다. (자동화는 추후 배울 예정)

## 7. 대회에서 요구하는 평가지표가 낯설 때 — 유사 지표 전략

- Kaggle Bike Sharing Demand의 공식 평가지표는 **RMSLE**(Root Mean Squared **Logarithmic** Error).

$$
RMSLE = \sqrt{\frac{1}{n}\sum_{i=1}^{n}(\log(y_i+1) - \log(\hat{y}_i+1))^2}
$$

- **로그를 씌우는 이유**: 오차 값 자체가 너무 커서(연산 시 오버플로 위험) 로그로 스케일을 줄인다. 예: 10 → log 1, 100 → log 2, 1000 → log 3.
- **+1을 더하는 이유**: `log(0)`은 정의되지 않아 마이너스 무한대로 발산한다. 0이 존재할 수 있는 데이터이므로 0을 만들지 않기 위해 1을 더한다.
- **로그 변환의 핵심 원칙**: 한쪽에 로그를 씌웠으면 **관련된 모든 데이터에 동일한 비율로** 씌워야 한다. (x든 y든 일부만 변환하면 안 됨)

### 낯선 지표를 만났을 때의 실전 전략

> **`model.compile(loss='rmsle')`처럼 직접 지정할 수 없는 지표는 컴파일에 넣을 수 없다.**
> → 대신 **유사한 지표(MSE)로 훈련**시키고, 그중 **가장 좋은 결과를 제출**하면 된다.
> → 유사 알고리즘은 서로 함께 좋아지고 함께 나빠지는 경향이 있어, 정확한 지표를 몰라도 실용적으로 대응 가능하다.
> → 실제 채점은 대회 서버가 알아서 RMSLE로 계산해준다. 우리는 로컬에서 RMSE로 판단하면 충분.

## 8. 오버플로(Overflow) 주의

- 숫자 스케일이 너무 크면(예: 10조 단위) 연산 중 **오버플로**가 발생해 계산이 멈추거나 이상한 값이 나올 수 있다.
- 신경망은 곱셈·덧셈의 연속이기 때문에, 값이 크면 클수록 그 위험이 누적된다.
- **로그 변환(log transform)**은 데이터 스케일을 줄여 이런 문제를 예방하는 전처리 기법 중 하나다.
- 몇 시간 훈련시키다가 오버플로로 멈춰버리는 경우도 실제로 있다 — 큰 스케일의 데이터를 다룰 때는 항상 염두에 둘 것.

## 9. Public / Private 리더보드

- 실제 대회는 점수가 하나가 아니라 **Public**과 **Private** 두 개로 나뉜다.
- 대회 진행 중에는 **Public 점수만 공개**되고, Private는 대회 종료 후 공개된다.
- 마지막 제출 파일을 고를 때 **Public 점수만 보고 "제일 좋아 보이는 것"을 고르면 함정에 빠질 수 있다.** (Public에서 과적합된 제출이 Private에서 순위가 폭락하는 사례가 실제로 있었음 — 1등이 4,000등으로 추락한 사례)
- **판단 원칙**: 로컬 검증 점수와 제출 점수가 크게 어긋나 판단이 안 설 때는 **로컬(자신의 검증 결과)을 믿는 것이 안전할 수 있다.** 다만 이건 절대 법칙이 아니라 상황에 따라 다르다 — 많은 경험을 통해 감을 길러야 하는 영역.

## 10. 활성화 함수(Activation Function) — ReLU

### 왜 필요한가

- 신경망은 기본적으로 **곱셈과 덧셈의 반복**이다 (`y = wx + b`를 층마다 반복).
- 최초 가중치는 매우 작은 값(때로 음수)으로 초기화되기 때문에, 층을 거치며 **음수가 누적되어 최종 출력이 음수**가 될 수 있다.
- 그런데 우리가 원하는 출력(예: 자전거 대여 수 count)은 **절대 음수가 될 수 없는 값**이다. 이럴 때 결과값에 `abs()` 같은 수치 보정을 가하면, 그건 AI 모델링이 아니라 **수치 조작**으로 간주되어 대회에서 실격 처리될 수 있다.
- → 모델 자체가 양수만 뽑아내도록 구조적으로 제한해야 한다. 이 역할을 하는 것이 **활성화 함수(= 한정 함수)**.

### ReLU (Rectified Linear Unit)

$$
ReLU(x) = \max(0, x)
$$

- **x가 0 이상이면 그대로 통과, x가 0 미만이면 0으로 만들어버린다.**
- Default 활성화 함수는 `linear`(그대로 통과, 아무 제한 없음).
- ReLU를 각 은닉층(hidden layer)에 적용하면:
  - 음수가 층을 거치며 누적되는 문제를 해결
  - 역전파(backpropagation) 시 효율이 좋아 학습 성능도 향상됨
  - 강사 체감상 "85점짜리"였던 기본 모델이 ReLU 적용 후 "95점짜리" 수준으로 좋아짐

### 코드 적용

```python
model = Sequential()
model.add(Dense(64, input_dim=8, activation='relu'))
model.add(Dense(32, activation='relu'))
model.add(Dense(16, activation='relu'))
model.add(Dense(1))                      # 마지막 층은 보통 activation 지정 안 함 (linear가 기본)
```

- **어느 레이어에 붙여도 상관없다** — 각 층마다 자유롭게 붙이거나 뺄 수 있는 **하이퍼파라미터 튜닝 요소**다.
- **마지막 출력층에는 보통 ReLU를 넣지 않는다** (관례). 다만 이번처럼 출력이 반드시 0 이상이어야 하는 경우(count 예측)엔 마지막 층에 넣어도 이론상 문제는 없다.
- ReLU는 회귀뿐 아니라 이미지·비전 분야(CNN)에서 더 많이 쓰이는 활성화 함수다. 지금은 이해하기 쉬운 수치 데이터로 개념을 먼저 익히는 것.

## 11. 하이퍼파라미터 튜닝 요소 총정리 (5일차 기준)

| 단계 | 튜닝 가능한 요소 |
|---|---|
| #1 데이터 | `random_state`, `train_size`(또는 `test_size`) |
| #2 모델 | 레이어의 깊이(층 수), 노드(뉴런)의 개수, **활성화 함수(activation)** |
| #3 컴파일·훈련 | `epochs`, `batch_size`, optimizer |

> 총 **6가지 이상**의 조절 지점이 있다. 이 조합을 바꿔가며 성능을 올리는 과정이 튜닝이다.

### 실험 기록(명세) 습관화 — 매우 중요

매번 파라미터를 바꿔 돌릴 때마다 **주석으로 실험 기록을 남겨야** 한다. 그렇지 않으면 어떤 조합이 최고 성능이었는지 재현할 수 없게 된다.

```python
# 1차 시도
# random_state = 337, train_size = 0.75, epochs = 50, batch_size = 32
# 결과: RMSE = 37, R2 = 0.60

# 2차 시도
# random_state = 337, train_size = 0.75, epochs = 200, batch_size = 32
# 결과: RMSE = 27, R2 = 0.67
```

- 형식은 자유지만 **원칙은 반드시 지킬 것**: 어떤 설정으로 어떤 결과가 나왔는지 기록.
- 실전에서 "1등을 했는데 어떻게 잡은 값인지 기억이 안 나서" 순위가 무너진 사례가 실제로 있었다고 함.

- **자동 저장(Auto Save)은 아직 켜지 말 것.** CSV를 실수로 건드려 저장되면 원본 데이터가 오염된다. 명시적으로 `Ctrl+S`를 습관화.
- **CSV 파일은 절대 손으로 수정하지 않는다.** VS Code의 Edit CSV 확장 등은 "보기용"으로만 사용.
- 회사 데이터는 종종 **"장난(트릭)"이 섞여 있다** — 예: 이상치, 액면분할 같은 상황을 인지하지 못하고 잘못된 값을 그대로 수집하는 경우. 데이터를 다룰 때 항상 "이 값이 진짜 맞는가?"를 의심하는 습관이 필요.
- AI 에이전트와 협업하는 시대 — 에이전트에게 데이터 수집을 맡기더라도, **명확한 지시**를 내리고 **결과를 검증**할 수 있는 지식이 있어야 한다. 모델 구조, 전처리 원리를 모르는 채로 "만들어줘"만 반복하면 결과물의 한계가 뚜렷하다.
- 논문은 "완벽한 설계도"가 아니라 **"이렇게 해봤더니 잘 됐다"는 발견의 기록**에 가까운 경우가 많다 — 실험적 태도가 AI 분야의 본질.

## 부록 — Kaggle Bike Sharing 전체 코드 템플릿

```python
import numpy as np
import pandas as pd
from tensorflow.keras.models import Sequential
from tensorflow.keras.layers import Dense
from sklearn.model_selection import train_test_split
from sklearn.metrics import r2_score, mean_squared_error

# ===== #1 데이터 =====
path = './_data/kaggle_bike/'
train_csv = pd.read_csv(path + 'train.csv', index_col=0)
test_csv = pd.read_csv(path + 'test.csv', index_col=0)
submission_csv = pd.read_csv(path + 'submission.csv', index_col=0)

print(train_csv.shape, test_csv.shape, submission_csv.shape)
print(train_csv.info())
print(train_csv.describe())

# 결측치 확인
print(train_csv.isna().sum())
print(test_csv.isna().sum())

# train은 삭제 (있다면), test는 절대 삭제 금지 → 평균으로 채움
train_csv = train_csv.dropna()
test_csv = test_csv.fillna(test_csv.mean())

# x, y 분리 (casual, registered는 test에 없으므로 함께 제거)
x = train_csv.drop(['casual', 'registered', 'count'], axis=1)
y = train_csv['count']

x_train, x_test, y_train, y_test = train_test_split(
    x, y, train_size=0.75, random_state=337
)

# ===== #2 모델 =====
model = Sequential()
model.add(Dense(64, input_dim=8, activation='relu'))
model.add(Dense(32, activation='relu'))
model.add(Dense(16, activation='relu'))
model.add(Dense(1))

# ===== #3 컴파일 · 훈련 =====
model.compile(loss='mse', optimizer='adam')
model.fit(x_train, y_train, epochs=200, batch_size=32)

# ===== #4 평가 · 예측 =====
loss = model.evaluate(x_test, y_test)
y_predict = model.predict(x_test)

def RMSE(y_test, y_predict):
    return np.sqrt(mean_squared_error(y_test, y_predict))

print("loss :", loss)
print("R2   :", r2_score(y_test, y_predict))
print("RMSE :", RMSE(y_test, y_predict))

# ===== 제출 파일 생성 =====
y_submit = model.predict(test_csv)
submission_csv['count'] = y_submit
submission_csv.to_csv(path + 'submit/' + 'submission_01.csv')
```
