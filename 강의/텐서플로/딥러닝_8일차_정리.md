## 1. 회귀 · 이진분류 · 다중분류 복습 — 모델의 전부는 이 세 가지뿐

AI 모델링은 결국 **회귀, 이진분류, 다중분류** 이 세 가지 뿐이다. 더 이상 늘어나지 않는다.

- 로지스틱 회귀(Logistic Regression)는 이름에 "Regression"이 들어가지만 **실제로는 분류(이진분류) 모델**이다. `~Regression`이라는 이름이 붙은 모델 대부분은 회귀지만, 이것만 예외라는 점을 기억해두면 면접 등에서 도움이 된다.
- `model.predict()`로 나온 값이 0~1 사이의 소수점이라도, **원값(y) 자체를 임의로 반올림(round)해서 저장하거나 조작하면 안 된다.** 반올림은 어디까지나 sklearn 같은 외부 지표에 넣기 위한 **판단 단계에서만** 적용한다. 모델링 자체의 결과값은 건드리지 않는다.

## 2. Iris(붓꽃) 데이터셋 — 다중분류의 헬로우월드

```python
from sklearn.datasets import load_iris

datasets = load_iris()
x = datasets.data      # (150, 4)
y = datasets.target    # (150,)
```

- **150개 행(Instance), 4개 컬럼(Attribute)**: sepal length, sepal width, petal length, petal width (전부 cm 단위).
- **클래스(Y의 종류)는 3개**: Setosa, Versicolor, Virginica — 각각 50개씩 균등하게 분포.
- `datasets.DESCR`을 출력하면 각 컬럼의 min/max, 표준편차(SD), **상관관계(Correlation)** 까지 상세하게 나온다. 상관관계는 나중에 매우 중요하게 다뤄지는 개념 — 두 컬럼이 상관관계가 높다고 항상 좋은 것은 아니고, 상황에 따라 좋을 수도 나쁠 수도 있다.

### Y값 먼저 확인하는 습관 (복습)

```python
import numpy as np
print(np.unique(y, return_counts=True))
# 또는
import pandas as pd
print(pd.Series(y).value_counts())
```

- 코드 한 줄만 봐도("`value_counts` 썼네" 등) 그 데이터가 분류 데이터라는 걸 짐작할 수 있을 만큼, Y값 확인은 모델링의 시작점이다.

## 3. `train_test_split`에서 shuffle을 꼭 켜야 하는 이유

```python
x_train, x_test, y_train, y_test = train_test_split(
    x, y, test_size=0.2, random_state=337, shuffle=True, stratify=y
)
```

- `shuffle=False`로 두면, 만약 데이터가 라벨별로 순서대로 정렬돼 있는 경우(Iris도 0,0,...,1,1,...,2,2... 순서), train에 특정 라벨만 몰리고 test에는 아예 안 들어가는 **최악의 상황**이 발생할 수 있다.
- 그래서 **회귀·분류 상관없이(시계열 데이터 제외) 원칙적으로 `shuffle=True`를 기본으로 유지**한다.
- 분류 데이터에는 `stratify=y`도 함께 넣어 라벨 비율까지 균등하게 맞추는 게 안전하다.

## 4. 다중분류 모델 구성 — 반드시 지켜야 하는 3가지 규칙

> **① 마지막 레이어의 activation은 반드시 `softmax`**
> **② `model.compile()`의 loss는 반드시 `categorical_crossentropy`**
> **③ 마지막 레이어의 노드(뉴런) 개수는 반드시 Y의 클래스 개수와 동일**

```python
model = Sequential()
model.add(Dense(64, input_dim=4, activation='relu'))
model.add(Dense(32, activation='relu'))
model.add(Dense(3, activation='softmax'))   # 클래스 개수 = 3

model.compile(loss='categorical_crossentropy', optimizer='adam', metrics=['acc'])
```

- 다중분류의 loss는 회귀(MSE 등 여러 선택지)나 이진분류(사실상 1가지)처럼 다양하지 않고, **`categorical_crossentropy` 하나뿐**이다.
- 마지막 레이어의 노드 개수를 클래스 개수(예: 3)로 맞추지 않으면 → `ValueError`가 발생한다. (아래 5번 참고)

---

## 5. Softmax 함수 — 다중 클래스를 위한 한정 함수

### 왜 필요한가

- 이진분류에서 Sigmoid가 0~1 사이 값 하나로 결과를 한정했다면, 다중분류에서는 **클래스 개수만큼의 출력값 전체를 한꺼번에 한정**해야 한다.
- 예: 3개 클래스라면 각 노드에서 나온 값(WX+B)을 그대로 쓰면 0.7, -1.3, 5.2 같은 제멋대로인 값이 나온다. 이를 Softmax에 통과시키면:
  - 모든 값이 **0~1 사이**로 변환된다.
  - **전체를 더하면 항상 1이 된다** (예: 0.7 + 0.2 + 0.1 = 1.0)
  - 값이 클수록 확률(비중)이 크다는 의미가 된다.
- 이후 가장 큰 값을 가진 위치를 최종 예측 클래스로 판단한다.

### 이해를 돕는 비유

- 로또/뽑기처럼 여러 선택지 중 "가장 당첨 확률이 높은 것"을 찾는 개념과 유사.

## 6. One-Hot Encoding — 다중분류 Y값 전처리의 필수 과정

### 왜 필요한가 (핵심 개념)

- Y값이 세토사=0, 버시칼라=1, 버지니카=2처럼 **단순 숫자로 라벨링**되어 있으면, 모델이 이걸 그냥 **연속된 수치**로 오해할 위험이 있다.
- 문제: 라벨 2(버지니카)가 라벨 1(버시칼라)의 2배 가치를 가진 게 아니다. 배추=0, 파=1, 상추=2로 라벨링했다고 해서 "상추 두 개 = 파 하나"라는 계산이 성립하면 안 된다. 남자=1, 외계인=2로 했을 때 "남자 두 명 = 외계인 한 명"이 아닌 것과 같다.
- 모든 클래스는 **동등한 가치**를 가져야 한다. 그래서 각 라벨을 숫자 크기가 아니라 **"위치값"**으로 표현하도록 바꾼다 — 이게 One-Hot Encoding이다.

### 변환 방식

클래스가 3개(세토사/버시칼라/버지니카)라면:

| 원래 라벨 | One-Hot 벡터 |
|---|---|
| 0 (세토사) | `[1, 0, 0]` |
| 1 (버시칼라) | `[0, 1, 0]` |
| 2 (버지니카) | `[0, 0, 1]` |

- 원본 Y의 shape이 `(150,)`였다면, One-Hot 인코딩 후에는 `(150, 3)`으로 **차원이 하나 늘어난다.**
- 클래스가 10개(예: 0~9 손글씨 숫자)면 `(N, 10)`으로, 100개면 `(N, 100)`으로 늘어난다.

### One-Hot Encoding의 치명적 단점 (중요 — LLM/임베딩까지 연결되는 개념)

- 클래스 개수가 많아질수록(예: CIFAR-100의 100개 클래스) 데이터 대부분이 **0으로 가득 채워진다.**
- 데이터 크기가 원본보다 클래스 개수만큼 커진다 — 예: 6만 개 데이터 × 100 클래스 = 600만 개 스칼라. 이 중 절대다수가 의미 없는 0.
- 결과적으로 **연산 속도 저하, 메모리 낭비(Memory Full 위험)**가 발생한다.
- 이 문제는 나중에 **LLM/임베딩(Embedding)**을 다룰 때 다시 등장하는 근본적인 한계다.
- 지금(Iris, 클래스 3개) 수준에서는 전혀 문제되지 않지만, 클래스가 수백~수만 개로 커지면 반드시 다른 방식(임베딩 등)을 고려해야 한다.

### One-Hot Encoding vs Train/Test 분리 — 순서는 상관없다

- "먼저 One-Hot 인코딩을 하고 나서 train/test를 나눌지, 먼저 나누고 나중에 인코딩할지"는 **결과에 큰 차이가 없다.**
- 실무적으로는 **원핫을 먼저 하고 통으로 자르는 게 조금 더 편하다** — 나중에 인코딩을 두 번(train용, test용) 나눠서 할 필요가 없기 때문.
- 극단적으로 데이터가 한쪽으로 쏠려 있으면 특정 클래스가 완전히 소멸될 위험이 있을 수 있지만, 일반적인 상황에서는 순서를 크게 신경 쓰지 않아도 된다.

## 7. One-Hot Encoding의 3가지 방법 (실전 비교)

### 방법 1 — TensorFlow `to_categorical` (가장 적게 쓰임)

```python
from tensorflow.keras.utils import to_categorical

y = to_categorical(y)
```

- 가장 간단하지만 **TensorFlow에 종속적**이라는 단점이 있다. PyTorch로 작업 중인데 이거 하나 쓰자고 TensorFlow를 무겁게 추가로 설치하는 건 비효율적 (두 프레임워크를 한 가상환경에 몰아넣으면 충돌 위험도 커짐).
- **치명적 함정**: `to_categorical`은 **무조건 0부터 시작한다고 가정**한다. 만약 원본 라벨이 1부터 시작하는 데이터(예: Fetch Covertype 데이터셋)에 그대로 적용하면, **존재하지 않는 "0" 클래스를 위한 빈 컬럼이 자동으로 하나 더 생겨버린다.**
  - 예: 라벨이 1~7인 데이터(7개 클래스)에 `to_categorical`을 적용하면 결과 shape이 `(N, 7)`이 아니라 `(N, 8)`이 되어버림 — 앞에 항상 0으로만 채워진 쓸모없는 컬럼이 하나 생긴다.
  - 이 빈 컬럼 때문에 **불필요한 연산**이 발생한다 (예: 데이터 50만 개면 50만 번의 낭비 연산).
  - **해결법**: 이런 경우 라벨에서 1을 빼주거나(0부터 시작하도록 맞추거나), 빈 컬럼을 슬라이싱으로 제거해야 한다.

### 방법 2 — Pandas `get_dummies`

```python
import pandas as pd

y = pd.get_dummies(y)
```

- 간결하지만 결과가 **불리언(Boolean, True/False) 타입**으로 나올 수 있다.
- Keras 모델은 대부분 True/False를 자동으로 1/0으로 인식해서 그냥 돌아가긴 하지만, **정석대로는 정수형(int)으로 명시 변환**하는 게 안전하다.

```python
y = pd.get_dummies(y, dtype='int')
```

### 방법 3 — Sklearn `OneHotEncoder` (실무에서 가장 많이 쓰임)

```python
from sklearn.preprocessing import OneHotEncoder

ohe = OneHotEncoder(sparse_output=False)   # sparse 행렬 형태 대신 일반 배열로 받기
y = y.reshape(-1, 1)                        # 반드시 2차원으로 변환 필요
y = ohe.fit_transform(y)
```

- **`OneHotEncoder`는 반드시 2차원 배열(행렬)을 입력으로 요구한다.** Y가 원래 벡터(1차원, `(150,)`) 형태이면 다음 에러가 뜬다:
  > `Expected 2D array, got 1D array instead`
  > (2차원 배열을 기대했는데 1차원 배열을 받았다)
- 그래서 `.reshape(-1, 1)`로 `(150,)` → `(150, 1)`로 바꿔줘야 한다.
- **`sparse_output=False`**를 지정하지 않으면 결과가 **Sparse Matrix(희소행렬)** 형태로 반환되어 바로 다루기 불편하다 — 반드시 `False`로 꺼줘야 일반 배열로 나온다.
- `.fit()` → 학습(어떤 값들이 있는지 파악) / `.transform()` → 실제 변환. 둘을 합친 `.fit_transform()`을 관용적으로 많이 쓴다.

## 8. `reshape` — 데이터 차원을 바꾸는 핵심 도구

### 절대 원칙 (반드시 암기)

> **reshape 전후로 ① 데이터의 값(내용)이 바뀌면 안 된다. ② 데이터의 순서가 바뀌면 안 된다.**

- 오직 **shape(모양)만** 바뀔 뿐, 안에 들어있는 값과 그 순서는 그대로 유지되어야 한다.
- 이 원칙을 어기면 "reshape"이 아니라 **데이터 조작(오염)**이 되어버린다. 예: 제출 파일의 순서가 뒤바뀌면 채점 자체가 완전히 틀어진다.

```python
y = y.reshape(-1, 1)
```

- `-1`은 "나머지는 알아서 계산해라"는 의미. 파이썬에서 배열의 맨 끝 인덱스가 `-1`인 것과 같은 원리 — 크기를 몰라도(또는 매번 하드코딩하기 귀찮아도) `-1`을 쓰면 자동으로 맞춰준다.
- 예: `y.shape`이 `(150,)`일 때 `y.reshape(-1, 1)`을 하면 `-1` 자리에 150이 자동으로 채워져 `(150, 1)`이 된다.

### 차원(Dimension) 개념 정리

| 이름 | 차원 | 예시 |
|---|---|---|
| 스칼라(Scalar) | 0차원 | `5` |
| 벡터(Vector) | 1차원 | `[1, 2, 3]` |
| 행렬/매트릭스(Matrix) | 2차원 | `[[1,2],[3,4]]` |
| 텐서(Tensor) | 3차원 이상 | 이미지 데이터 등 |

- **CNN에서 다루는 이미지 데이터는 보통 4차원**: `(전체 이미지 개수, 세로, 가로, 컬러채널)`. 예: 10,000장의 100×100 RGB 이미지 → `(10000, 100, 100, 3)`.
- 지금은 2차원 데이터만 다루지만, 나중에 CNN을 배울 때 2차원 데이터를 4차원으로 reshape해야 하는 경우가 반드시 나온다 — 그때도 "값과 순서는 유지" 원칙이 그대로 적용된다.

## 9. 딕셔너리 접근 방식 — `.data`와 `['data']`는 같다

```python
datasets = load_iris()
x1 = datasets.data
x2 = datasets['data']   # 위와 완전히 동일한 결과
```

- sklearn의 데이터셋 객체는 완전한 순수 딕셔너리는 아니지만, **딕셔너리처럼 key-value 접근을 지원하도록 감싸(wrapping)져 있다.**
- 그래서 점(`.`) 표기법과 대괄호(`['key']`) 표기법 둘 다 사용 가능하다 — 어제 배운 `hist.history['loss']`와 같은 원리.

## 10. 실전 코드 — 다중분류 전체 흐름 (Iris)

```python
import numpy as np
import time
from tensorflow.keras.models import Sequential
from tensorflow.keras.layers import Dense
from tensorflow.keras.callbacks import EarlyStopping
from tensorflow.keras.utils import to_categorical
from sklearn.model_selection import train_test_split
from sklearn.metrics import accuracy_score
from sklearn.datasets import load_iris

# ===== #1 데이터 =====
datasets = load_iris()
x = datasets.data
y = datasets.target

print(np.unique(y, return_counts=True))   # Y값 확인 필수

y = to_categorical(y)   # 원-핫 인코딩: (150,) -> (150, 3)

x_train, x_test, y_train, y_test = train_test_split(
    x, y, test_size=0.2, random_state=337, shuffle=True, stratify=y
)

# ===== #2 모델 =====
model = Sequential()
model.add(Dense(64, input_dim=4, activation='relu'))
model.add(Dense(32, activation='relu'))
model.add(Dense(3, activation='softmax'))   # 클래스 개수만큼

# ===== #3 컴파일 · 훈련 =====
model.compile(loss='categorical_crossentropy', optimizer='adam', metrics=['acc'])

es = EarlyStopping(monitor='val_loss', patience=20, mode='min',
                    restore_best_weights=True)

start_time = time.time()
model.fit(x_train, y_train, epochs=1000, batch_size=8,
          validation_split=0.2, callbacks=[es], verbose=1)
end_time = time.time()

# ===== #4 평가 · 예측 =====
result = model.evaluate(x_test, y_test)
loss = result[0]
acc = result[1]

y_predict = model.predict(x_test)
y_predict = np.argmax(y_predict, axis=1)   # 다중분류는 반올림이 아니라 argmax!
y_test_arg = np.argmax(y_test, axis=1)     # 정답도 다시 정수 라벨로 변환

acc_score = accuracy_score(y_test_arg, y_predict)

print("loss:", round(loss, 4))
print("acc (tf):", round(acc, 4))
print("acc (sklearn):", round(acc_score, 4))
print("걸린시간:", round(end_time - start_time, 2), "초")
```

### `np.argmax` — 다중분류 예측값을 되돌리는 핵심 함수

- 이진분류에서는 예측값(0.5 기준)을 `np.round()`로 반올림해서 0/1로 바꿨다면, **다중분류에서는 `np.argmax()`를 사용**한다.
- `model.predict()`가 뽑아낸 결과는 `(N, 3)` 형태로 `[0.1, 0.7, 0.2]`처럼 확률 분포다.
- `np.argmax(y_predict, axis=1)`는 **각 행에서 가장 큰 값의 인덱스(위치)를 반환**한다. 예: `[0.1, 0.7, 0.2]` → 인덱스 1(가장 큰 값의 위치) 반환.
- 이렇게 해야 원래 라벨(0, 1, 2) 형태로 되돌려서 `accuracy_score`에 넣어 비교할 수 있다. **정답값(y_test)도 One-Hot 상태이므로 마찬가지로 `argmax`로 되돌려야 한다.**
- `model.evaluate()`의 accuracy는 텐서플로가 내부적으로 이 argmax 비교까지 자동으로 처리해준 값이다.

## 11. 회귀·이진분류·다중분류 최종 비교표

Shop(#1 데이터 → #2 모델 → #3 컴파일/훈련 → #4 평가/예측) 순서로 정리:

| 단계 | 회귀 | 이진분류 | 다중분류 |
|---|---|---|---|
| **#1 데이터** | 특별히 건드릴 것 없음 | 특별히 건드릴 것 없음 | **원-핫 인코딩 필수** |
| **#2 모델 — 마지막 activation** | `linear`(생략 가능, 기본값) | `sigmoid` (필수) | `softmax` (필수) |
| **#2 모델 — 마지막 노드 개수** | 자유(보통 1개) | **무조건 1개** | **클래스 개수만큼** |
| **#3 compile — loss** | `mse`, `mae`, `rmse` 등 다양 | `binary_crossentropy` (사실상 유일) | `categorical_crossentropy` (유일) |
| **#4 predict 후 처리** | 그대로 사용 (조작 불필요) | `np.round()`로 반올림 | `np.argmax(axis=1)`로 위치값 추출 |

> 데이터를 받았을 때 이 표 하나만 있으면, 회귀인지 이진분류인지 다중분류인지 판단해서 **바로 모델링에 들어갈 수 있다.** 성능은 별개 문제지만, 최소한 "돌아가는 모델"은 즉시 구성 가능해진다.

## 12. 실무 팁 · 습관

- **에러가 뜨면 겁먹지 말고 순서대로 읽는다**: ① 에러가 뜬 라인 번호 확인 → ② 메시지 끝부분(핵심 에러 타입/설명)을 읽는다. 중간 스택트레이스는 무시해도 된다.
- **`.shape` 확인은 매번 습관화**: reshape이나 인코딩 등 데이터를 변형한 직후에는 반드시 `.shape`을 찍어서 의도한 대로 바뀌었는지 확인한다.
- **AI 도구(ChatGPT 등)에 의존하지 않고 직접 검색해서 찾아보는 연습**을 강조 — 초반 학습 단계에서 이 훈련이 실력을 좌우한다는 반복된 강조.
- **변수명과 함수명이 같아도 실제 메모리 위치는 다르다** — 이름이 겹쳐도(가독성을 위해 일부러 비슷하게 짓는 경우) 파이썬 내부적으로는 독립적으로 처리되므로 실무에서도 흔히 보이는 패턴.
- 코드 복습은 **직접 타이핑하며 반복**하는 것이 가장 효과적 — 단순 복사보다 손으로 직접 치는 습관을 권장.

## 부록 — One-Hot Encoding 3가지 방법 요약

```python
# 방법 1: TensorFlow (가장 간단하지만 프레임워크 종속적, 0-based 필수)
from tensorflow.keras.utils import to_categorical
y = to_categorical(y)

# 방법 2: Pandas (간단, 결과가 bool일 수 있음 → dtype 지정 권장)
import pandas as pd
y = pd.get_dummies(y, dtype='int')

# 방법 3: Sklearn (실무에서 가장 흔함, 2차원 입력 필수)
from sklearn.preprocessing import OneHotEncoder
ohe = OneHotEncoder(sparse_output=False)
y = y.reshape(-1, 1)
y = ohe.fit_transform(y)
```

## 부록 — 전체 코드 템플릿 (다중분류)

```python
import numpy as np
import time
from tensorflow.keras.models import Sequential
from tensorflow.keras.layers import Dense
from tensorflow.keras.callbacks import EarlyStopping
from tensorflow.keras.utils import to_categorical
from sklearn.model_selection import train_test_split
from sklearn.metrics import accuracy_score
from sklearn.datasets import load_iris

# 데이터
datasets = load_iris()
x, y = datasets.data, datasets.target
print(np.unique(y, return_counts=True))

y = to_categorical(y)

x_train, x_test, y_train, y_test = train_test_split(
    x, y, test_size=0.2, random_state=337, shuffle=True, stratify=y
)

# 모델
model = Sequential()
model.add(Dense(64, input_dim=x.shape[1], activation='relu'))
model.add(Dense(32, activation='relu'))
model.add(Dense(y.shape[1], activation='softmax'))   # 클래스 개수 자동 반영

# 컴파일 & 훈련
model.compile(loss='categorical_crossentropy', optimizer='adam', metrics=['acc'])
es = EarlyStopping(monitor='val_loss', patience=20, mode='min',
                    restore_best_weights=True)

start = time.time()
model.fit(x_train, y_train, epochs=1000, batch_size=8,
          validation_split=0.2, callbacks=[es], verbose=1)
end = time.time()

# 평가 & 예측
loss, acc = model.evaluate(x_test, y_test)
y_predict = np.argmax(model.predict(x_test), axis=1)
y_test_label = np.argmax(y_test, axis=1)

print("loss:", round(loss, 4))
print("acc:", round(acc, 4))
print("accuracy_score:", accuracy_score(y_test_label, y_predict))
print("시간:", round(end - start, 2), "초")
```
