## 1. 왜 컬럼별로(feature-wise) 스케일링해야 하는가 — 핵심 원리 복습

### 스케일링 없이 여러 컬럼을 그대로 쓰면 생기는 문제

- 예시: 키(180), 몸무게(60), 연봉(10억)을 X 데이터로 쓴다고 하자.
- 신경망의 첫 연산은 `w1×키 + w2×몸무게 + w3×연봉 + b`. 초기 가중치가 모두 같은 값(예: 0.1)이라면, 연산 결과는 **연봉(1억 단위)이 지배적으로 큰 값**이 되어버린다.
- 그 결과 최종 예측값도 거의 전적으로 **연봉에만 좌우**되고, 키·몸무게는 있으나 마나 한 컬럼이 되어버린다 — 실제로는 세 컬럼이 골고루 의미 있는 정보를 담고 있을 수 있는데도.
- 이건 **AI가 "생각"해서 연봉이 중요하다고 판단한 게 아니라**, 순전히 숫자의 스케일 차이 때문에 발생하는 연산상의 왜곡이다.

### 해결책 — 컬럼별로 각각 스케일링

- 키는 키 컬럼 내에서 0~1로, 몸무게는 몸무게 컬럼 내에서 0~1로, 연봉은 연봉 컬럼 내에서 0~1로 **각각 독립적으로** 스케일링한다.
- 이렇게 하면 세 컬럼 모두 동일한 범위(0~1)를 갖게 되어, **어느 컬럼도 숫자 크기 때문에 부당하게 지배적인 영향력을 갖지 않게 된다.**
- `sklearn`의 `MinMaxScaler`, `StandardScaler` 등은 기본적으로 **컬럼(feature) 단위로 스케일링을 수행**한다 — 전체 데이터를 통으로 한 번에 스케일링하는 게 아니다.
- 어제(9일차) 배운 "전체를 통으로 스케일링하면 안 된다"는 원칙과 결이 같은 이야기: **기준을 세밀하게 나눠 적용해야 정보가 왜곡되지 않는다.**

## 2. StandardScaler — 평균 0, 표준편차 1 기준으로 정규화

### 수식

$$
X_{scaled} = \frac{X - \mu}{\sigma}
$$

($\mu$: 평균, $\sigma$: 표준편차)

### 원리를 쉽게 이해하기

- **분산(Variance)**: 각 데이터에서 평균을 뺀 값을 제곱해서 모두 더한 뒤 평균낸 것. (MSE와 매우 비슷한 형태 — "평균과의 거리"를 재는 방식)
- **표준편차(Standard Deviation)**: 분산에 루트를 씌운 것.
- StandardScaler는 원값에서 **평균을 빼고** 그 결과를 **표준편차로 나눈다.**

### 데이터가 어떻게 바뀌는가

1. **평균을 뺀다** → 원래 데이터의 평균 지점이 정확히 **0**이 된다. 데이터 전체가 0을 중심으로 좌우(양수/음수)로 재배치된다.
2. **표준편차로 나눈다** → 0을 중심으로 퍼져 있는 정도(폭)가 줄어들어 값이 더 조밀하게 모인다.

- Min-Max처럼 정확히 0~1로 한정되는 건 아니고, **평균이 0이 되도록 중심을 이동**시키고 **표준편차만큼 스케일을 축소**하는 방식.
- 컬럼이 여러 개일 때, 각 컬럼이 전부 **"평균 0"이라는 동일한 기준점**을 갖게 되므로 컬럼 간 비교·연산에서 왜곡이 줄어든다.

### 음수가 나와도 괜찮은 이유

- Min-Max처럼 0~1의 양수 소수뿐 아니라, StandardScaler는 **음수와 양수를 모두 포함하는 소수** 형태로 나온다.
- 연산이 잘 먹히는 건 "0~1 사이"라서가 아니라 **작은 소수 단위의 값**이라서다 — 음수든 양수든 소수 범위 안에 있으면 오버플로 위험 없이 안정적으로 연산된다.
- 이미지 데이터 전처리에서도 자주 쓰이는 스케일링 방식 중 하나.

### 코드

```python
from sklearn.preprocessing import StandardScaler

scaler = StandardScaler()
scaler.fit(x_train)
x_train = scaler.transform(x_train)
x_test = scaler.transform(x_test)

# 또는 한 줄로:
x_train = scaler.fit_transform(x_train)
```

- 사용법은 `MinMaxScaler`와 완전히 동일하다 — `fit()`은 train에만, `transform()`은 train/test 모두에.

## 3. MaxAbsScaler — 절댓값 기준 최댓값으로 나누기

### 원리

- 데이터에 음수와 양수가 섞여 있을 때(예: -100, -50, 0, 100, 200), **절댓값이 가장 큰 값**으로 전체 데이터를 나눈다.
- 예: 최대 절댓값이 200이면, 모든 값을 200으로 나눈다 → 결과는 **-1 ~ 1 사이**로 수렴한다 (정확히 0이 원점이 아니어도 된다).

### Min-Max와의 차이

- Min-Max는 "0을 최솟값 기준으로, 1을 최댓값 기준으로" 맞추기 위해 **최솟값을 빼는 과정**이 필수였다.
- MaxAbsScaler는 그 과정 없이 **그냥 절댓값 최댓값 하나로 통째로 나눈다** — 더 단순한 접근.
- 결과 범위가 정확히 0~1일 필요는 없다는 발상: "**크기만 충분히 작아지면 오버플로 문제는 해결된다**"는 실용적 관점.
- 실제 성능은 데이터셋에 따라 Min-Max보다 좋을 때도, 나쁠 때도 있다 — **여러 번 시도했을 때 단 한 번이라도 성능이 개선되면 그걸 채택**하는 것이 실전 전략(EarlyStopping의 best-weight 채택 논리와 같은 맥락).

### 코드

```python
from sklearn.preprocessing import MaxAbsScaler

scaler = MaxAbsScaler()
x_train = scaler.fit_transform(x_train)
x_test = scaler.transform(x_test)
```

- 사용법(`fit`/`transform` 패턴)은 다른 스케일러와 완전히 동일하다.

## 4. RobustScaler — 이상치(Outlier)에 강한 스케일러

### 이상치가 스케일링에 미치는 악영향 복습

- 평균 계산에 극단적인 이상치(예: 초고소득자 데이터)가 섞이면 **평균 자체가 왜곡**된다 — "평균의 오류".
- 이럴 때 대안으로 쓰는 게 **중위값(Median)** — 데이터를 순서대로 나열했을 때 정중앙에 있는 값. 극단값의 영향을 받지 않는다.

### 사분위수(Quartile)와 IQR 개념

| 용어 | 의미 |
|---|---|
| Q1 (제1사분위수) | 데이터를 순서대로 나열했을 때 하위 25% 지점 |
| Q2 (중위값, Median) | 하위 50% 지점 |
| Q3 (제3사분위수) | 하위 75% 지점 |
| IQR (사분위 범위) | Q3 − Q1 (데이터 중심 50%가 퍼진 폭) |

### 이상치 판별 방법 (IQR 기반, 개념 소개)

- 대부분의 정상 데이터는 Q1~Q3 사이(중심 50%)에 몰려 있다는 가정.
- Q3에서 IQR만큼 더 위로, Q1에서 IQR만큼 더 아래로 벗어나는 값들을 **이상치로 간주**하는 방식이 널리 쓰인다 (구체적인 배수 조정은 추후 "이상치 처리" 챕터에서 상세히 다룰 예정 — 이번 시간은 개념만 소개).
- 이상치로 분류된 데이터는 삭제하거나 별도 조정하고, 나머지 정상 데이터만으로 분석을 진행하는 것이 일반적인 흐름.

### RobustScaler 수식

$$
X_{scaled} = \frac{X - Median}{Q3 - Q1}
$$

- **중위값을 뺀다** (평균이 아니라!) → 이상치에 흔들리지 않는 중심점 사용.
- **IQR(Q3-Q1)로 나눈다** → 역시 극단값의 영향을 덜 받는, 데이터 중심부의 실제 퍼짐 정도를 기준으로 스케일 축소.
- 이 방식 덕분에 이상치가 섞여 있는 데이터에서도, 이상치 자체는 여전히 크게 벗어난 값으로 남지만(즉 여전히 눈에 띄지만) **정상 데이터 내에서의 상대적 영향력은 줄어든다.**

### 코드

```python
from sklearn.preprocessing import RobustScaler

scaler = RobustScaler()
x_train = scaler.fit_transform(x_train)
x_test = scaler.transform(x_test)
```

### 주의사항

- RobustScaler가 이상치에 "강하다"고 해서 **무조건 믿고 쓰면 안 된다.**
- 정석적인 흐름은: ① 먼저 별도로 이상치를 탐지·처리 → ② 그 다음 정제된 데이터에 원하는 스케일러(Min-Max, Standard 등)를 적용하는 것이 더 안정적이다.
- RobustScaler는 "이상치에 상대적으로 강하다" 정도로 이해하고, 이상치 처리를 대체하는 수단으로 과신하지 않는다.

## 5. 스케일러 선택 전략 — 정답은 없다, 실험이 답이다

### 4가지 스케일러 요약 비교

| 스케일러 | 기준값 | 결과 범위 | 특징 |
|---|---|---|---|
| MinMaxScaler | 최소/최대값 | 정확히 0~1 | 가장 기본, 직관적 |
| StandardScaler | 평균/표준편차 | 평균 0, 음수 포함 | 컬럼 간 비교에 강함, 역전파에 유리 |
| MaxAbsScaler | 절댓값 최대 | 정확히 -1~1 | 단순하고 빠름 |
| RobustScaler | 중위값/IQR | 이상치 영향 적은 범위 | 이상치가 있는 데이터에 유리 |

### 실전 판단 원칙

- **어떤 스케일러가 절대적으로 우월하다는 법칙은 없다.** 데이터셋마다 다르게 반응한다.
- 실험 순서: 스케일링 없음 → MinMax → Standard → MaxAbs → Robust 순으로 전부 시도해보고, 코드 하단에 **매번 결과를 기록**한다.
- 10개의 서로 다른 데이터셋에 하나의 스케일러를 적용했을 때, **전부 향상되지 않아도(예: 3개만 향상되어도) 그건 유의미한 성과**로 간주한다 — 모든 경우에 만능인 기법은 없다는 전제.
- 여러 스케일러를 조합(예: Standard 다음에 다시 MinMax)해서 쓸 수도 있지만, 경험상 겹쳐 쓴다고 항상 더 좋아지는 건 아니다 — 이것도 실험해서 판단할 문제.
- **컬럼별로 서로 다른 스케일러를 적용하는 것도 가능하다** (예: A컬럼은 MinMax, B컬럼은 Standard) — 이것 역시 **피처 엔지니어링(Feature Engineering)**의 한 영역이다. 결국 최상의 성능을 결정짓는 것은 모델 구조보다 **데이터를 얼마나 정교하게 다듬었는가**인 경우가 많다.

## 6. 딥러닝 모델의 실체 — "저장된 가중치 + 입력값 연산"이라는 관점

### ChatGPT 같은 서비스형 AI가 실시간 학습하지 않는 이유

- ChatGPT 등에 질문을 던지면, 이미 사전 학습이 끝나 **완성된 최적의 가중치(Weight)가 저장된 상태**에서, 사용자의 입력을 그 가중치에 넣어 **순전파(추론) 연산만 수행**한다.
- 즉 `Y = XW + B` 구조에서 `W`와 `B`는 이미 고정되어 있고, 사용자가 입력한 문장이 벡터/임베딩으로 수치화되어 `X` 자리에 들어가는 것뿐이다.
- 그래서 사용자가 입력한 대화 내용 자체가 그 자리에서 실시간으로 모델을 재학습시키지는 않는다 (다만 별도의 로그·피드백 파이프라인을 통해 추후 모델 개선에 반영될 수는 있다).
- 이 구조를 이해하면, **왜 미리 학습된 모델(사전학습 모델)을 "가져다 쓰는" 방식이 실무에서 흔한지**도 자연스럽게 이해된다 — 결국 관건은 "저장해둔 가중치를 얼마나 잘 활용하느냐"이다.

## 7. 모델 저장 — `model.save()`

### 기본 사용법

```python
model.save('경로/파일명.keras')
```

- 확장자는 최신 버전에서 `.keras` 형식을 권장 (과거에는 `.h5` 확장자를 많이 사용했으나, 현재는 `.keras`가 표준적으로 쓰인다). 둘 다 동작은 유사하다.
- 경로는 문자열 결합(`path + '파일명'`)으로 구성하는 게 일반적 — 앞서 배운 경로 처리 패턴과 동일.

### 저장 위치(시점)에 따라 저장되는 내용이 완전히 다르다 — 가장 중요한 개념

> **모델을 `#2 모델 구성` 직후에 저장하면 "모델 구조 + 초기(랜덤) 가중치"만 저장된다.**
> **`#3 컴파일·훈련` 이후에 저장하면 "모델 구조 + 학습 완료된(최적) 가중치"가 저장된다.**

| 저장 시점 | 저장 내용 | 용도 |
|---|---|---|
| 모델 구성 직후 (`model = Sequential()...` 다음) | 모델 구조 + **랜덤 초기 가중치** | 다른 사람에게 "모델 설계도"만 전달하고, 각자 새로 학습시키고 싶을 때 |
| `model.fit()` 훈련 완료 후 | 모델 구조 + **학습된 최적 가중치** | 이미 완성된 모델을 그대로 가져다 바로 쓰고 싶을 때 (재훈련 불필요) |

- 이 차이를 모르고 무작정 `model.save()`를 훈련 전에 호출하면, 나중에 불러와서 평가해도 **훈련이 전혀 안 된 랜덤 상태의 성능**만 나온다 — 실수하기 매우 쉬운 지점이라 반드시 구분해서 기억해야 한다.

### 모델 구조만 필요한 경우 vs 가중치까지 필요한 경우 (실전 시나리오)

- 동료의 모델 **구조만** 필요하다 (직접 처음부터 훈련시키고 싶다) → **`#2 모델 구성 직후`에 저장한 파일**을 받으면 된다.
- 동료가 이미 훈련까지 마친 **완성된 결과물 그대로** 쓰고 싶다 → **`#3 컴파일·훈련 이후`에 저장한 파일**을 받으면 된다.

## 8. 모델 불러오기 — `load_model()`

### 기본 사용법

```python
from tensorflow.keras.models import load_model

model = load_model('경로/파일명.keras')
model.summary()   # 불러온 모델 구조 확인
```

- `load_model()`로 불러오면, **기존에 `Sequential()`로 새로 모델을 만드는 코드(`#2 모델` 구성 부분)는 전부 생략(주석 처리)**해도 된다 — 이미 저장된 모델 자체를 그대로 가져오는 것이므로.
- 불러온 모델의 `.summary()`를 찍어서, 원래 저장했던 모델과 구조가 동일한지 검증하는 습관을 들이면 좋다.

### 훈련까지 끝난 모델을 불러왔다면 — 재훈련도 필요 없다

- `#3 컴파일·훈련 이후`에 저장한 모델을 `load_model()`로 불러오면, **그 안에 이미 최적 가중치가 포함**되어 있으므로 **다시 컴파일하거나 `.fit()`으로 훈련시킬 필요가 없다.**
- 코드 흐름 예:

```python
# #1 데이터 준비 (동일)
# #2 모델 — 아래처럼 새로 만들지 않고 불러오기만 함
model = load_model(path + 'keras29_3_save_model.keras')

# #3 컴파일·훈련 — 이미 학습 완료된 모델이므로 생략!

# #4 평가·예측 — 바로 진행 가능
loss = model.evaluate(x_test, y_test)
```

- 실제로 이렇게 하면 `model.evaluate()`가 **거의 즉시(ChatGPT가 답변하는 속도만큼 빠르게)** 결과를 반환한다 — 추론(순전파)만 수행하기 때문에 훈련 과정 없이도 바로 결과가 나온다.
- 반환되는 결과는 **저장 당시의 마지막(혹은 최적) 훈련 결과와 동일**해야 정상이다.

## 9. 실무 활용 시나리오 — 동료와 모델 공유하기

### 시나리오별 요청 방법

- "네가 설계한 모델 **구조**만 줘봐" → `#2 모델 구성 직후`에 저장된 파일을 요청.
- "네가 다 학습시킨 **완성본**을 그대로 줘봐" → `#3 훈련 완료 이후`에 저장된 파일을 요청.

### 실전 프로젝트에서의 의미

- 팀 프로젝트에서 여러 명이 각자 모델을 튜닝하다가, 누군가의 모델이 특히 좋은 성능을 낸다면 → **그 가중치 파일을 공유받아** 다른 팀원들도 즉시 같은 성능의 모델을 사용할 수 있다.
- 이는 파란색(하이퍼파라미터) 튜닝 경쟁이 반복되는 실전 프로젝트 환경에서 **결과물을 재사용 가능하게 만드는 핵심 장치**다.

## 10. 실무 팁 · 습관

- 저장 파일은 별도 폴더(`_save` 등)를 만들어 관리 — 여러 실습 파일에서 나온 저장물이 뒤섞이지 않도록.
- 파일명에 실습 번호를 포함시키는 습관(`keras29_1_save_model.keras`처럼) — 어떤 코드에서 저장된 결과인지 추적하기 쉬워진다.
- 코드 복사 시 **이전 파일명을 주석으로 남겨서**("29에 1번 카피") 어디서 파생된 파일인지 기록해두면 복습 때 유용하다.
- 모델을 저장하기 전에는 반드시 **`#3` 이후(훈련 완료 후)**에 저장 코드가 위치해 있는지 확인하는 습관을 들인다 — 이게 이번 강의에서 가장 실수하기 쉬운 지점으로 강조된 부분.

## 부록 — 모델 저장/불러오기 전체 코드 템플릿

```python
from tensorflow.keras.models import Sequential, load_model
from tensorflow.keras.layers import Dense
from tensorflow.keras.callbacks import EarlyStopping

path = './_save/keras29/'

# ===== #2 모델 =====
model = Sequential()
model.add(Dense(64, input_dim=x.shape[1], activation='relu'))
model.add(Dense(32, activation='relu'))
model.add(Dense(1))

# 모델 구조 + 초기 가중치만 저장 (원하는 경우)
model.save(path + 'keras29_1_save_model.keras')

# ===== #3 컴파일 · 훈련 =====
model.compile(loss='mse', optimizer='adam')
es = EarlyStopping(monitor='val_loss', patience=20, mode='min',
                    restore_best_weights=True)
model.fit(x_train, y_train, epochs=1000, batch_size=32,
          validation_split=0.2, callbacks=[es], verbose=1)

# 모델 구조 + 학습 완료된 최적 가중치 저장 (이게 실전에서 더 유용)
model.save(path + 'keras29_3_save_model.keras')

# ===== 나중에 새 파일에서 불러오기 =====
model = load_model(path + 'keras29_3_save_model.keras')
model.summary()

# 훈련 완료된 모델이므로 재훈련 없이 바로 평가/예측 가능
```
