# 딥러닝 14일차 정리 — CNN & TensorFlow

> 강의 녹취 기반 정리. 잡음이 많은 원본에서 텐서플로/파이썬 실습과 관련된 핵심 개념만 추려 정리했습니다.

## 1. CNN 파라미터(가중치) 계산 원리

- 필터(커널) 하나당 파라미터 수 = **(필터 가로 × 필터 세로 × 입력 채널 수) + 바이어스 1개**
  - 예: 3×3 필터, 입력이 흑백(채널 1)이면 필터당 파라미터 = 3×3×1 + 1 = 10개
- 입력 채널이 1(흑백) 또는 3(컬러)인 이유: 이미지가 보통 흑백 아니면 RGB 컬러이기 때문
- 두 번째 컨볼루션 레이어부터는 입력 채널 수가 1·3이 아니라 **이전 레이어의 필터 개수**로 결정됨
  - 즉, N번째 레이어의 입력 채널 = (N-1)번째 레이어의 필터 개수
- 필터 개수 관례: 층이 깊어질수록 필터 개수를 늘려가는 패턴이 흔함 (예: 16 → 32 → 64 → 128)
  - 앞쪽 레이어는 단순한 특징(에지 등)만 잡으면 되므로 필터 수가 적어도 되고, 뒤로 갈수록 더 복잡한 특징을 잡아야 하므로 필터 수를 늘림
- 파라미터 수는 순식간에 커질 수 있음 (예시: 20만 개 이상까지 증가하는 케이스 언급) → MaxPooling으로 공간 크기를 줄여 파라미터 폭증을 억제

## 2. MaxPooling / 다운샘플링

- 개념: 2×2 블록으로 잘라서 그 중 **가장 큰 값 1개만 남기고 나머지는 버림**
  - 결과적으로 가로·세로 크기가 각각 절반으로 줄어듦 (피처맵 축소)
- 목적: 굳이 모든 위치에서 컨볼루션 연산을 반복할 필요가 없을 때, 불필요한 연산을 줄이고 노이즈에 덜 민감하게 만듦
  - 노이즈가 있는 픽셀이 그대로 다음 레이어에 전달되지 않도록, 맨 처음 레이어 바로 위에는 잘 안 넣는 것이 일반적이라는 언급
- 실습 순서 예시: Conv → Dropout → MaxPooling 순으로 레이어를 쌓음 (강의에서 언급된 순서)
- Flatten 직전에는 반드시 어떤 형태로든 데이터가 정리되어 있어야 계산이 가능 (마지막 차원 처리 이슈 언급)

## 3. GlobalAveragePooling vs Flatten

- Flatten: 펴서(1차원으로) 그대로 다음 레이어에 전달 — 성능이 더 좋을 때가 있음
- GlobalAveragePooling: 평균으로 압축해서 전달 — 상대적으로 성능이 살짝 떨어질 수 있지만 연산량을 줄여줌
- 상황에 따라 선택 (둘 다 실습에서 비교)

## 4. 이미지 데이터 전처리 (스케일링)

- 원본 픽셀 값 범위: 0 ~ 255
- Conv/Dense 레이어에 넣기 전 **반드시 스케일링** 필요
  - 0~1 사이, 또는 -1~1 사이로 정규화
- Reshape → 정규화(스케일링) → One-hot 인코딩 순서로 데이터 정리
- 실습에서 확인한 사항: `X_train`, `X_test`, `y_train`, `y_test` 각각의 shape을 항상 확인

## 5. 채널 순서(리쉐이프) 관련

- 이미지 텐서 형태를 (채널, 높이, 너비) ↔ (높이, 너비, 채널)로 바꿔가며 실습
- 채널이 반드시 1 또는 3이어야 하는 건 아니고, 컨볼루션 레이어를 거치면 필터 개수만큼의 채널로 자연스럽게 바뀜 → 구조적으로 문제 없음

## 6. CNN vs DNN — 모델에 종속되지 말 것

- 같은 데이터셋을 CNN과 DNN(완전연결) 양쪽으로 다 돌려보는 실습 진행
- 경험적으로:
  - **이미지 데이터**: CNN이 대체로 더 좋은 성능
  - **매트릭스(표) 형태 데이터**: 반드시 CNN이 더 좋은 건 아니고 데이터셋에 따라 다름
- 핵심 교훈: "이 데이터는 이미지니까 CNN, 이 데이터는 표니까 DNN"처럼 고정적으로 생각하지 말고, 두 가지 접근을 모두 시도해보는 사고의 확장이 필요

## 7. 하이퍼파라미터에 대한 관점

- 레이어 수, 필터 개수, 노드 개수 등 모든 하이퍼파라미터의 "최적 조합"을 이론적으로 완벽히 설명할 수 있는 사람은 없음
- 실무에서는 대략적인 경험치(예: 몇백 개 단위로 몇 가지 시도해보고 잘 나오는 값 채택)로 접근
- 즉, 하이퍼파라미터 튜닝은 이론적 최적화라기보다 실험적 탐색에 가깝다는 취지의 설명

## 8. 컨볼루션 연산의 역사적 맥락

- 컨볼루션 개념 자체는 1980년대에 이미 정립됨
- 당시 컴퓨팅 파워로는 지금 몇 분/몇십 분 걸리는 연산도 훨씬 오래 걸렸을 것이라는 비교 언급 (GPU가 없던 시절)

## 9. 실습 워크플로 (CNN 10개 모델 비교)

- 하루 실습 목표: 동일 데이터셋으로 **CNN 모델 10개**를 구성해 성능 비교
- 파일/폴더 네이밍 예시: `cnn1`, `cnn2` … 순차적으로 저장
- 절차:
  1. 데이터 reshape / 정규화 / one-hot 인코딩
  2. 모델 10개를 각각 한 번씩 돌려보기
  3. 돌려본 뒤 성능 향상이 있었는지 비교하며 구조(필터 개수, 레이어 순서 등) 조정
- GPU/CPU 선택: 작업 유형(특히 패치 기반 작업)에 따라 GPU/CPU 선택을 신중히 할 것
