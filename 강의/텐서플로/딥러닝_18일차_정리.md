## 1. Optimizer — Adam과 Learning Rate 튜닝

- `Adam`은 Gradient Descent 계열(모멘텀 + RMSProp 결합)의 대표 옵티마이저. 기본값(default)이 잘 잡혀 있어 대부분 그대로 사용 가능.
- Keras/TensorFlow의 SGD 갱신식 기본 개념:
  ```
  weight = weight - learning_rate * (dLoss/dWeight)
  ```
- 기존에는 `optimizer='adam'`처럼 문자열로 default lr(0.001)을 썼지만, lr을 직접 조정하려면 Adam 옵티마이저 객체를 만들어서 넘겨야 함.

```python
from tensorflow.keras.optimizers import Adam

lr = 0.0001  # 튜닝 대상 하이퍼파라미터
model.compile(optimizer=Adam(learning_rate=lr), loss='...', metrics=['acc'])
```

### Learning Rate 스윕(실험) 패턴
- **다른 조건(에폭, 레이어 구조, batch size 등)은 절대 바꾸지 않고 learning_rate 하나만 바꿔가며 비교**하는 것이 핵심.
- 예시로 준비한 lr 후보군(사람마다 취향껏 1개 정도만 선택해서 테스트):
  - `0.01`, `0.005`, `0.001`(default), `0.0001`, `0.00001` 등
- 방법: 파일을 여러 개 복사해서 만든 뒤(예: 1~10번), 각 파일에서 learning_rate 값만 교체 → 실행 → 성능(정확도 등) 기록 → 갱신되면 다음 단계로 진행.
- Learning rate를 낮추는 것과 epoch(에폭)을 늘리는 것의 차이: epoch을 늘리면 컴퓨팅 자원만 더 태우는 경우가 많고, 실제 성능 개선에는 learning rate 조정이 더 효율적인 경우가 많음.
- 성능 향상 목표 기준 예시: 0.001 단위 개선도 경진대회 수준에서는 큰 개선 → 무리하게 욕심내지 않아도 됨.

### ReduceLROnPlateau / Early Stopping 관련
- 성능이 정체될 때 learning rate를 줄여주는 방식:
  - 일반 모델: factor `0.1`
  - (특정 계열, 예: DenseNet/"딥볼트") 모델: factor `0.01` 처럼 더 작게 주는 경우도 있음
- `patience`: 개선이 없어도 몇 번(EarlyStopping 카운트)까지 기다릴지 지정. patience 횟수 내에서 갱신 없으면 학습 종료(끊음).

## 2. 클래스 불균형(Class Imbalance)

- 데이터 클래스 비율이 한쪽으로 치우치면(예: 10:1) 모델이 다수 클래스로 쏠리는 경향이 생김 → 성능이 왜곡됨.
- 대응: 클래스 밸런스를 맞추는 것이 기본 원칙 (예: `class_weight` 활용, 또는 데이터 자체를 균형 있게 샘플링).
- (참고) `PatchGAN`류 방식은 상대적으로 불균형에 취약하다는 언급 → 2D 데이터에서는 다른 방식으로 접근 필요.

## 3. RNN 기초 — 시계열 데이터 구조와 순환 구조

### 데이터 구성 (시계열 → 지도학습 형태로 변환)
- 예: 태양광 발전량(전력량) 데이터에서 **Y(정답)는 회사가 제공하지 않으므로 직접 만들어야 함**.
  - N일치 데이터를 입력(X)으로 잘라서, 그다음 날(N+1일차) 값을 Y로 설정하는 식으로 구성.
  - 예: 3일치를 잘라서 4일차를 Y로 만드는 패턴.

### RNN 순환(recurrent) 연산 구조
- 타임스텝마다 가중치(Weight)가 **공유**된다는 것이 RNN의 핵심 특징 (CNN의 필터 가중치 공유와 유사한 개념).
- Hidden state 계산 예시(개념 정리):
  ```
  H0 = 0 (초기 hidden state)
  H1 = X1 * W1 + H0 * W2   # 이전 hidden state 반영
  H2 = X2 * W1 + H1 * W2
  H3 = X3 * W1 + H2 * W2   # 이 값이 최종 출력으로 이어짐
  ```
  - `W1`: 입력(X)에 곱해지는 가중치, `W2`: 이전 hidden state에 곱해지는(순환) 가중치 → 이 두 가중치가 타임스텝마다 동일하게 재사용(공유)됨.
- RNN의 파라미터 개수 공식(정리):
  ```
  parameters = unit * unit + unit * feature수 + unit  (bias 포함)
  ```

### 데이터 차원(shape) 관련
- RNN 입력은 기본적으로 **3차원**(batch, timesteps, features) 데이터.
- 모델이 특정 차원에 종속되지 않도록 설계하는 것이 좋음(=DNN용 데이터를 CNN에 넣을 수 있도록 shape만 맞춰 재구성 가능해야 함). 데이터의 배치(batch) 차원만 제외하고 나머지를 input으로 구성.
- `input_shape` 대신 배치 크기를 포함한 형태(`batch_input_shape`)로 명시하는 방법도 있음.

### LSTM / GRU / Attention 관련 코멘트
- RNN 단순 구조는 시퀀스가 길어질수록 학습이 어려워짐 → LSTM/GRU 같은 게이트 구조 등장.
- LSTM은 연산량이 늘어나는 대신(속도 저하) 성능은 순수 RNN보다 좋음.
- 최근에는 Attention 계열 구조가 LSTM 계열보다 더 우수한 경향이 있다는 언급(LSTM의 대안으로 부상).

## 4. CNN 관련 정리 (짧게 언급된 내용)

- CNN도 RNN과 마찬가지로 필터(가중치)가 이미지 전체에서 **공유**됨.
- DNN 데이터를 CNN 구조에 맞게 변환해서 사용 가능 → 모델 구조에 데이터가 종속되지 않도록 설계하는 습관이 중요.

## 5. 실습/코드 작성 관련 팁

- 코드는 직접 타이핑(손코딩) 연습을 권장 — 처음엔 느리더라도 익히는 데 도움.
- Learning rate 등 하이퍼파라미터를 여러 값으로 실험할 때는, **기존 코드를 복사한 뒤 바꾸는 파라미터 한 곳만 수정**하는 방식으로 진행(다른 부분을 건드리면 에러 원인 추적이 어려워짐).
