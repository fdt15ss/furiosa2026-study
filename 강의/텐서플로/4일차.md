## 1. AI 개발의 4단계 프로세스

모든 AI 작업은 아래 4단계를 반복한다. PyTorch든 LLM이든 RAG든 방식은 동일하다.

| 단계 | 이름 | 내용 |
|---|---|---|
| #1 | 데이터 | 로드 → 전처리 → train/test 분리 |
| #2 | 모델링 | 레이어 구성 |
| #3 | 컴파일 · 훈련 | loss, optimizer 설정 → fit |
| #4 | 평가 · 예측 | evaluate, predict |

- **실무와의 차이**: 없음. 각 단계가 더 디테일해질 뿐 구조는 같다.
- **추론(inference)만 할 때**: #1 데이터 필요, #2 모델은 가져다 씀, **#3 훈련은 통째로 생략**, #4 평가·예측 수행.
  - 학습하지 않는다 = 역전파가 일어나지 않는다. `model.predict`, `model.evaluate`는 가중치를 갱신하지 않는다.

## 2. train / test 분리

- **왜 나누는가**: 명확한 판단(평가)을 위해서. 테스트 데이터는 훈련에 **절대** 사용하지 않는다.
- 귀한 데이터의 25~30%를 훈련에 못 쓰는 손해를 감수하면서까지 나누는 이유가 바로 "객관적 평가".
- **순서대로 자르면 안 된다** → 데이터에 경향성이 있으면 train/test 분포가 완전히 갈라진다. 전체에서 **랜덤하게** 추출해야 한다.

```python
from sklearn.model_selection import train_test_split

x_train, x_test, y_train, y_test = train_test_split(
    x, y, train_size=0.8, random_state=42
)
```

## 3. 용어 정리 — 반드시 암기

> **Loss = Error = 오차 = Cost**

네 단어 모두 AI에서 같은 의미로 쓰인다. 코드에서 `cost`라고 적혀 있으면 loss를 뜻하는 것.

- 자주 쓰는 용어는 이해보다 **암기**가 먼저. 쓰다 보면 이해가 따라온다.

## 4. MSE (Mean Squared Error, 평균제곱오차)

### 수식

$$
MSE = \frac{1}{n}\sum_{i=1}^{n}(y_i - \hat{y}_i)^2
$$

### 각 요소가 왜 필요한가

| 요소 | 이유 |
|---|---|
| 원값 − 예측값 | 오차 그 자체 |
| 제곱 | 음수 제거 (오차가 상쇄되는 것 방지) |
| 시그마(합) | 전체 데이터의 오차를 모두 반영 |
| 나누기 n (평균) | 데이터 개수에 상관없이 비교 가능한 값으로 |

예: 캘리포니아 데이터셋 20,000개 중 훈련 14,000개라면, 14,000개의 오차를 모두 더해 14,000으로 나눈다.

### MSE의 문제점

- **제곱 때문에 오차가 과도하게 커진다.**
  - 실제 오차가 1,000이면 → MSE에서는 1,000,000
  - 실제 오차가 10,000이면 → 100,000,000
- 1보다 큰 값은 더 커지고, 이상치(outlier)가 있으면 그 영향이 제곱으로 증폭된다.
- 평균의 오류: 이상치 하나가 전체 지표를 왜곡한다.

## 5. RMSE (Root Mean Squared Error)

MSE가 너무 커지니 **루트를 씌워 원래 스케일로 되돌리자**는 발상.

$$
RMSE = \sqrt{\frac{1}{n}\sum_{i=1}^{n}(y_i - \hat{y}_i)^2}
$$

> 주의: 각 개체마다 루트를 씌우는 게 아니라, **전체 MSE를 구한 뒤 마지막에 한 번** 루트를 씌운다.

---

## 6. R2 Score (결정계수)

$$
R^2 = 1 - \frac{SS_{res}}{SS_{tot}}
$$

### 왜 필요한가 — loss는 상대적 지표이기 때문

- **정확도(accuracy)**: 0~100%로 **절대적** 기준이 명확하다.
- **loss(오차)**: 최저 0은 좋다는 걸 알지만, **최악이 얼마인지 기준이 없다.** 2,000만이 나쁜 건지 좋은 건지 그 자체로는 판단 불가 → 다른 모델과 비교해야만 의미가 생긴다.

그래서 회귀 모델에는 절대적 감각을 주는 **보조지표**가 필요하고, 그게 R2다.

### R2의 성질

- **최대값 1** (1에 가까울수록 좋음)
- 최소값은 0이 이상적이지만 **음수가 나올 수 있음**
- **음수가 나오면 = 모델이나 데이터가 잘못된 것.** 즉시 수정해야 한다.
- 0.7이 나오면 "accuracy 70%와 비슷한 느낌" 정도로 해석 (같다는 뜻은 아님)

### 주지표 vs 보조지표

| 구분 | 주지표 | 보조지표 |
|---|---|---|
| 회귀(Regression) | **loss (MSE 등)** | R2 |
| 분류(Classification) | **loss** | Accuracy |

- 판단이 애매할 때 보조지표를 함께 본다.
- 같은 데이터·같은 조건이라면 loss와 R2는 거의 함께 움직인다. 극단적으로 어긋나는 경우에만 보조지표로 판단.
- 예: loss 1000 / R2 0.99 → 괜찮은 모델. loss 0.0001 / R2 0.3 → 아직 개선 여지가 많다는 뜻.

### 너무 잘 나오면 의심하라

R2가 0.999처럼 지나치게 잘 나오면 뿌듯해할 게 아니라 **"내가 뭘 잘못했지?"** 부터 의심해야 한다. 개발 경험이 쌓일수록 지나치게 좋은 결과가 두려워진다.

## 7. 회귀 모델 vs 분류 모델

AI 모델링은 딱 두 가지뿐이다.

### 회귀 (Regression)
- 결과가 **수치**로 나옴 (1.1, 2.2, 3.3 …)
- 정답이 3인데 3.3이 나왔다면 → **틀린 게 아니라 오차 0.3**
- 그래서 accuracy를 쓰면 전부 0%가 되어버림 → **MSE, RMSE, R2**를 써야 한다

### 분류 (Classification)
- 결과가 **정해진 라벨 중 하나** (남/여, 가위/바위/보, 0~9)
- 라벨의 한계가 정해져 있어 그 밖의 값은 나올 수 없음
- accuracy로 바로 판단 가능 (5명 중 4명 맞추면 0.8)

## 8. 코드 구현

### 8-1. 예측값 만들기

```python
y_predict = model.predict(x_test)
```

- `y = wx + b` 의 x 자리에 `x_test`를 넣어 만든 예측값.

### 8-2. evaluate vs sklearn 지표 — 인자가 다른 이유 (중요)

```python
loss = model.evaluate(x_test, y_test)      # x, y 둘 다
r2   = r2_score(y_test, y_predict)          # 원값, 예측값
```

- `model.evaluate`는 내부에 **predict가 포함**되어 있다. x_test를 넣으면 스스로 예측값을 만들고, y_test와 비교해 loss를 반환한다.
- sklearn은 TensorFlow와 무관한 별개 라이브러리라 predict 기능이 없다. 그래서 우리가 **직접 예측값을 만들어 넘겨줘야** 한다.
- **모든 평가지표의 본질은 하나: 원값 vs 예측값의 비교.** (loss, R2, accuracy 전부 동일)

### 8-3. sklearn 지표 사용

```python
from sklearn.metrics import r2_score, mean_squared_error

r2 = r2_score(y_test, y_predict)
mse = mean_squared_error(y_test, y_predict)

print("R2 :", r2)
print("MSE:", mse)
```

- `model.evaluate`의 loss(MSE)와 sklearn의 `mean_squared_error` 결과는 **동일하게 나온다.**
- 최신 sklearn에는 `root_mean_squared_error`도 생겼다. (예전 버전엔 없어서 직접 만들어 썼음)

### 8-4. RMSE 함수 직접 만들기 — 파이썬 함수 기초

```python
import numpy as np
from sklearn.metrics import mean_squared_error

def RMSE(y_test, y_predict):
    return np.sqrt(mean_squared_error(y_test, y_predict))

rmse = RMSE(y_test, y_predict)
print("RMSE:", rmse)
```

**포인트**
- `def`는 **정의**일 뿐, 아무 동작도 하지 않는다. 호출해야 실행된다.
- `return`이 없으면 호출해도 아무 의미가 없다.
- 함수명 대문자는 원래 네이밍룰 위반(선임한테 지적당함). 여기선 강조용.

**파이썬 들여쓰기 규칙**
- 파이썬은 **라인 위주 언어**다.
- 같은 열에 있으면 → 동급
- 한 탭 들여쓰면 → **윗줄에 종속**
- `def` 아래 들여쓰지 않으면 바로 에러

```python
def FUNC(a, b):
    c = a + b      # 들여쓰기 → 함수에 포함됨
    return c
c = 1              # 들여쓰기 없음 → 함수 밖
```

### 8-5. 컴파일에는 RMSE를 못 넣는다

`model.compile(loss='rmse')`는 지원되지 않는다. MSE를 넣어 훈련하고, 평가 단계에서 RMSE로 판단하면 된다. (알고리즘상 거의 같이 움직인다)

## 9. 신경망 순전파 수식 (참고 — 지금은 몰라도 됨)

입력 2개 → 은닉층 3개 → 출력 1개인 아주 단순한 신경망:

```
h1 = w1·x1 + w2·x2 + b
h2 = w3·x1 + w4·x2 + b
h3 = w5·x1 + w6·x2 + b

ŷ  = w7·h1 + w8·h2 + w9·h3 + b
```

- 전체 모델에서 "선을 하나 긋는다"는 표현은 엄밀히는 부정확하다. 이 식들을 전부 그려야 한다.
- 다행히 **제곱항이 없는 1차항** → 선형대수로 처리 가능.
- 층이 10개, 40개로 늘어나면 이 식이 그만큼 길어질 뿐 원리는 같다.

## 10. Pandas 데이터 전처리

### 10-1. 왜 CSV인가

- 데이터 분석·AI 실무의 **90~99%는 CSV**로 작업한다.
- 관계형 DB는 설치·연결에 시간이 너무 걸려 잘 쓰지 않는다.
- Kaggle, Dacon 등 데이터 분석 컴피티션에서 RDB로 작업한 사례는 사실상 없다.

### 10-2. 경로 지정과 문자열 결합

```python
import pandas as pd

path = './_data/따릉이/'          # '.' = 현재 작업 폴더(스터디 폴더)
train_csv = pd.read_csv(path + 'train.csv', index_col=0)
```

- `'.'` = 현재 작업 폴더, `/` = 하위 폴더
- 따옴표 안의 내용은 **문자(str)**. 큰따옴표/작은따옴표 구분 없음(단 앞뒤는 일치해야 함)
- **문자 + 문자 = 문자열 결합** → `'./_data/따릉이/' + 'train.csv'`
- 경로를 변수로 분리해두면 test.csv, submission.csv 불러올 때 재사용 가능

### 10-3. `index_col=0` — 반드시 챙길 것

- CSV 첫 컬럼이 `id`처럼 **인덱스 역할**만 하는 경우가 많다.
- **인덱스는 데이터가 아니다.** 훈련에 포함시키면 안 된다.
- `index_col=0`을 주면 0번째 컬럼을 인덱스로 지정해 데이터에서 제외한다.
- 확인: 11 columns → 10 columns 로 줄어드는 것으로 검증

### 10-4. 데이터 확인 3종 세트

```python
print(train_csv.shape)      # (행, 열)  → (1459, 10)
print(train_csv.columns)    # 컬럼명 목록
print(train_csv.info())     # 컬럼별 Non-Null Count, dtype
```

- `.info()`의 **Non-Null Count**로 결측치 개수를 파악한다.
  - 전체 1459개인데 어떤 컬럼이 1457개 → 결측치 2개

### 10-5. 결측치(NaN) 처리

**처리 방법은 10가지 이상 존재한다.**

| 방법 | 적합한 상황 |
|---|---|
| 평균값 | 일반적 |
| 중위값 | 이상치가 섞여 있을 때 |
| 앞/뒤 값(보간) | 시계열·기상 데이터 (10도 → ? → 12도면 11도일 확률 높음) |
| 특정값(0, 777 등) | 임의 |
| **행 삭제 (dropna)** | 데이터가 충분히 많고, 결측치 비율이 낮을 때 |

**판단 기준**
- 데이터가 몇백 개뿐인데 절반이 결측치 → 어떻게든 살려야 한다
- 데이터가 몇만 개인데 몇백 개 결측 → **차라리 삭제가 안전**
- 잘못된 값을 채워 넣으면 데이터 자체가 **오염**되어 모델이 틀어진다

```python
train_csv = train_csv.dropna()
print(train_csv.shape)   # (1459, 10) → (1328, 10)  약 130행 삭제
```

> **주의**: `dropna()`는 NaN이 있는 **행 전체를 삭제**한다. 한 행에 NaN이 3개 있어도 삭제되는 건 그 행 하나.

### 10-6. 이상치(Outlier)

- 예: 50~60대 평균 연봉을 구하는데 이재용이 표본에 섞여 있는 경우 → 평균이 완전히 왜곡됨
- 예: 겨울 새벽 2시 따릉이 대여량이 500대 → 5대를 500대로 잘못 기입했을 가능성
- **하지만 맥락이 중요하다.** "100대 그룹 회장단 연봉" 데이터셋이라면 100억은 이상치가 아니다.
- 대표적 처리: IQR 방식(25%~75% 범위 밖 제거)

> **결론: 데이터를 받는 순간 가장 먼저 생각할 것 = 이상치와 결측치를 어떻게 처리할 것인가**

### 10-7. x, y 분리

```python
# x : count 컬럼만 제외한 나머지 전부
x = train_csv.drop(['count'], axis=1)

# y : count 컬럼만
y = train_csv['count']

print(x.shape)   # (1328, 9)
print(y.shape)   # (1328,)  → 벡터 형태
```

- `axis=0` = 행, `axis=1` = 열 (행이 앞이니 0, 열이 두 번째니 1)
- `axis=1` 대신 `columns='count'`로 써도 된다
- **drop은 원본을 건드리지 않는다.** 잘라낸 결과를 새 변수에 담는 것.

## 11. 컴피티션(Dacon / Kaggle) 제출 흐름

주어지는 파일 3개의 역할:

| 파일 | 역할 |
|---|---|
| `train.csv` | x와 y가 모두 있음 → **이것만으로 훈련** |
| `test.csv` | **y가 없음.** 우리가 평가할 test가 아니라 **predict용 입력** |
| `submission.csv` | y 컬럼명만 있고 값은 비어 있음 → 제출 양식 |

**전체 흐름**

```
train.csv 로드
   → 결측치 처리
   → x, y 분리
   → train_test_split (여기서 나온 test로 검증·RMSE 확인)
   → 모델링 / 컴파일 / 훈련
   → 평가 (loss, RMSE, R2)
   → model.predict(test_csv)
   → 결과를 submission.csv에 채워넣기
   → csv로 저장 후 제출
```

- 실무와 거의 동일하다. 실무에선 제출 대신 보고서를 쓸 뿐.
- **모르는 지표가 나오면?** (예: RMSLE) 유사 지표(RMSE, MSE)로 훈련시키고, 그중 가장 좋은 결과를 제출하면 된다. 유사 알고리즘이면 함께 움직인다.

## 12. 실무 팁 · 학습 태도

### 개발 습관
- **처음 만든 모델은 epoch를 1~10으로 낮춰서 끝까지 돌려보라.** 에러 없이 완주하는지 확인 후에 1000 epoch를 돌린다. 그렇지 않으면 10분 기다린 끝에 에러가 터진다.
- 주석은 **지저분하다 싶을 정도로** 많이 달아라.
- 파일명 네이밍을 명확히 (`keras12_R2_RMSE_01_california.py`)
- 원본 CSV를 손으로 수정하지 마라 → 그 순간 **오염된 데이터**가 된다. 반드시 코드로 처리할 것.

### 버전 관리
- pandas와 numpy는 **가장 사고를 많이 치는** 라이브러리. 다른 패키지를 설치할 때마다 numpy 버전이 바뀌며 충돌한다.
- 팀/강의에서는 **경로와 버전을 통일**하는 것이 기본.

### AI 도구 사용
- 초반 한 달은 코드에 대해 ChatGPT 등 AI를 쓰지 말 것. **AI 자동완성도 끄기.**
- 이유: AI가 고민하면 내가 고민하지 않게 된다. 무엇을 물어봐야 할지 모르는 상태가 되고, 면접에서 아무것도 답할 수 없다.
- AI가 들어가지 않은 순수 자동완성 기능은 사용해도 무방.

### 시각화
- 프로젝트 발표·PT에는 항상 시각화를 넣어라. 그림으로 보면 더 명확히 보이고, 심사자에게 어필된다.

### 마인드
- **"쓰레기 데이터가 들어가면 결과도 쓰레기"** — 보석 같은 데이터를 넣어도 모델링을 못하면 쓰레기가 나올 수 있지만, 쓰레기를 넣으면 100% 쓰레기가 나온다.
- 회사는 **일을 배우러 가는 곳이 아니라 일을 하러 가는 곳**이다. "열심히 배우겠습니다"는 탈락 사유.
- 데이터를 받으면 → 전처리 → 모델링 → 컴파일 → 훈련 → 평가·예측 → 보고서. 이 흐름이 머리에서 바로 나와야 한다.

## 부록 — 전체 코드 템플릿

```python
import numpy as np
import pandas as pd
from tensorflow.keras.models import Sequential
from tensorflow.keras.layers import Dense
from sklearn.model_selection import train_test_split
from sklearn.metrics import r2_score, mean_squared_error

# ===== #1 데이터 =====
path = './_data/ddarung/'
train_csv = pd.read_csv(path + 'train.csv', index_col=0)
test_csv = pd.read_csv(path + 'test.csv', index_col=0)
submission_csv = pd.read_csv(path + 'submission.csv', index_col=0)

print(train_csv.shape)
print(train_csv.columns)
print(train_csv.info())

# 결측치 처리
train_csv = train_csv.dropna()

# x, y 분리
x = train_csv.drop(['count'], axis=1)
y = train_csv['count']

x_train, x_test, y_train, y_test = train_test_split(
    x, y, train_size=0.8, random_state=42
)

# ===== #2 모델 =====
model = Sequential()
model.add(Dense(64, input_dim=9))
model.add(Dense(32))
model.add(Dense(16))
model.add(Dense(1))

# ===== #3 컴파일 · 훈련 =====
model.compile(loss='mse', optimizer='adam')
model.fit(x_train, y_train, epochs=10, batch_size=32)   # 처음엔 10으로 확인

# ===== #4 평가 · 예측 =====
loss = model.evaluate(x_test, y_test)
y_predict = model.predict(x_test)

def RMSE(y_test, y_predict):
    return np.sqrt(mean_squared_error(y_test, y_predict))

print("loss :", loss)
print("R2   :", r2_score(y_test, y_predict))
print("RMSE :", RMSE(y_test, y_predict))
```
