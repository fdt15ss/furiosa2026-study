## 1. Local Minima vs Global Minima

### 훈련 초기 그래프가 요동치는 이유

- 최초 가중치(weight)는 랜덤한 작은 값으로 시작한다.
- 그 상태로 선을 그으면 오차가 크다 → 초기 몇 epoch 동안 loss가 크게 튀는 이유.
- 훈련이 진행되며 값이 갱신되다가, 어느 순간부터 갱신과 역행을 반복하며 **핑퐁(oscillation)** 치는 구간이 나타난다 — 이게 EarlyStopping이 patience로 감지하는 구간.

### Local Minima (국소 최저점)

- 훈련 중 도달한 "지금까지는 가장 낮은 지점"이지만, **진짜 최저점이라는 보장은 없다.**
- EarlyStopping이 멈춘 지점 = Local Minima일 가능성이 높다.
- patience를 늘리면 이 지점을 지나쳐서 더 깊은 곳(새로운 Local Minima)을 찾을 수도 있지만, 그 지점 역시 확정된 답은 아니다 — 계속 의심하고 다시 갱신될지 지켜봐야 한다.

### Global Minima (전역 최저점)

- 진짜 이론상 가장 낮은 지점. 하지만 **거의 파랑새(잡을 수 없는 이상향)**에 가깝다.
- 이유: Local Minima를 갱신해서 새 지점을 찾아도, 그게 Global인지 또 다른 Local인지 확신할 수 없다. 계속 의심하며 반복 탐색할 수밖에 없는 구조.
- Loss가 정확히 0이 되는 지점은 사실상 **과적합(overfitting)**을 의심해야 하는 신호지, 이상적인 최적점이 아니다.

### 실전 판단

- 로스가 어떤 구간에서 **계속 같은 패턴을 반복**하고 있다면 → 그 근방이 사실상의 최적 구간일 가능성이 높다.
- loss와 val_loss가 **함께 같은 패턴으로 반복**되고 있으면 판단 근거가 더 명확해진다.
- 확신이 서지 않을 때는 **여러 번 재훈련**해서 반복되는 패턴인지 확인하는 것이 실전적인 접근.

## 2. 회귀(Regression) vs 분류(Classification) — 최종 정리

| 구분 | 목표 | 예시 |
|---|---|---|
| **회귀** | 원값과 예측값의 **오차(수치)**를 줄이는 것 | 3인데 3.1로 예측 (딱 떨어지지 않아도 됨, 오차가 작으면 OK) |
| **분류** | **딱 떨어지는 라벨**을 맞추는 것 | 남자/여자, 정상/암 (미리 정해진 라벨 중 하나) |

- 회귀 모델로 분류 문제를 계산하면(예: 0.0001, 1.0001처럼 나옴) 머신 입장에서는 **"1과 1.0001은 다른 값"**으로 취급되어 아예 맞지 않는 방식이 된다. 분류에는 분류 전용 방식이 필요하다.
- 분류는 다시 두 가지로 나뉜다: **이진분류(2개 라벨)**, **다중분류(3개 이상 라벨)**.

```python
from sklearn.datasets import load_breast_cancer

datasets = load_breast_cancer()
```

### 데이터셋 자체가 딕셔너리 형태

- 그래서 `datasets.data`와 `datasets['data']` **둘 다 동작한다** — 딕셔너리의 key-value 접근 방식과 동일한 원리.
- 어제 배운 `History` 객체(`hist.history['loss']`)와 같은 개념: **딕셔너리에서 key를 넣으면 value가 나온다.**

- **주의**: 이 함수는 sklearn 교육용 데이터셋 전용이다. 실무에서는 pandas의 `describe()`를 쓴다 — csv로 받는 실무 데이터는 전부 pandas로 다루기 때문.
- `number of instances` = 행(row) 개수, `number of attributes` = 열(column) 개수.

### `.feature_names` — 컬럼명 확인

```python
print(datasets.feature_names)   # 컬럼명 배열 반환
```

- pandas에도 동일한 개념의 `.columns`가 있다.

## 4. 검증형 데이터에서 `Y` 값을 반드시 확인해야 하는 이유

```python
import numpy as np
print(np.unique(y))                       # 고유값만 출력
print(np.unique(y, return_counts=True))   # 고유값 + 각각의 개수
```

- 이진분류인 줄 알고 데이터를 받았는데, 실제로는 라벨이 3개 이상 섞여 있으면 → 모델이 전부 에러를 뿜는다.
- `np.unique()`로 Y값의 고유 라벨과 각 라벨의 개수를 미리 확인하는 습관이 필요하다.
- 만약 이상한 라벨(정의되지 않은 값)이 섞여 있다면 → 그 자체가 **이상치(오염된 데이터)**이므로 삭제하거나 데이터 제공자에게 재확인해야 한다.

### pandas로 확인하는 법

```python
import pandas as pd
print(pd.Series(y).value_counts())
# 또는
print(pd.value_counts(y))
```

- `np.unique(y, return_counts=True)`와 `pd.Series(y).value_counts()`는 결과는 동일하지만 표현 방식이 다르다. 어느 걸 써도 무방.

### 라벨 불균형과 성능의 관계

- 예: 0이 212개, 1이 357개처럼 **어느 정도 차이는 정상 범위**다. 문제 되지 않는다.
- 문제가 되는 건 **극단적 불균형**이다. 예: 신용카드 신용불량자 예측 모델에서 정상 고객 99만 명, 불량 고객 1,000명처럼 한쪽에 극도로 쏠려 있으면:
  - 그냥 "무조건 정상"이라고만 답해도 **accuracy 99% 이상**이 나온다 — 모델이 의미가 없어짐.
  - 이런 경우 실무에서는 **데이터 증폭(augmentation)** 기법으로 소수 클래스를 늘려 균형을 맞춘다. (단순 복제가 아니라 실제 데이터 조작 없이 늘리는 기술이 존재)
- **Kaggle Santander 대회 사례**: 실제 은행 데이터는 0(18만 개) : 1(2만 개)로 심하게 불균형했다. 이런 경우 모델이 전부 0을 찍기만 해도 로컬 accuracy가 0.9 근처로 나오는 착시가 발생한다 — 진짜 성능은 "1을 얼마나 잘 잡아내는가"로 판단해야 한다.

## 5. `train_test_split`의 `stratify` — 분류 데이터 전용 옵션

### 왜 필요한가

- 분류 데이터를 그냥 랜덤하게 train/test로 나누면, 우연히 한쪽에 특정 라벨이 몰릴 위험이 있다.
- 예: 전체 데이터에 0이 100개, 1이 100개 있는데, 랜덤하게 나눴더니 train에 0이 90개·1이 10개처럼 극단적으로 쏠릴 수 있다 (드물지만 가능).
- **`stratify`**: Y의 클래스 비율을 **train/test에 똑같은 비율로 유지**하며 분리해주는 옵션.

```python
x_train, x_test, y_train, y_test = train_test_split(
    x, y, test_size=0.3, random_state=337, stratify=y
)
```

- 원본 데이터에 0이 212개, 1이 357개(비율 약 0.594:1) 있다면, `stratify=y`를 넣으면 train/test 모두 **동일한 비율**로 유지된 채 나뉜다.
- `stratify=y`를 넣지 않으면 그 비율이 흐트러질 수 있다.
- **성능이 항상 더 좋아지는 건 아니다** — 넣고 빼는 것도 하나의 하이퍼파라미터 튜닝 요소다. 분류 데이터에는 넣는 걸 권장하지만 절대 규칙은 아니다.

## 6. 이진분류 모델 구성 — 반드시 지켜야 하는 2가지 규칙

> **① 마지막(출력) 레이어의 activation은 반드시 `sigmoid`**
> **② `model.compile()`의 loss는 반드시 `binary_crossentropy`**

이 두 가지는 **무조건, 예외 없이** 지켜야 하는 규칙이다. (회귀에서 loss가 MSE/RMSE/MAE 등 다양한 선택지가 있는 것과 달리, 이진분류의 loss는 사실상 이거 하나뿐)

```python
model = Sequential()
model.add(Dense(64, input_dim=30, activation='relu'))
model.add(Dense(32, activation='relu'))
model.add(Dense(1, activation='sigmoid'))    # 반드시 sigmoid

model.compile(loss='binary_crossentropy', optimizer='adam', metrics=['acc'])
```

- 회귀에서는 마지막 층에 activation을 명시하지 않으면 기본값(`linear`, 즉 `y = wx + b` 그대로)이 적용됐지만, 이진분류에서는 **명시적으로 `sigmoid`를 써야 한다.**
- `metrics=['acc']`(또는 `['accuracy']`) — 보조지표로 정확도를 함께 확인. loss가 상대적 지표라 판단이 애매할 때, accuracy는 "몇 %를 맞췄는지" 직관적으로 알려준다.
- `metrics`는 **리스트 형태로 받는다** — 나중에 여러 개의 보조지표를 동시에 넣을 수 있다는 힌트(콜백을 리스트로 받았던 것과 같은 패턴).

## 7. Sigmoid 함수 — 왜 필요한가

### 수식

$$
\sigma(z) = \frac{1}{1 + e^{-z}}, \quad z = wx + b
$$

### 핵심 성질

- 입력값이 **아무리 크거나 작아도**, 출력은 항상 **0과 1 사이의 값**으로 수렴한다.
  - $z \to +\infty$ 이면 $\sigma(z) \to 1$ (정확히 1이 되지는 않고 한없이 가까워짐)
  - $z \to -\infty$ 이면 $\sigma(z) \to 0$ (정확히 0이 되지는 않고 한없이 가까워짐)
  - $z = 0$ 이면 $\sigma(z) = 0.5$
- 회귀 모델 마지막에 아무 activation 없이 나오는 값(`wx+b`)은 어떤 범위든 나올 수 있어서, 그대로는 "0이냐 1이냐"를 판단할 근거가 없다.
- 그래서 최종 결과값을 sigmoid 함수에 통과시켜, 항상 0~1 사이의 값으로 **한정(제한)**시킨다 — 이게 "활성화 함수 = 한정 함수"라고 부르는 이유.

### 중요: sigmoid를 통과해도 정확히 0 또는 1이 나오는 게 아니다

- `model.predict()`로 직접 뽑아보면 0.7, 0.3, 0.9999 같은 **소수점 값**이 나온다.
- `model.evaluate()`에서 `metrics=['acc']`를 통해 보이는 accuracy는 **텐서플로가 내부적으로 0.5 기준 반올림 처리를 해준 값**이다.
- 하지만 `model.predict()`의 순수 출력값(추론 결과)은 반올림되지 않은 0~1 사이 소수값 그대로 나온다.

### 실전 코드 — predict 결과 반올림 처리

```python
y_predict = model.predict(x_test)
y_predict = np.round(y_predict)     # 0.5 기준으로 0 또는 1로 반올림
```

- `accuracy_score` 같은 sklearn 지표에 넣기 전에 **반드시 반올림 처리**해야 한다.
- 반올림하지 않고 sklearn의 `accuracy_score(y_test, y_predict)`에 그대로 넣으면 **에러 발생**:
  > `ValueError: Classification metrics can't handle a mix of binary and continuous target`
  > (이진값과 연속값을 섞어서 처리할 수 없다는 뜻 — 원값은 0/1인데 예측값은 소수라서 비교 불가)

### 왜 계단함수(Step Function)를 안 쓰고 시그모이드를 쓰는가

- 아주 오래된 활성화 함수인 **계단함수**는 0 또는 1로 딱 떨어지는 값만 출력한다.
- 하지만 순전파 이후 반드시 **역전파(미분)**가 필요한데, 계단함수는 미분이 불가능한 구간(불연속점)이 있어 학습에 부적합하다.
- Sigmoid는 부드러운 곡선(연속함수)이라 미분 가능 → 역전파 계산이 가능하다.
- 반올림은 **추론 결과를 사람이 해석할 때만** 적용하는 것이지, 학습(순전파+역전파) 과정 자체에는 관여하지 않는다.

## 8. 이진분류 코드 전체 흐름

```python
import numpy as np
import pandas as pd
from tensorflow.keras.models import Sequential
from tensorflow.keras.layers import Dense
from tensorflow.keras.callbacks import EarlyStopping
from sklearn.model_selection import train_test_split
from sklearn.metrics import accuracy_score
from sklearn.datasets import load_breast_cancer

# ===== #1 데이터 =====
datasets = load_breast_cancer()
x = datasets.data
y = datasets.target

print(np.unique(y, return_counts=True))   # 라벨 분포 확인

x_train, x_test, y_train, y_test = train_test_split(
    x, y, test_size=0.25, random_state=337, stratify=y
)

# ===== #2 모델 =====
model = Sequential()
model.add(Dense(64, input_dim=30, activation='relu'))
model.add(Dense(32, activation='relu'))
model.add(Dense(1, activation='sigmoid'))   # 이진분류 필수

# ===== #3 컴파일 · 훈련 =====
model.compile(loss='binary_crossentropy', optimizer='adam', metrics=['acc'])

es = EarlyStopping(monitor='val_loss', patience=20, mode='min',
                    restore_best_weights=True)

model.fit(x_train, y_train, epochs=1000, batch_size=32,
          validation_split=0.3, callbacks=[es], verbose=1)

# ===== #4 평가 · 예측 =====
loss = model.evaluate(x_test, y_test)      # [loss, acc] 형태로 반환
print("loss:", round(loss[0], 4), "acc:", round(loss[1], 4))

y_predict = model.predict(x_test)
y_predict = np.round(y_predict)            # 0.5 기준 반올림 필수

acc = accuracy_score(y_test, y_predict)
print("accuracy_score:", acc)
```

- `model.evaluate()`에 `metrics`를 추가했으면 반환값이 **`[loss, acc]` 리스트 형태**로 나온다. 인덱스로 각각 접근 가능(`loss[0]`, `loss[1]`).
- 텐서플로 내부 accuracy와 sklearn `accuracy_score`로 각각 계산해도 **동일한 값**이 나오는 것으로 검증 가능.

## 9. Kaggle Santander Customer Transaction Prediction — 실전 이진분류

### 데이터 특징

- 실제 산탄데르 은행(Santander Bank)의 고객 거래 예측 대회 (2019년, 상금 총 6.5만 달러 규모).
- 컬럼명이 `var_0`, `var_1`, ..., `var_199`처럼 **전부 익명화(blind 처리)**되어 있다 — 은행이 실제 컬럼의 의미(나이, 자산 등)를 공개하지 않기 위함.
- Y(target)는 고객이 향후 특정 거래를 할지(1) 안 할지(0)를 나타내는 이진값.
- 총 200개 컬럼 + `ID_code`(인덱스) + `target`(정답).

### 상위권 전략 (참고)

- 각 컬럼의 데이터 분포(최소/최대/분포 형태)를 분석해 "이건 나이 같다", "이건 소득 같다"처럼 **컬럼의 의미를 역추정**하는 피처 엔지니어링을 한다.
- 200개 전부 쓰기보다 **중요한 컬럼만 선별해서 학습**시키면 오히려 성능이 좋아지는 경우가 있다 (Feature Selection).
- 컬럼을 압축하는 기술(차원 축소)도 활용된다.
- 이런 정교한 작업은 실무·대회 상위권의 영역이며, 지금 단계의 목표는 **정상적으로 작동하는 이진분류 모델을 완성해서 제출까지 해보는 것**.

### 코드 흐름 (기존 이진분류와 거의 동일)

```python
path = './_data/kaggle_santander/'
train_csv = pd.read_csv(path + 'train.csv', index_col=0)
test_csv = pd.read_csv(path + 'test.csv', index_col=0)
submission_csv = pd.read_csv(path + 'sample_submission.csv', index_col=0)

# 결측치 확인
print(train_csv.isna().sum())    # 원본은 없음 (200개라 눈으로 다 보긴 힘드니 sum()으로 총합만 확인)
```

## 10. 실무·취업 관련 팁 (부가 내용)

- **회고(해고)** 는 한국에서 법적으로 매우 어렵다 — 노동위원회를 거쳐야 하고 근로자가 대체로 유리하다. 그래서 신입을 뽑을 때 회사는 신중하다.
- 면접에서 "특정 언어(자바 등)에 종속적이지 않은 개발자"라는 어필이 중요하다 — 조건문(if)과 반복문(for)만 이해하면 어떤 언어든 문법 차이일 뿐이라는 개념과 연결된다.
- 면접 복장은 무조건 "편하게"가 아니라 **최소한의 격식(정장 등)**을 갖추는 것이 안전 — 합격 이후 캐주얼로 전환하는 게 일반적인 순서.
- 계약직/인턴을 무조건 기피할 필요는 없다 — 실력이 있으면 이 바닥은 계약 형태보다 **실력 자체가 protection**이 된다는 관점.
- NPU(Neural Processing Unit)는 **추론(순전파)만 가능**하고 **학습(역전파)은 불가능**하다 — 이미 학습이 끝난 가중치를 얹어 서비스 단계에서 빠르고 저전력으로 동작시키는 용도. 이런 서비스 방식을 **전이학습(transfer learning)** 개념과 연결지어 이해하면 된다.

## 부록 — 이진분류 공식 요약표

| 항목 | 값 |
|---|---|
| 마지막 레이어 activation | `sigmoid` (필수) |
| compile의 loss | `binary_crossentropy` (필수) |
| compile의 metrics | `['acc']` 또는 `['accuracy']` (권장) |
| train_test_split | `stratify=y` 권장 |
| predict 후 처리 | `np.round()`로 반올림 필수 (sklearn 지표 사용 시) |
| evaluate 반환값 | `[loss, acc]` — metrics를 추가한 만큼 리스트 길이 증가 |

## 부록 — 전체 코드 템플릿 (Breast Cancer 이진분류)

```python
import numpy as np
from tensorflow.keras.models import Sequential
from tensorflow.keras.layers import Dense
from tensorflow.keras.callbacks import EarlyStopping
from sklearn.model_selection import train_test_split
from sklearn.metrics import accuracy_score
from sklearn.datasets import load_breast_cancer

# 데이터
datasets = load_breast_cancer()
x, y = datasets.data, datasets.target
print(np.unique(y, return_counts=True))

x_train, x_test, y_train, y_test = train_test_split(
    x, y, test_size=0.25, random_state=337, stratify=y
)

# 모델
model = Sequential()
model.add(Dense(64, input_dim=x.shape[1], activation='relu'))
model.add(Dense(32, activation='relu'))
model.add(Dense(16, activation='relu'))
model.add(Dense(1, activation='sigmoid'))

# 컴파일 & 훈련
model.compile(loss='binary_crossentropy', optimizer='adam', metrics=['acc'])
es = EarlyStopping(monitor='val_loss', patience=20, mode='min',
                    restore_best_weights=True)
model.fit(x_train, y_train, epochs=1000, batch_size=32,
          validation_split=0.3, callbacks=[es], verbose=1)

# 평가 & 예측
loss = model.evaluate(x_test, y_test)
y_predict = np.round(model.predict(x_test))
acc = accuracy_score(y_test, y_predict)

print("loss:", round(loss[0], 4))
print("acc (tf):", round(loss[1], 4))
print("acc (sklearn):", round(acc, 4))
```
