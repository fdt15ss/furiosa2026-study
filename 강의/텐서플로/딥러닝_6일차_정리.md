## 1. 모든 랭귀지는 결국 "조건문 + 반복문"

- 어떤 언어(Python, Java, C++...)든 핵심은 **조건문(if)**과 **반복문(for)** 뿐이다. 나머지는 문법상의 차이일 뿐.
- `model.fit()` 안에서 매 epoch마다 결과가 출력되는 것도 알고 보면 내부에 **for문**이 돌고 있는 것이다.
- PyTorch에는 `model.fit()`이 없다 — 훈련 루프를 **직접 for문으로 구현**해야 한다. 지금 Keras로 익히는 개념(에포 반복, loss 계산, 검증)이 그대로 PyTorch에서도 쓰인다.

## 2. `verbose` — 훈련 출력 조절

**verbose**(버보스) = "말수가 많다"는 뜻의 영단어. `model.fit()`의 파라미터로, 훈련 중 출력되는 정보의 양을 조절한다.

```python
model.fit(x_train, y_train, epochs=100, batch_size=32, verbose=0)
```

| verbose 값 | 출력 내용 |
|---|---|
| `0` | 아무것도 출력 안 함 (침묵) — 훈련은 정상적으로 진행됨 |
| `1` | **기본값(default)**. progress bar + loss 등 전부 표시 |
| `2` | progress bar 생략, epoch 단위 결과만 표시 |
| `3` 이상 | epoch 번호만 표시 |

- **verbose는 성능에 영향을 주지 않는다.** 단순히 "보여주는 방식"의 차이일 뿐, 훈련 결과는 동일하다.
- 그런데도 `verbose=1`(전체 출력)이 실행 속도를 늦춘다 — 1 epoch가 실제로는 매우 빠르게 끝나더라도, 화면에 출력하고 사람이 인식할 수 있게 하려고 **인위적인 딜레이**가 발생한다.
- **실전 판단 기준**:
  - 훈련이 짧게 끝나고 빠른 성과가 중요하다 → `verbose=0` 또는 `2`로 꺼서 속도 확보
  - 훈련이 며칠씩 걸리는 대형 모델 → 어차피 오래 걸리니 `verbose=1`로 진행 상황을 지켜보는 게 낫다
  - **상황에 맞게 개발자가 선택하는 것**이지 정답은 없다.

## 3. Validation(검증) — 훈련 중 실시간 평가

### 왜 필요한가

- `verbose=1`로 보이는 훈련 중 loss는 **train 데이터에만 과적합된 값**이다. 훈련 데이터로 훈련시키고 그 loss만 보면 "계속 좋아지고 있다"고 착각하기 쉽다.
- 이건 마치 문제집만 계속 풀면서 "나는 잘하고 있다"고 믿는 것과 같다. **실전 감각을 확인하려면 모의고사(다른 문제)를 풀어봐야 한다.**
- 그래서 훈련 중간중간(매 epoch마다) **훈련에 사용하지 않은 데이터로 검증**을 함께 수행한다.

### 데이터를 3등분한다

| 구분 | 역할 |
|---|---|
| **Train** | 실제 가중치 학습에 사용 |
| **Validation** | 훈련 중 매 epoch마다 "모의고사"처럼 검증만 함. **학습(가중치 갱신)에는 관여하지 않는다** |
| **Test** | 모든 훈련이 끝난 후 최종 평가 (수능) |

- `loss`는 train 데이터 기준, **`val_loss`(발로스)는 validation 데이터 기준**의 손실값이다.
- **val_loss가 loss보다 신뢰도가 높다** — train 데이터에 과적합되지 않은, 처음 보는 데이터에 대한 성능이기 때문.

### validation 데이터는 학습에 직접 관여하지 않지만 간접적으로 영향을 준다

- 시스템적으로 val 데이터가 가중치 갱신에 쓰이는 건 아니다.
- 하지만 사람이 **val_loss를 기준으로 하이퍼파라미터를 튜닝**한다면, 결국 val 데이터의 정보가 모델 선택 과정에 간접적으로 반영된다.
- 그래서 **validation과 test는 별도로 분리해두는 것이 원칙적으로 더 안전**하다 (완전히 동일한 성능이더라도, 검증의 엄밀성을 위해).

### 방법 1 — `validation_data`로 미리 나눈 데이터를 넘기기

```python
x_train, x_test, y_train, y_test = train_test_split(x, y, train_size=0.75)
x_train, x_val, y_train, y_val = train_test_split(x_train, y_train, train_size=0.7)

model.fit(x_train, y_train, epochs=100, batch_size=32,
          validation_data=(x_val, y_val), verbose=1)
```

### 방법 2 — `validation_split`으로 train 안에서 자동 분리 (더 간편)

```python
model.fit(x_train, y_train, epochs=100, batch_size=32,
          validation_split=0.3, verbose=1)   # train의 30%를 검증용으로 자동 분리
```

- 처음부터 3단으로 데이터를 나누는 것보다, **train 데이터를 통째로 넣고 `validation_split` 비율만 지정**하는 게 더 편하다.
- 두 방법의 **성능 차이는 없다.** 코드 편의성의 문제일 뿐 — 나중에 비율만 바꾸고 싶을 때 `validation_split` 방식이 조절하기 더 쉽다.

### `train_test_split`으로 3등분하는 법 (참고)

`train_test_split`은 한 번에 2개로만 나뉜다. 3등분하려면 **두 번 호출**해야 한다.

```python
# 1차: train / test 분리
x_train, x_test, y_train, y_test = train_test_split(x, y, test_size=0.25)
# 2차: train을 다시 train / validation으로 분리
x_train, x_val, y_train, y_val = train_test_split(x_train, y_train, test_size=0.33)
```

### 판단 원칙 — loss와 val_loss가 다르게 움직일 때

- **둘 다 함께 떨어지고 있다** → 아직 훈련이 부족하다. **epoch를 더 늘려라.**
- **loss는 계속 떨어지는데 val_loss가 핑퐁(oscillation) 친다** → **과적합(overfitting) 구간**에 진입했다는 신호.
- **두 값이 상반되게 움직이면(loss는 좋아지는데 val_loss는 나빠짐)** → **val_loss를 신뢰**하는 것이 원칙. 다만 데이터 분포(라벨 불균형 등) 상황에 따라 예외도 존재하므로 절대 법칙은 아니다.

## 4. 소요 시간 측정 — `time` 모듈

```python
import time

start_time = time.time()
model.fit(x_train, y_train, epochs=100, batch_size=32)
end_time = time.time()

print("걸린 시간:", round(end_time - start_time, 2), "초")
```

- `time.time()`은 현재 시각(초 단위 타임스탬프)을 반환한다.
- **시작 시각을 빼는 게 아니라 끝 시각에서 시작 시각을 뺀다** (`end - start`). 반대로 하면 음수가 나온다.
- `round(값, 2)` — 파이썬 기본 함수. 소수점 둘째 자리까지 반올림.
- **시간을 재는 위치**: 보통 `model.fit()` 구간만 측정한다. 데이터 전처리 시간이 아니라 **실제 훈련 시간**이 궁금하기 때문.

### 실전 활용 — 훈련 시간으로 향후 계획 세우기

- 100 epoch에 30분 걸렸다면 → 200 epoch는 대략 60분 예상 가능.
- "내일 아침까지 준비하라"는 요구를 받았는데, 1 epoch에 3시간이 걸린다면 남은 12시간 동안 **4 epoch밖에 못 돌린다** — 이런 걸 미리 계산해서 모델/데이터 크기를 조절하는 판단이 필요.
- 전기세, 자원(GPU/메모리), 납기 등 실무적으로 훈련 시간은 매우 중요한 지표.

## 5. `model.fit()`의 반환값 — `History` 객체

### 발견 과정

- `model.fit()`을 실행하면 화면에 loss가 출력된다. 이건 그냥 `print`가 아니라, **fit 함수 자체가 어떤 값을 반환(return)하고 있다**는 신호다.
- 반환값을 변수에 담아보면 무엇이 들어있는지 확인 가능:

```python
hist = model.fit(x_train, y_train, epochs=10, validation_split=0.2, verbose=1)
print(hist)
```

- 위처럼 출력하면 `<keras.src.callbacks.History object at ...>`처럼 **래핑(wrapping)된 객체** 형태로 나온다. 바로 내용이 보이지 않는다.
- 진짜 내용을 보려면 `.history` 속성을 확인:

```python
print(hist.history)
```

### 결과 형태 — 딕셔너리(Dictionary)

```python
{'loss': [803.56, 320.52, ...], 'val_loss': [810.2, 298.1, ...]}
```

- 파이썬 자료형 두 가지 핵심 개념:
  - **리스트(List)**: 두 개 이상의 값을 순서대로 모아놓은 것. `[1, 2, 3]`
  - **딕셔너리(Dictionary)**: **key-value(키-값)** 쌍으로 이루어진 자료형. `{'로스': 값, '발로스': 값}`
- `hist.history`는 딕셔너리이고, 그 안의 `'loss'`, `'val_loss'` 값은 각각 **리스트**로 저장되어 있다 (epoch마다 하나씩 쌓여서).
- **검증 방법**: `model.fit()` verbose 출력에서 직접 보였던 loss/val_loss 숫자와, `hist.history['loss']`, `hist.history['val_loss']`의 값을 하나씩 대조해보면 정확히 일치한다 — 즉 화면에 출력되던 값이 바로 이 History 객체에 담겨 있었던 것.
- AI 코딩에서 데이터는 대부분 **딕셔너리 아니면 리스트** 형태로 다뤄진다 — 이 두 가지가 90% 이상을 차지.

## 6. Matplotlib으로 loss / val_loss 시각화

```python
import matplotlib.pyplot as plt

plt.plot(hist.history['loss'], label='loss')
plt.plot(hist.history['val_loss'], label='val_loss')
plt.legend()
plt.title('Loss Graph')
plt.xlabel('epochs')
plt.ylabel('loss')
plt.show()
```

- 그래프로 보면 loss와 val_loss가 **동반 하락하는지, 어느 지점부터 val_loss가 튀는지(과적합 구간)** 를 한눈에 파악할 수 있다.
- **1 epoch 째 값이 지나치게 크게 나오는 경우**: 초기 가중치가 랜덤이라 갱신이 안 된 상태라서 그런 것 — 첫 지점 때문에 그래프 스케일이 뭉개져 보이면, **그래프를 그릴 때 2번째 epoch부터 슬라이싱**해서 그리면 나머지 흐름이 잘 보인다.

```python
plt.plot(hist.history['loss'][1:], label='loss')       # 1번째(index 0) 제외
plt.plot(hist.history['val_loss'][1:], label='val_loss')
```

> 이건 **분석 편의를 위한 시각화 트릭**일 뿐이며, 실제 훈련 로직이나 데이터를 조작하는 게 아니다.

### 과적합(Overfitting) 구간 읽는 법

- 그래프가 **꾸준히 우하향**하는 동안은 아직 학습이 부족한 상태 → epoch를 더 늘려도 좋다.
- val_loss 그래프가 **바닥을 찍고 다시 올라가기 시작하는 지점**이 바로 **overfitting이 시작되는 지점**이다.
- 그 지점 이후로 훈련을 더 시켜도 train loss는 계속 낮아지지만, 실제 일반화 성능(val_loss)은 오히려 나빠진다.
- 가장 좋은 모델은 **val_loss가 최소값을 찍는 지점**의 가중치다. (다음 개념인 EarlyStopping이 바로 이걸 자동으로 잡아주는 도구)

## 7. EarlyStopping — 조기 종료

### 필요성

- 그래프를 보고 "val_loss가 가장 낮았던 지점"을 사람이 눈으로 찾는 건 비효율적이고, 그 지점을 지나서도 계속 훈련시키는 건 시간·자원 낭비다.
- **EarlyStopping**: val_loss가 더 이상 개선되지 않으면 자동으로 훈련을 멈추는 콜백(callback) 함수.

### 핵심 개념 — patience(참을성)

```python
from tensorflow.keras.callbacks import EarlyStopping

es = EarlyStopping(monitor='val_loss', patience=10, mode='min', restore_best_weights=True)

model.fit(x_train, y_train, epochs=5000000, batch_size=32,
          validation_split=0.2, callbacks=[es], verbose=1)
```

| 파라미터 | 의미 |
|---|---|
| `monitor='val_loss'` | 어떤 지표를 기준으로 감시할지 |
| `patience=10` | val_loss가 **10번 연속** 개선되지 않으면 훈련을 멈춘다 |
| `mode='min'` | val_loss는 낮을수록 좋으므로 최소값 기준으로 판단 |
| `restore_best_weights=True` | 훈련을 멈출 때 **가장 좋았던 시점의 가중치로 복원** |

### patience 값 설정 전략

- **patience를 너무 작게 주면** — 진짜 최저점(global minimum)에 도달하기 전에 "국소적으로 잠깐 안 좋아 보이는 구간(local minima)"에서 성급하게 멈출 수 있다.
- **patience를 크게 주면** — 로컬 미니멈을 지나쳐서 더 깊은 최저점을 찾을 가능성이 커진다. 대신 불필요한 훈련도 늘어난다.
- **실전 전략**: `epochs`는 아주 크게(예: 500만) 잡아두고, **patience를 넉넉하게(예: 100)** 준 뒤 EarlyStopping이 알아서 최적 지점 근처에서 멈추게 하는 방식이 안전하다. 자동으로 멈추기 때문에 epochs를 크게 잡아도 실제로는 필요한 만큼만 돈다.
- patience가 너무 크면 필요 이상으로 도는 것 아니냐는 우려가 있지만, 그 이상은 어차피 계속 갱신되지 않는 이상 곧 다시 멈추게 되므로 큰 낭비는 아니다.

### 로스값에서 최저 지점 확인하는 법 (수동 검증)

- EarlyStopping이 몇 번째 epoch에서 멈췄는지 확인한 뒤, `patience` 값만큼 거꾸로 세면 실제 최적 지점을 찾을 수 있다.
- 예: 총 39 epoch에서 멈췄고 patience=10이라면 → **29번째 epoch가 실제 최적점**(29 + 10 = 39에서 종료).
- `hist.history['val_loss']` 리스트에서 해당 인덱스의 값을 직접 대조해서 검증 가능.

### 두 지표가 다를 때의 최종 판단

- loss와 val_loss가 함께 계속 떨어지고 있다면 → 아직 훈련 부족, 더 훈련.
- 과적합 구간(핑퐁 구간)에 들어서면 → 그 지점에서 멈추는 것이 맞다.
- 판단이 애매하면 **재훈련해서 같은 패턴이 반복되는지 확인** — 반복되면 val_loss를 신뢰, 아니면 다시 판단.

### PyTorch에서도 사용

- EarlyStopping은 특정 프레임워크 전용 기능이 아니라 **모델 개발 전반에서 반드시 쓰이는 개념**이다. PyTorch로 넘어가도 (직접 구현하더라도) 반드시 필요.

---

## 8. Overfitting(과적합) 개념 정리

- 훈련을 너무 많이 시키면 모델이 **train 데이터에만 지나치게 최적화**되어, 오히려 새로운 데이터(val/test)에 대한 성능이 떨어지는 현상.
- 그래프상으로는 val_loss가 **어느 지점을 찍고 다시 올라가는** 형태로 나타난다.
- "많이 훈련시키는 것"과 "적당히 많이 훈련시키는 것"은 다르다 — **최적점을 지나면 오히려 역효과**.
- EarlyStopping은 이 최적점을 사람이 눈으로 찾지 않고 자동으로 감지해서 멈추게 하는 도구.

## 9. 실무 팁 · 코드 습관

- 파일을 복사(카피)해서 새 실습 파일을 만들 때는 **원본 파일명을 주석으로 명시**해두면, 나중에 "이 파일이 어디서 파생됐는지" 추적하기 쉽다.
- 여러 데이터셋(California, Diabetes, Boston, 따릉이, Kaggle Bike)에 같은 기법(validation, EarlyStopping 등)을 적용하는 반복 실습을 통해 코드 작성 속도를 끌어올리는 것이 목표.
- 항상 **가장 좋은 하이퍼파라미터(best tuning 값)를 기준으로** 새로운 기법(validation, EarlyStopping 등)을 추가 실습해야 한다 — 튜닝값과 신규 기법을 동시에 무작위로 바꾸면 어떤 게 성능에 기여했는지 판단할 수 없다.

## 부록 — Validation + EarlyStopping + History 시각화 전체 템플릿

```python
import numpy as np
import pandas as pd
import time
import matplotlib.pyplot as plt
from tensorflow.keras.models import Sequential
from tensorflow.keras.layers import Dense
from tensorflow.keras.callbacks import EarlyStopping
from sklearn.model_selection import train_test_split
from sklearn.metrics import r2_score, mean_squared_error

# ===== #1 데이터 =====
x_train, x_test, y_train, y_test = train_test_split(
    x, y, train_size=0.75, random_state=337
)

# ===== #2 모델 =====
model = Sequential()
model.add(Dense(64, input_dim=x.shape[1], activation='relu'))
model.add(Dense(32, activation='relu'))
model.add(Dense(16, activation='relu'))
model.add(Dense(1))

# ===== #3 컴파일 · 훈련 =====
model.compile(loss='mse', optimizer='adam')

es = EarlyStopping(monitor='val_loss', patience=50, mode='min',
                    restore_best_weights=True)

start_time = time.time()
hist = model.fit(x_train, y_train, epochs=5000000, batch_size=32,
                  validation_split=0.2, callbacks=[es], verbose=1)
end_time = time.time()

print("걸린 시간:", round(end_time - start_time, 2), "초")

# ===== #4 평가 · 예측 =====
loss = model.evaluate(x_test, y_test)
y_predict = model.predict(x_test)

def RMSE(y_test, y_predict):
    return np.sqrt(mean_squared_error(y_test, y_predict))

print("loss :", loss)
print("R2   :", r2_score(y_test, y_predict))
print("RMSE :", RMSE(y_test, y_predict))

# ===== 시각화 =====
plt.figure(figsize=(9, 6))
plt.plot(hist.history['loss'], label='loss')
plt.plot(hist.history['val_loss'], label='val_loss')
plt.legend()
plt.title('Loss / Val_Loss')
plt.xlabel('epochs')
plt.ylabel('loss')
plt.grid()
plt.show()
```
