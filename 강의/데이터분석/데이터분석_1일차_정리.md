## 1. 보간법 (Interpolation)

### 개념
- **보간(補間)**: 알고 있는 **점과 점 사이의 값을 추정**해서 채우는 것
- **선형 보간(linear)**: 두 점을 직선으로 잇고 그 위의 값을 사용
- **쌍선형 보간(bilinear)**: 4개 점이 있을 때, 두 점의 중간 → 다른 두 점의 중간 → 그 두 중간값의 중간을 구함. 이미지 확대/축소 등에서 사용 (Mask R-CNN 의 RoIAlign 등)
- 사용처: **결측치 처리**, **이상치 처리**, 이미지 확대·축소

> 데이터를 보고 "여기엔 4가 들어가겠네" 하고 머릿속으로 판단했다면, 이미 머릿속에서 선형 보간을 한 것.

### pandas에서 사용
`Series`와 `DataFrame` 모두 `.interpolate()`를 제공 (기본값 `method='linear'`).

```python
import numpy as np
import pandas as pd

dates = pd.to_datetime(['2025-11-01','2025-11-02','2025-11-03','2025-11-04','2025-11-05',
                        '2025-11-06','2025-11-07','2025-11-08','2025-11-09'])
# pd.to_datetime → 판다스의 datetime 타입. 인덱스로 쓰기 위해 생성

ts = pd.Series([2, np.nan, 6, 8, np.nan, 12, np.nan, 16, np.nan], index=dates)
print(ts.interpolate())
# [2, 4, 6, 8, 10, 12, 14, 16, 16]
```

**동작 규칙 (시험·실무 포인트)**
| 위치 | 결과 |
|---|---|
| 중간 NaN | 앞뒤 값으로 **선형 보간** |
| **마지막** NaN | 직전 값으로 채워짐 (ffill 처럼) |
| **첫 번째** NaN | **채워지지 않음** → 직접 처리해야 함 (`bfill`, 평균, 0 등) |

```python
ts.iloc[0] = np.nan
ts.interpolate()           # 첫 값은 여전히 NaN
ts.interpolate().bfill()   # 첫 값은 뒤의 값으로 따로 채움
```

**인덱스는 데이터가 아니다**
- `print(ts)` 할 때 앞에 보이는 날짜는 **인덱스**. 연산 시 제외됨
- 하지만 날짜 인덱스는 **연/월/일/요일/주말·평일/휴일** 등 파생 피처를 만들 수 있는 아주 좋은 재료

> ⚠️ interpolate는 시계열처럼 "선형으로 이어지는 데이터"에서 깔끔하게 나오지만 **무조건 신뢰하면 안 됨**. 데이터 분석이 같이 들어가야 함.

## 2. 결측치 처리 방법 총정리

| # | 방법 | 설명 / 주의점 |
|---|---|---|
| 1 | **삭제** | 행 삭제(주로) 또는 열 삭제. 셀 하나만 지우는 건 불가능. 데이터가 적으면 치명적 |
| 2 | **임의의 값 채우기** | 0, 평균(mean), 중위값(median), 최빈값, 앞값(ffill), 뒷값(bfill), 특정값(777 등) |
| 3 | **보간** | `interpolate()` |
| 4 | **모델로 예측** | 결측치 있는 컬럼을 y, 나머지를 x로 두고 학습 → predict로 채움 |
| 5 | **부스팅/트리 계열 모델** | XGBoost, LightGBM, CatBoost는 결측치를 **자체적으로 처리** |
| 6 | (참고) 랜덤값 등 | 비추천 |

> 이상치는 **RobustScaler**로 어느 정도 대응 가능하지만, **결측치는 별도로 처리해야 함**.

### 2-1. 각 방법의 함정
- **0으로 채우기**: `2, 0, 6, 8, 10, 0, 14, 16` → 선형 데이터가 완전히 망가짐
- **평균**: 이상치에 취약 (데이터에 10억 같은 값이 하나 있으면 평균이 끌려감)
- **중위값(median)**: 평균보다 이상치에 **안정적**
- **ffill/bfill**: 온도처럼 앞뒤 값이 비슷한 데이터에 적합. 몇 분 사이 15도 → 230도로 튀지 않으니까
- **어설픈 전처리 = 데이터 조작**. 확신이 없으면 오히려 **삭제가 가장 깔끔**할 수 있음
- 단, 데이터 100개 중 결측치 40개 같은 상황에서 삭제하면 끝장

### 2-2. 모델로 예측해서 채우기 (방법 4)
1. 결측치가 있는 컬럼을 **y**, 나머지를 **x**로 둔다
2. 값이 있는 행으로 학습 → 가중치 생성
3. 그 가중치로 결측 행을 `predict`
- 문제점: 그 모델에 **과적합**될 수 있음
- 같은 모델을 두 번 쓰면 사실상 과적합 → 채울 때와 실제 학습할 때 **서로 다른 모델**을 쓰는 게 낫다

### 2-3. 부스팅 계열이 결측치에 강한 이유 (방법 5)
- 트리 구조는 "어떤 값보다 크면 왼쪽, 작으면 오른쪽" 식으로 분기
- XGBoost는 학습할 때 **결측값이 갈 기본 방향(default direction)** 을 분기마다 같이 학습함 → NaN이 있어도 학습이 돌아감
- 트리 분기는 값의 크기 순서만 보므로 극단적인 이상치가 와도 결국 어느 한 구간에 들어감 → 이상치 영향이 상대적으로 적음
- `n_estimators` = 트리(부스팅 라운드)를 몇 개 만들지 = **에포크처럼 생각** (XGBoost 기본값 **100**)
- 선생님 실험: XGBoost에 결측치 그대로 넣은 결과 ≈ 직접 예측으로 채운 뒤 XGBoost 돌린 결과
- 그래도 **100% 신뢰 금물** — 빠르게 값을 뽑아 기준을 잡는 용도로는 좋음

> 딥러닝은 NaN이 있으면 `y = wx + b` 연산 자체가 안 됨 (Dropout은 노드를 끄는 것이지 NaN과는 다름).

## 3. pandas로 결측치 처리 (`pd02`)

### 데이터 준비
```python
data = pd.DataFrame([[2, np.nan, 6, 8, 10],
                     [2, 4, np.nan, 8, np.nan],
                     [2, 4, 6, 8, 10],
                     [np.nan, 4, np.nan, 8, np.nan]])
data = data.T                      # 행/열이 거꾸로 들어갔으니 전치(transpose)
data.columns = ['x1', 'x2', 'x3', 'x4']
```
```
     x1   x2   x3   x4
0   2.0  2.0  2.0  NaN
1   NaN  4.0  4.0  4.0
2   6.0  NaN  6.0  NaN
3   8.0  8.0  8.0  8.0
4  10.0  NaN 10.0  NaN
```

### 3-1. 결측치 확인
```python
data.isnull()          # True = 결측치 위치  (isna()와 동일)
data.isnull().sum()    # 컬럼별 결측치 개수 → x1:1, x2:2, x3:0, x4:3  ★ 외우기
data.info()            # Non-Null Count 로 확인
```

### 3-2. 삭제 `dropna`
```python
data.dropna()          # 기본값 axis=0 → NaN 있는 '행' 삭제 → 3번 행만 남음
data.dropna(axis=0)    # 행 삭제
data.dropna(axis=1)    # NaN 있는 '열' 삭제 → x3만 남음
```
> axis=0 → 행, axis=1 → 열

### 3-3. 채우기 `fillna` / `ffill` / `bfill`
```python
data.fillna(0)              # 특정값 0
data.fillna(777)            # 특정값 777
data.fillna(data.mean())    # 각 '열'의 평균  (x1=6.5, x2≈4.67, x4=6.0)
data.fillna(data.median())  # 각 열의 중위값
data.ffill()                # 앞의 값으로 채움 (forward fill)  → 첫 행 NaN은 그대로
data.bfill()                # 뒤의 값으로 채움 (backward fill) → 마지막 행 NaN은 그대로
```
> ⚠️ **pandas 3.0 변경**: 예전 `fillna(method='ffill')` 방식은 제거됨 → `ffill()` / `bfill()` 사용
> ffill은 첫 값, bfill은 마지막 값이 NaN으로 남으니 **한 번 더 처리** 필요

### 3-4. 컬럼별로 처리하기 ★ 실무 권장
데이터프레임 **전체**에 같은 방법을 쓰는 건 **매우 위험**.
컬럼마다 성격이 다르기 때문 (온도 데이터 vs 수익률 데이터 등).

```python
means = data['x1'].mean()      # 6.5
med   = data['x4'].median()    # 6.0

data['x1'] = data['x1'].fillna(means)   # x1 → 평균
data['x2'] = data['x2'].ffill()         # x2 → 앞값 (마지막이 NaN이라 ffill이 적합)
data['x4'] = data['x4'].fillna(med)     # x4 → 중위값
print(data)                             # 결측치 모두 처리됨
```
> 무엇을 고를지는 **경험 + 실력 + 데이터 분석**으로 판단. (선생님 경험상 컬럼 4천 개짜리 데이터도 있었는데, 그런 경우는 컬럼별로 하나하나 할 수 없음)

## 4. scikit-learn Imputer

sklearn에는 교육용 데이터, 레거시 머신러닝 모델, 전처리 도구가 다 들어 있음 (신형 모델은 Hugging Face).
**Imputer는 Scaler와 사용법이 동일** → `fit`, `transform`, `fit_transform`

```python
from sklearn.impute import SimpleImputer, KNNImputer
from sklearn.experimental import enable_iterative_imputer   # ★ 반드시 먼저 import
from sklearn.impute import IterativeImputer
```

> `IterativeImputer`는 아직 **experimental(실험적)** 기능이라 `enable_iterative_imputer`를 먼저 import하지 않으면 에러. (`HalvingGridSearchCV`도 같은 방식)
> 대문자로 시작 → **클래스**. 객체를 만들어서 사용.

### 4-1. SimpleImputer — `strategy` 파라미터
```python
imputer = SimpleImputer()                       # 기본값 strategy='mean'
data2 = imputer.fit_transform(data)             # 평균

SimpleImputer(strategy='mean')                  # 평균
SimpleImputer(strategy='median')                # 중위값
SimpleImputer(strategy='most_frequent')         # 최빈값
SimpleImputer(strategy='constant', fill_value=777)   # 특정값
```
| strategy | 의미 |
|---|---|
| `mean` (기본) | 평균 |
| `median` | 중위값 |
| `most_frequent` | 최빈값 (같으면 작은 값) |
| `constant` + `fill_value` | 지정한 특정값 |

> pandas `fillna`로 하든 sklearn `Imputer`로 하든 **편한 쪽 쓰면 됨**. Imputer는 결과가 **numpy 배열**로 나온다는 점만 주의.

### 4-2. KNNImputer
```python
imputer = KNNImputer()                 # n_neighbors 기본값 5
data2 = imputer.fit_transform(data)
```
- **KNN (K-Nearest Neighbors)**: 가장 가까운 이웃 K개를 보고 판단
  - 분류: 가까운 K개 중 다수 클래스로 결정 (K=3 → B 2개, A 1개 → B)
  - Imputer: 가까운 이웃(행)들의 값의 평균으로 결측치 채움
- 거리는 **유클리드 거리** = 두 점 사이의 직선 거리 `√Σ(a-b)²`
- 원래 sklearn의 **모델**이지만 결측치 처리에도 사용. 이상치를 NaN으로 바꾼 뒤 쓸 수도 있음
- 원래라면 모델 구성 → predict 해야 하는 걸 **간편하게 해준 게 Imputer**

> 면접에서는 "잠시만요 검색해볼게요"가 안 됨 → 유클리드 거리, 어텐션 등 기본 개념은 **말로 설명할 수 있게** 준비

### 4-3. IterativeImputer ★ 오늘의 하이라이트
**Iterative = 반복적**. 결측치 컬럼을 하나씩 y로 두고, 나머지를 x로 회귀 모델 학습 → 예측으로 채움 → 이를 반복.
= 2-2에서 말한 "모델로 예측해서 채우기"를 자동화한 것.

```python
from xgboost import XGBRegressor

xgb = XGBRegressor(max_depth=5)       # n_estimators 기본 100

imputer = IterativeImputer(
    estimator=xgb,       # 채울 때 사용할 모델 (평가자)
    max_iter=10,         # 최대 반복 횟수
    tol=0.001,           # 조기 종료 기준 (기본값 0.001)
    random_state=333,
)
data2 = imputer.fit_transform(data)
print(data2)
print(imputer.n_iter_)  # 실제 반복 횟수 (끝에 언더바 _ 가 붙은 속성 = 학습 후 생긴 값)
```

**동작 이해**
- 결측치 있는 컬럼이 3개(x1, x2, x4) → 한 번의 iteration에서 **모델 3번 학습** (각 100 트리)
- `max_iter=10` → 최대 10 × 3 = **30번 학습**
- `n_iter_`가 2~3으로 나오는 이유 → **자동 조기 종료(early stop)** (환경마다 조금 다를 수 있음)
- 조기 종료 기준: 직전 iteration 대비 값의 변화량이 `tol × (데이터의 최대 절댓값)` 보다 작으면 멈춤
  - 예: 최대값 12 × 0.001 = 0.012 → 변화량이 이보다 작으면 "더 돌려도 미미하다" → 종료
- 헷갈리면 `estimator`, `max_iter` 정도만 써도 충분히 좋은 결과

> XGBoost, LightGBM, CatBoost(부스팅 3대장)는 머신러닝 중 느린 편이라 **GPU 학습**도 지원. `n_estimators`를 늘리고 early stopping을 함께 쓰는 게 일반적.

## 5. loc / iloc ★★★ (판다스에서 제일 헷갈리는 부분)

### 실습 데이터
```python
data = [['삼성', 2000, 2100],
        ['현대', 1500, 1700],
        ['LG',   2500, 2400],
        ['아모레', 3500, 6000],
        ['네이버', 100, 1500]]
index   = ['031', '059', '033', '045', '023']
columns = ['종목명', '시가', '종가']

df = pd.DataFrame(data, index=index, columns=columns)
```
- 실제 데이터는 `삼성 ~ 1500` 부분. **인덱스와 컬럼명은 연산에 포함되지 않음**
- `df * 2` 같은 연산을 하면 안의 값들만 연산됨 (판다스의 강력한 점)

### 5-1. 판다스 열행 ★ 외우기
리스트는 `data[0]` → 0번째 **행**. 하지만 판다스 `df[...]`는 **열(컬럼) 기준**.

```python
df[0]              # ❌ KeyError
df['045']          # ❌ KeyError  (인덱스명도 안 됨)
df[3, 1]           # ❌ KeyError
df['종목명']        # ✅ 열이 나옴!
df['종목명']['045'] # ✅ 열 → 행 순서 (거꾸로 하면 KeyError)
```
> **"판다스 열행"** — 대괄호를 바로 쓰면 **열이 먼저**.
> 왜? 판다스는 데이터 분석용으로 만들어졌고, 데이터에서 가장 중요한 건 **컬럼**이니까.

### 5-2. 행렬처럼 쓰고 싶으면 → `loc` / `iloc`
| | 원래 뜻 | 이렇게 기억하기 | 넣는 값 |
|---|---|---|---|
| `iloc` | index location | **int location** | **숫자(위치)** 만 — 0, 1, 2, 3... |
| `loc` | location | **인덱스 이름 / 컬럼명** | **문자(라벨)** — '045', '종가' |

- 둘 다 **[행, 열]** 순서 (일반 행렬과 동일)
- `iloc`에 문자 넣으면 바로 에러 / `loc`에 위치 숫자 넣으면 에러
- 이름이 index location이라 "인덱스 값('045')을 넣는 건가?" 하고 헷갈림 → **iloc의 i는 int** 로 생각

```python
df.iloc[3]            # ✅ 4번째 행 (아모레)
df.loc['045']         # ✅ 인덱스 '045' 행 (아모레)

df.iloc['045']        # ❌ TypeError (iloc엔 숫자만)
df.loc[3]             # ❌ KeyError  (3이라는 인덱스 라벨 없음)
```

### 5-3. 특정 값 하나 뽑기 — 아모레의 종가 (6000)
```python
df.iloc[3, 2]             # ✅ 6000  (3행 2열, 0부터 셈)
df.loc['045', '종가']     # ✅ 6000

df.iloc[3, '종가']        # ❌ 섞어 쓰기 안 됨
df.loc['045', 2]          # ❌ 섞어 쓰기 안 됨
df.iloc[3][2]             # ❌ KeyError ← pandas 2.x에선 됐지만 3.0에서 안 됨
```

**체이닝으로 섞어 쓰기 (가독성 좋음, 실수 적음)**
```python
df.iloc[3]['종가']        # ✅ 6000  (뒤의 [ ]는 판다스 방식 → 라벨)
df.iloc[3].iloc[2]        # ✅ 6000
df.iloc[3].loc['종가']    # ✅ 6000
df.loc['045'].loc['종가'] # ✅ 6000
df.loc['045'].iloc[2]     # ✅ 6000
```
> 한 대괄호 안에서 섞으면 에러, **`.loc[...]` / `.iloc[...]`를 따로 이어 붙이면** 섞어 써도 OK.

### 5-4. 범위 뽑기 (`pd06_loc_iloc_2_범위.py`) — 아모레·네이버의 시가 (3500, 100)
```python
df.iloc[3:5, 1]                 # ✅ [3500, 100]  iloc 슬라이싱은 끝 미포함 (3, 4)
df.loc['045':'023', '시가']      # ✅ [3500, 100]  loc 슬라이싱은 끝 포함!

df.iloc[3:5, '시가']             # ❌ 섞어 쓰기 안 됨

# 체이닝 버전
df.iloc[3:5]['시가']             # ✅
df.iloc[3:5].iloc[:, 1]          # ✅
df.loc['045':'023'].iloc[:, 1]   # ✅
df.iloc[3:5].loc[:, '시가']      # ✅
```
> ⚠️ **`iloc` 슬라이싱은 끝 미포함** (리스트와 같음), **`loc` 슬라이싱은 끝 포함** (라벨 기준이라)
> 가장 안정적인 방식: **앞(행)은 loc 또는 iloc, 뒤(열)는 iloc**

### 5-5. 한 줄 요약
```
판다스 [ ]    → 열행 (열 먼저)
loc / iloc   → 행렬 (행 먼저)
iloc의 i     → int  (숫자 위치만)
loc          → 인덱스명 / 컬럼명 (문자 라벨)
섞어 쓰기     → 한 대괄호 안 ❌ / .loc[].iloc[] 체이닝 ✅
```
> 어떤 방식을 쓸지는 **팀/회사 코드 스타일과 가독성**에 맞추면 됨. 회사 코드를 혼자 마음대로 바꾸는 건 비추.
