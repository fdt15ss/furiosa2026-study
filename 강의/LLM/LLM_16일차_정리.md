## 2. WSL 리눅스 사용법 (핵심 실습)

### 2-1. 왜 PowerShell에서 접속하는가

- Windows 터미널에서 그냥 `wsl`만 입력하면 **기본(대표) 배포판 하나**로만 들어감
- 우분투 등 리눅스를 **여러 개(10개, 20개) 설치**해서 쓸 수 있으므로, **이름을 지정해서 접속**하는 방식이 편함
- 나중에 NPU 서버 접속도 이런 방식으로 하게 됨

### 2-2. 주요 명령어

| 명령어 | 의미 |
|---|---|
| `wsl -l -v` | 설치된 배포판 목록 + 버전/상태 확인 (`-l` list, `-v` verbose) |
| `wsl -l -o` | 설치 가능한 리눅스 배포판 목록 확인 (online) |
| `wsl -d <배포판이름>` | 특정 배포판으로 접속 (`-d` distribution) |
| `exit` | 리눅스에서 빠져나오기 |

- `wsl -l -v` 결과에서 **별표(\*)** 가 붙은 것이 기본(대표) 배포판
- 별표 없는 다른 배포판은 `wsl -d 이름`으로 접속해야 함
- PowerShell 창을 여러 개 열어 **여러 리눅스에 동시에 접속**해 작업 가능

### 2-3. 화면 지우기

- Windows 명령 프롬프트: `cls` (clear screen)
- 리눅스: `clear`

### 2-4. 패키지 업데이트

```bash
sudo apt update      # 패키지 목록 최신화 (리눅스 처음 설치하면 보통 먼저 실행)
sudo apt upgrade     # 실제 업그레이드 (이번 수업에서는 생략해도 된다고 함)
```

## 3. Hermes 에이전트 확인 및 실행

### 3-1. 정상 설치 확인

```bash
hermes gateway status
```

- 결과에 **enabled**가 나오면 정상
- 설치 시 "시작할 때 자동 실행" 옵션을 체크했다면 그 상태가 유지되어 있어야 함
- OpenClaw도 비슷하지만 **설치 방법만 조금 다름**

### 3-2. 실행 방식

- `hermes` : 터미널(커맨드창)에서 바로 채팅
- `hermes dashboard` : 웹 대시보드(세션/채팅 화면)로 사용 → 터미널보다 편함
- 대시보드 종료: `Ctrl + C` (이때 종료되는 건 대시보드뿐, **게이트웨이는 계속 실행 중**)

## 4. 텔레그램 봇 만들고 Hermes와 연동하기

### 4-1. 준비

- 웹 텔레그램(Telegram Web)에 로그인 (QR 코드 또는 인증번호) — **데스크탑 앱 설치는 불필요**

### 4-2. 봇 생성 (BotFather)

1. 텔레그램에서 **BotFather** 검색 후 열기
2. **Create a New Bot** (`/newbot`) 선택
3. **봇 이름(Name)** 입력 — 표시되는 이름, 임의로 지정 가능
4. **봇 사용자명(Username)** 입력
   - **다른 사람과 중복되면 안 됨** → 본인 번호(자리 번호 등)를 붙여서 고유하게 만들기
   - **반드시 `bot`으로 끝나야 함**
   - "available"이 표시되면 사용 가능
5. 생성되면 **API 토큰**이 발급됨 → 복사

### 4-3. 내 텔레그램 User ID 확인

- 텔레그램 검색창에서 `@userinfobot`, `@get_id_bot` 같은 ID 확인 봇 검색 → **Start**
- 숫자(약 10자리) ID가 나오면 그게 내 User ID
- 한 봇이 안 되면 다른 봇으로 시도
- 다른 사람 ID를 따라 쓰지 말고 **반드시 본인 ID** 사용

### 4-4. Hermes에 연결

1. WSL 터미널(Hermes 배포판)에서 텔레그램 설정 진행
2. **Automatic / Manual** 중 **Manual(2번)** 선택 (Automatic은 잘 안 붙는 경우가 많음)
3. **봇 토큰** 붙여넣기
   - 터미널 붙여넣기는 **마우스 우클릭** (Ctrl+V가 아님)
4. **내 User ID** 입력
5. **Home channel로 사용할지** → `Yes` (기본값, 엔터)
6. **게이트웨이 재시작할지** → `Yes`

### 4-5. 동작 확인

- 텔레그램에서 내가 만든 **봇 사용자명 검색 → Start** → 인사하면 응답
- 핸드폰 텔레그램에서도 동일하게 동작하는지 확인
- 이후 텔레그램으로 작업을 지시하고 결과를 이메일/작업 폴더로 받는 식의 활용이 가능
  - 폴더 관리, 문서 작성, 이메일, 구글 드라이브, 캘린더 연동까지 가능

## 5. AI 에이전트 사용 시 주의사항

- **할루시네이션**: 거짓말을 할 수 있으니 결과를 그대로 믿지 말 것
- **권한을 너무 많이 주지 말 것**
  - 작업 폴더를 **한정**해서 "이 폴더에서만 작업해라"로 제한
  - 잘못하면 내 PC를 포맷하는 등 큰 사고 가능
- **이메일 삭제 같은 작업은 절대 시키지 말 것** — 중요한 메일을 한꺼번에 지워버릴 수 있음
- 비유: **"아주 똑똑한 신입사원인데 한국말을 잘 못 알아듣는 사람"** 이라고 생각하고 구체적으로 지시
- 다른 도구(Codex, 업스테이지 무료 모델, Claude Code 등)도 같이 써보며 비교해 보기

## 6. 미니 프로젝트 발표 규칙

| 항목 | 내용 |
|---|---|
| 제출물 | **PPT 1개 + PDF 1개** (PPT가 안 열릴 경우 대비), 제목은 **미니 프로젝트 팀명** |
| 발표 시간 | **무조건 10분 컷** — 타이머로 재고 10분이 되면 발표 중단, 초과 시 감점(사실상 탈락 수준) |
| 슬라이드 수 | 제한 없음 (500장도 가능하지만 10분 안에 끝내야 함) |
| 발표 속도 | 수업 때 강사가 설명하는 정도의 속도로, 랩처럼 빠르게 하지 말 것 |
| 질의응답 | **시간 무제한** — 궁금증이 다 풀릴 때까지 |
| 발표자 선정 | **당일 랜덤으로 1명 지정** (팀 5명이면 내가 걸릴 확률 1/5) |
| 필수 내용 | **핵심 코드 2페이지 이상** 포함 |

### 포인트

- 모든 팀원이 **자기 팀 PPT 전체를 숙지**하고 있어야 함 (누가 뽑힐지 모름)
- 팀이 "한 명만 취업시키고 싶다"면 그 한 명만 준비해도 되지만, 그 경우 **그 사람만** 평가에 반영
- 코드 페이지는 **뒷자리에서도 보이는 글씨 크기**로, 성의 있게
- 코드 2페이지에 대해서는 **세부적인 부분까지 질문**함
  - 프로젝트 성격상 당연히 들어가야 할 내용/코드가 빠져 있으면 질문이 나옴
- PPT 제출 직후부터 **발표 연습**, 시간 재면서 연습
- 실무에서도 발표는 보통 **10~15분 컷**이 가장 많고, 시간 초과하면 하고 싶은 말을 못 하게 됨
