## 1. 복습: 아키텍처를 이해해야 하는 이유

- 흐름: **LSTM/GRU의 한계 → 어텐션 → 트랜스포머 → LLM**. 전부 이어져 있어서 외우든 이해하든 해야 한다.
- 랭체인은 함수·클래스로 모듈화가 잘 되어 있어 "가져다 쓰기"는 쉽지만, **커스터마이징이나 직접 만들어야 할 때** 아키텍처를 모르면 막힌다.
- 면접에서 자주 나오는 질문
  - 셀프 어텐션 vs 멀티헤드 어텐션의 차이
  - 멀티헤드 어텐션 vs 마스크드 멀티헤드 어텐션의 차이
- 연구 예시: **Normalization과 Feed Forward의 위치만 바꿔도** 성능이 달라진다 (Pre-LN / Post-LN 계열). 이런 구조 변경만으로도 논문이 나온다.

## 2. 복습: 케라스 함수형 API 앙상블

### 2-1. 두 가지 접근
1. **데이터를 합쳐서 단일 모델**로 학습
2. **모델을 분기/병합**하는 앙상블 (데이터셋별 모델을 따로 만든 뒤 합침)

→ 어떤 게 더 좋은지는 **다 해봐야 안다**. 선택지를 모두 구현할 수 있어야 한다.

### 2-2. 합치기와 나누기
- **합치기**: `concatenate` (merge)
- **분기**: 한 레이어의 출력을 여러 갈래 레이어에 각각 연결
- 분기 → 병합 → 다시 분기 구조도 가능 (Skip connection처럼 활용)
- 서로 영향을 주기 때문에 **항상 성능이 좋다고는 할 수 없다**

### 2-3. 실습: 단일 입력 → 다중 출력
- 앞서 만든 파일(69번대)을 복사해서 시작
- `x2`, `x3` 입력을 삭제하고 **단일 입력 모델**로 변경
- 출력은 3개든 5개든 원하는 만큼 분기 (병합 이후 분기 모델의 입력으로 연결)
- 나머지는 동일, **예측값(y) 부분만 수정**

## 3. 실습 과제: 삼성전자 내일 시가 예측

### 3-1. 문제 조건
- **목표**: 내일 아침 삼성전자의 **시가(Open)** 맞추기
- 데이터: 삼성전자 / 아모레퍼시픽 / SK하이닉스 일별 주가 CSV 3개 (**원본 수정 금지**, 파일명 변경 금지)
- **앙상블** 사용
- 모델별 입력 **컬럼 5개 이상**
  - 파생변수는 여러 개 만들어도 **원본 컬럼 1개당 1개로 인정** (날짜 → 연/월/요일 = 1개)
- 모델은 **LSTM**과 **Conv1D**를 각각 사용
- 삼성 모델은 컬럼을 하나만 써도 되고, 앙상블 모델을 하나 더 만들어도 됨
- **시가는 반드시 y**. X에 넣으면 안 됨
- **시계열 데이터 → split을 반드시 시간순으로** (랜덤 셔플 금지)
- 오늘 날짜(10월 12일) 행은 현재 시점 종가라 값이 바뀔 수 있음
- CPU/GPU 상관없음, 팀원 간 논의 가능 (가중치·코드 그대로 복사는 금지)

### 3-2. 파일/경로 규칙
- 파일: `keras70_...py` 형태, 파일이 여러 개면 `70-1`, `70-2` 식으로 번호 부여
- 데이터는 `삼성` 폴더 안에 CSV 3개를 함께 보관
- 가중치 저장 경로: `./_save/keras70/` 아래 (경로를 바꾸지 말 것)

### 3-3. 데이터 읽기 팁
```python
import pandas as pd

# 한글 CSV는 인코딩 때문에 에러가 자주 난다
try:
    df = pd.read_csv('./삼성/삼성전자.csv', encoding='utf-8')
except UnicodeDecodeError:
    df = pd.read_csv('./삼성/삼성전자.csv', encoding='euc-kr')
```
- `read_csv`에서 멈추면 대부분 인코딩 문제 (`euc-kr` 또는 `utf-8`)

### 3-4. 제출물 3종 (메일 제목: **본인 이름 + 예측 가격**만)
1. **학습 코드 `.py`** (모델 구성 → 학습 → 가중치 저장)
2. **예측 전용 `.py`** (저장된 가중치와 스케일러를 로드 → 바로 가격 출력)
3. **가중치 파일**

핵심 포인트
- 예측 코드는 **학습 없이 가중치만 불러와서** 가격이 바로 찍혀야 한다
- **스케일러도 fit한 것을 저장**해 두었다가 예측 코드에서 다시 로드해야 같은 결과가 나온다 (`joblib` / `pickle`)
- 예측값은 소수점이 길어도 되고 **반올림해도 무방**
- 수정본을 다시 보내면 **마지막 제출본**을 인정
- 가중치를 깜빡하고 안 보냈으면 다시 보내면 됨

### 3-5. 보충 (강의 외 팁)
- 스케일러는 **train 구간에만 fit**하고 test에는 `transform`만 적용해야 정보 누수를 막을 수 있음
- 시계열 모델 입력은 `(samples, timesteps, features)` 형태로 만들어야 하고, LSTM과 Conv1D 모두 이 3차원 입력을 사용
- 주가처럼 **데이터 수가 적은 정형 데이터**는 딥러닝보다 트리 부스팅 계열이 더 잘 맞을 때도 있음 (아래 특별 탭 참고)

## 4. 랭체인 챗봇에 대화 히스토리 붙이기 (Gradio)

### 4-1. 문제 상황
- 벡터DB + RAG 체인만 있으면 `나는 OOO이야` 라고 말한 뒤 `내가 누구게?` 라고 물어도 **기억하지 못한다**. 매 호출이 독립적이기 때문
- ChatGPT 웹은 이전 대화를 같이 보내기 때문에 기억하는 것처럼 보임
- 랭체인 자체 메모리 기능은 약해졌고, 이후 **LangGraph** 쪽에서 다룰 예정
- 지금은 **Gradio의 `history`**를 활용

### 4-2. Gradio `ChatInterface`의 두 인자
```python
def answer(message, history):
    ...
```
| 인자 | 의미 |
|---|---|
| `message` | 방금 사용자가 입력한 문장 (파이썬 `input`과 비슷) |
| `history` | 지금까지의 대화 전체 (Gradio가 자동 관리) |

`history`의 형태 (Gradio가 만들어 줌):
```python
[
    {"role": "user", "content": "안녕"},
    {"role": "assistant", "content": "안녕하세요"},
    {"role": "user", "content": "나는 윤영선이다"},
    {"role": "assistant", "content": "당신은 윤영선이군요"},
]
```
- `user` / `assistant`는 **Gradio 규약**이다. FastAPI 등 다른 환경에서는 형태가 다를 수 있으니, 환경별로 맞춰 변환해야 한다.

### 4-3. 프롬프트에 히스토리 자리 만들기: `MessagesPlaceholder`
기존 `ChatPromptTemplate.from_template` 한 문장 → **메시지 리스트 형태 `from_messages`**로 변경

```python
from langchain_core.prompts import ChatPromptTemplate, MessagesPlaceholder

prompt = ChatPromptTemplate.from_messages([
    ("system", "다음 컨텍스트를 바탕으로 질문에 답하라.\n\n{context}"),
    MessagesPlaceholder(variable_name="chat_history"),   # 대화 히스토리가 들어갈 자리
    ("human", "{input}"),
])
```
- `{context}`: 리트리버(벡터DB 검색) 결과가 들어가는 자리
- `{input}`: 이번에 사용자가 입력한 질문
- `chat_history`: 이전 대화가 들어가는 자리
- 세 덩어리가 이어진 **하나의 프롬프트**라고 생각하면 된다

### 4-4. history → 랭체인 메시지로 변환
```python
from langchain_core.messages import HumanMessage, AIMessage

def answer(message, history):
    chat_history = []
    for item in history:
        if item["role"] == "user":
            chat_history.append(HumanMessage(content=item["content"]))
        elif item["role"] == "assistant":
            chat_history.append(AIMessage(content=item["content"]))

    response = rag_chain.invoke({
        "input": message,
        "chat_history": chat_history,   # 프롬프트의 variable_name과 반드시 일치
    })
    return response["answer"]
```
- `user` → `HumanMessage`, `assistant` → `AIMessage`로 변환해서 `append`
- `chat_history` 이름이 **프롬프트의 `variable_name`과 달라지면** 값이 안 들어가거나 문제가 생김
- `rag_chain`은 이전에 만든 `create_stuff_documents_chain` + `create_retrieval_chain` (모델 + 프롬프트 + 리트리버)

### 4-5. 실행 흐름 (턴별)
| 턴 | 사용자 입력 | history | 프롬프트에 들어가는 내용 |
|---|---|---|---|
| 1 | 안녕 | 비어 있음 | context + 안녕 |
| 2 | 나는 윤영선이다 | 1턴(2개) | context + 이전 2개 + 이번 입력 |
| 3 | 내가 누구게? | 2턴(4개) | context + 이전 4개 + 이번 입력 → "윤영선" 답변 |

- 답변이 끝나면 Gradio가 이번 턴을 history에 추가한다
- 결과: `"나는 윤영선이다"` 라고 말한 뒤 `"내가 누구게?"` 에 올바르게 답변

### 4-6. 토큰 비용 주의
- 대화가 길어질수록 **매번 전체 history를 같이 전송**하므로 토큰 사용량이 급증하고 느려진다
  - "내가 누구게?" 한마디도 실제로는 앞의 모든 대화가 입력으로 들어감
- 해결: **최근 N개만 사용**
```python
for item in history[-10:]:   # 최근 10개 메시지만 사용
    ...
```
- 말을 짧게 해서 비용을 아끼려 해도, 히스토리가 쌓이면 효과가 작다

### 4-7. 파일 작업
- 이전 파일(`20`번대) 복사 → `21`번(`..._gradio_history.py`)에 붙여 수정
- 실행해서 먼저 **돌아가는지 확인** → 이후 코드 한 줄씩 다시 설명
- 어렵다면 위 함수를 그대로 가져다 써도 된다. 핵심은 `message, history`를 받아 `answer`를 반환하는 함수

## 5. 특별 탭: AI 산업 · 취업 이야기

- **웹/백엔드에서 AI로 넘어온 경우**: 라이브러리가 잘 되어 있어 함수를 갖다 쓰기만 하면 어느 순간 기술적으로 막힌다. 논문과 기본 아키텍처 이해가 필요
- **면접 경향**: 최근까지는 논문·아키텍처를 집요하게 묻는 회사가 많았음. 다만 변화가 매우 빠름 (바이브 코딩 등)
- **데이터 규모 감각**: 은행/주가 같은 데이터는 빅데이터가 아니다. 1년 영업일 약 250일, 종목·변수를 늘려도 **수십만 건 이하**로 작은 편
  - 이런 정형·소규모 데이터는 **트리 부스팅 3대장(XGBoost / LightGBM / CatBoost)**이 LSTM 같은 딥러닝보다 더 잘 맞을 때도 있음
- **준비성**: 갑자기 면접·입사 기회가 오기도 하니 항상 준비해 둘 것

## 6. 미니프로젝트 / 제출 안내

- **PPT**: 표지에 이름 기재 (발표자를 가장 앞에), 양식 자유, **약 3장 이상**
- 포함할 것: **만들고 싶은 것 / 사용한 AI 기술 / 타깃으로 잡은 회사**
- 제출: 메일로 **목요일 오전(12시 전)**까지, **먼저 보낸 순서대로** 컨펌 및 발표
- 리젝되면 수정 후 재제출, 금요일부터 본격 진행
- PPT를 AI로 만들어도 무방. 평가 기준은 **AI 기술력**과 **타깃 회사 적합성**
- 배우지 않은 기술을 써도 되고, 제출할 회사에 부끄럽지 않을 정도면 충분
- 주말~다음 주부터 **LangGraph** 진행 예정
- 팀 논의에서 나온 이야기: 페르소나 정의(연령·인구통계 기반), 상권 데이터 분석 시 "취약 상권"의 **정의부터** 세우고 가설 → 검증하는 흐름

## 7. 오늘의 핵심 요약

1. 트랜스포머 구조를 이해해야 커스터마이징·면접에 대응할 수 있다.
2. 케라스 함수형 API로 **분기(branch) / 병합(concatenate)** 을 자유롭게 구현할 수 있어야 한다.
3. 시계열 예측은 **시간순 split**, 시가는 **y**, 스케일러·가중치 **저장 후 로드**해서 예측한다.
4. 챗봇의 기억 = **history를 `HumanMessage` / `AIMessage`로 바꿔 `MessagesPlaceholder`에 넣는 것**.
5. history가 길어지면 토큰 비용이 늘어나므로 **최근 N개만** 쓴다.
