## 2. 과적합 (Overfitting)

> "모든 점을 정확히 지나가게 모델을 꺾어서 만들면 되지 않나?"
> → **오히려 틀린 모델이 된다.**

- 훈련 데이터에는 완벽히 맞지만, 새로운 값이 들어오면 100% 빗나감
- 어느 정도의 loss를 **인정하는 것**이 제대로 된 모델
- loss가 0이 나오면 잘한 게 아니라 **뭔가 잘못됐다고 의심**해야 함
- 옛날 연구자들도 완전 매치를 시도해봤지만 성능이 더 떨어져서 안 쓰는 것

## 3. 성능을 흔드는 요소들

### random seed
- 초기 가중치가 달라지면 성능이 크게 달라짐
- 하이퍼파라미터 튜닝 없이 시드만 계속 바꿔서 상을 탄 사례도 있음
- 관행적으로 `random_state=42`를 많이 씀

### 노드 수 / 레이어 깊이
- 정답 없음, 직접 튜닝해야 함
- 입력 노드 = 컬럼 수, 최종 출력 노드 = 맞추려는 값의 개수 (회귀 예측이면 1개)

### batch_size
- **작으면** 성능은 좋아지지만 속도는 느려짐
- 데이터 20,000개에 `batch_size=1`이면 1 epoch에 20,000번 갱신
- epoch 출력의 `2/2`, `645/645` 같은 숫자는 **전체 데이터 ÷ 배치 크기**의 결과

## 5. 4단계 작업 흐름

> 데이터 내용을 전혀 몰라도 **shape만 알면** 모델링부터 결과까지 뽑을 수 있다.

| 단계 | 내용 |
|---|---|
| **#1 데이터** | `train_test_split`으로 훈련/테스트 분리 |
| **#2 모델** | `input_dim` = 컬럼 수 (캘리포니아는 8), 출력 노드 = 1개 |
| **#3 컴파일·훈련** | `loss='mse'`, `optimizer='adam'`, `epochs`, `batch_size` |
| **#4 평가·예측** | `model.evaluate(x_test, y_test)`, `model.predict` |

```python
# #1 데이터
x_train, x_test, y_train, y_test = train_test_split(x, y, random_state=42)

# #2 모델
model = Sequential()
model.add(Dense(16, input_dim=8))
model.add(Dense(16))
model.add(Dense(1))

# #3 컴파일 · 훈련
model.compile(loss='mse', optimizer='adam')
model.fit(x_train, y_train, epochs=100, batch_size=32)

# #4 평가 · 예측
loss = model.evaluate(x_test, y_test)
print(loss)
```

## 6. MSE — 핵심

$$
\text{MSE} = \frac{1}{n}\sum(y - \hat{y})^2
$$

**말로 풀면:** 원값에서 예측값을 뺀 뒤 → 제곱하고 → 전부 더해서 → 개수로 나눈다 (N빵)

### 제곱하는 이유
음수 때문. 오차가 `+1.5`와 `-1.5`면 그냥 더할 경우 **0**이 되어 "완벽한 모델"로 보이는 착시가 생긴다.

### 계산 예시 (w=0, b=1일 때)

| y (원값) | ŷ (예측값) | y − ŷ | 제곱 |
|---|---|---|---|
| 1 | 1 | 0 | 0 |
| 2 | 1 | 1 | 1 |
| 3 | 1 | 2 | 4 |

합 = 5 → 개수 3으로 나누면 **loss ≈ 1.667**
→ 이게 1 epoch째에 화면에 찍히는 값

### 결론
- loss는 **절대 음수가 나올 수 없다**
- 절대적 기준이 아니라 **상대평가 지표**

## 7. 순전파 → loss → 역전파 사이클

1. **순전파**: `ŷ = wx + b` 로 예측값 계산
2. **loss 계산**: MSE로 원값과 예측값 비교
3. **역전파**: 가중치 갱신

$$
w := w - \text{lr} \times \frac{\partial L}{\partial w}
$$

체인룰로 풀면 $L = \frac{1}{n}\sum(y-(wx+b))^2$ 를 미분해
$2(y-(wx+b)) \times (-x)$ 형태가 나온다.

4. 갱신된 w로 다시 순전파 → **epoch 수만큼 반복**

이 반복이 곧 딥러닝 학습이다.

> 역전파 손계산은 4개월 차쯤 제대로 다룰 예정. 지금은 "이런 흐름이다" 정도만 이해하면 됨.
> 실무 개발자 중에도 역전파를 직접 계산 못 하는 사람이 대부분.

### 추론(inference)
- 순전파만 하고 **가중치 갱신이 없음**
- NPU가 순전파만 지원하는 이유 — 최적의 가중치를 받아서 결과만 빠르게 뽑는 용도

---

## 8. fit / evaluate / predict 차이

| 메서드 | 입력 | 동작 |
|---|---|---|
| **fit** | `x_train, y_train` | epoch마다 loss 계산 → 가중치 갱신 반복 |
| **evaluate** | `x_test, y_test` | 훈련이 끝난 **최종 가중치 하나**로 ŷ를 만들어 y_test와 비교. **딱 한 번**만 수행 |
| **predict** | `x` | 최종 가중치로 새 입력의 예측값 출력 |

### evaluate와 batch_size
- `evaluate`에도 `batch_size` 기본값 **32**가 적용됨
- 다만 역전파(가중치 갱신)가 없으므로 **결과에는 영향 없음**
- 배치 크기만큼 끊어서 계산할 뿐이라 큰 의미는 없음
