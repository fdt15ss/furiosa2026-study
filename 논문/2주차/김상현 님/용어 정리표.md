# 용어 정리표

발표 슬라이드에 나오는 용어를 등장 순서대로 정리했습니다. 마지막 열은 처음 나오는 슬라이드 번호입니다.

## 1. 배경·구조

| 용어 | 쉬운 설명 | 슬라이드 |
| --- | --- | --- |
| seq2seq | 문장을 읽는 인코더와 문장을 만드는 디코더를 이어 붙인 번역 구조 | 3 |
| 인코더 / 디코더 | 입력을 이해해 표현으로 바꾸는 쪽 / 그 표현으로 출력을 만드는 쪽 | 3, 5 |
| RNN | 단어를 앞에서부터 하나씩 순서대로 처리하는 신경망. 앞 단계가 끝나야 다음 단계를 할 수 있어 병렬화가 안 됨 | 3 |
| CNN | 좁은 창을 밀며 주변을 보는 신경망. 병렬화는 되지만 먼 위치를 잇는 데 층이 많이 필요 | 3 |
| 고정 길이 벡터 (c) | 문장 전체를 담아 디코더에 넘기는 정해진 크기의 벡터. 긴 문장에서 정보가 샘 | 3 |
| 임베딩 | 단어나 번호를 숫자 벡터로 바꾼 것 | 5 |
| d\_model | 모델 전체에서 쓰는 표현의 크기. 논문 512, 로또 코드 128 | 5 |
| 층 (N) | 같은 블록을 몇 번 쌓았는지. 논문 6, 로또 코드 6 (Optuna가 2\~4로 바꿀 수 있음) | 5 |

## 2. 어텐션

| 용어 | 쉬운 설명 | 슬라이드 |
| --- | --- | --- |
| 어텐션 | 입력의 여러 부분 중 지금 필요한 곳에 가중치를 더 줘서 값을 섞는 연산 | 4 |
| Q, K, V (쿼리, 키, 값) | Q는 찾는 질문, K는 각 항목의 이름표, V는 실제 내용. Q와 K가 얼마나 비슷한지로 V를 섞는 비율을 정함 | 4 |
| 점수 함수 | Q와 K의 유사도를 숫자로 만드는 방법. 트랜스포머는 내적을 사용 | 4 |
| 내적 | 두 벡터의 같은 자리끼리 곱해서 더한 값. 클수록 비슷함 | 4 |
| softmax | 여러 점수를 합이 1인 비율(가중치)로 바꾸는 함수 | 6 |
| d\_k | 한 헤드에서 Q, K 벡터의 크기. 로또 코드는 128÷8=16 | 6 |
| 스케일링 (√d\_k로 나눔) | d\_k가 크면 내적이 너무 커져 softmax가 한쪽으로 쏠리므로, 크기에 맞춰 나눠 줌 | 6 |
| 멀티헤드 어텐션 | 어텐션을 서로 다른 가중치로 여러 개 나란히 하고 결과를 합침. 헤드마다 다른 관계를 봄 | 7 |
| 헤드 (h) | 나란히 도는 어텐션 하나. 로또 코드는 8개 | 7 |
| 셀프 어텐션 | Q, K, V가 모두 같은 문장에서 나오는 어텐션. 문장 안 단어끼리 서로 참조 | 8 |
| 마스크드 셀프 어텐션 | 디코더에서 아직 안 만든 미래 위치를 가리고 하는 셀프 어텐션 | 8 |
| 인코더-디코더 어텐션 | Q는 디코더, K와 V는 인코더에서 가져오는 어텐션 | 8 |
| 마스크 | 참조하면 안 되는 위치의 점수를 −∞로 만들어 가중치를 0으로 만드는 장치 | 8 |
| 양방향 | 마스크가 없어 앞뒤 모든 위치를 볼 수 있는 상태. 로또 코드가 해당 | 14 |

## 3. 받쳐 주는 부품

| 용어 | 쉬운 설명 | 슬라이드 |
| --- | --- | --- |
| FFN (피드포워드) | 위치마다 따로 적용하는 2층 신경망. 어텐션이 섞은 결과를 비선형으로 변환 | 9 |
| d\_ff | FFN 중간 층의 크기. 논문 2048, 로또 코드 256 | 9 |
| 비선형 / 활성화 함수 | 직선으로 표현 못 하는 관계를 배우게 하는 장치. 논문은 ReLU, 로또 코드는 GELU | 9 |
| 잔차 연결 | 층의 입력을 출력에 그대로 더해 주는 지름길. 깊게 쌓아도 학습이 안정적 | 9 |
| LayerNorm (층 정규화) | 한 토큰의 값들을 평균 0, 분산 1 근처로 맞춰 학습을 안정시킴 | 9 |
| Post-LN / Pre-LN | 정규화를 더한 뒤에 두면 Post-LN(논문), 서브층 앞에 두면 Pre-LN(로또 코드, norm\_first=True) | 9, 14 |
| 위치 인코딩 | 어텐션에는 순서 정보가 없어서 위치마다 고유한 벡터를 더해 줌 | 10 |
| 사인파 / 학습형 위치 | 논문은 사인·코사인 공식, 로또 코드는 학습으로 얻는 위치 벡터 | 10, 13 |
| 임베딩 가중치 공유 | 입력·출력 임베딩과 softmax 직전 선형층이 같은 가중치 행렬을 씀 | 9 |

## 4. 논문 결과

| 용어 | 쉬운 설명 | 슬라이드 |
| --- | --- | --- |
| 복잡도 O( ) | 입력이 커질 때 계산량이 어떻게 늘어나는지의 대략적 표기 | 11 |
| 순차 연산 | 앞 단계가 끝나야 할 수 있는 단계의 수. 적을수록 병렬화에 유리 | 11 |
| 최대 경로 길이 | 멀리 떨어진 두 위치가 정보를 주고받는 데 거치는 단계 수 | 11 |
| n, d | n은 시퀀스 길이, d는 표현 차원. n이 d보다 작으면 어텐션이 빠름 | 11 |
| BLEU | 번역 품질 점수. 기계 번역과 사람 번역이 얼마나 겹치는지. 높을수록 좋음 | 11 |

## 5. 로또 실험 코드

| 용어 | 쉬운 설명 | 슬라이드 |
| --- | --- | --- |
| 멀티핫 벡터 | 여러 칸이 동시에 1인 벡터. 한 회차의 당첨 번호 6개를 45칸 중 6칸 1로 표시 | 12 |
| 인코더 전용 모델 | 디코더 없이 인코더만 쓰는 구조. 이 노트북의 모델 | 12 |
| nn.TransformerEncoderLayer / Encoder | PyTorch가 제공하는 내장 모듈. 어텐션과 FFN이 내부에 구현돼 있어 노트북에는 수식이 안 보임 | 13 |
| Lookback (L) | 예측에 쓰는 과거 회차 수. 계산 예시는 50 | 15 |
| 배치 | 한 번에 같이 계산하는 샘플 묶음. 예시는 32 | 15 |
| 텐서 | 다차원 숫자 배열. \[32, 50, 128\]은 배치×회차×특징 | 15 |
| 곱셈 수 | 연산량을 가늠하는 지표로 센 곱셈 횟수 (실측이 아닌 계산값) | 17 |
| 파라미터 | 학습으로 정해지는 가중치와 편향의 개수. 이 모델은 약 818,605개 | 19 |
| 시그모이드 | 값을 0\~1 확률로 바꾸는 함수. 번호마다 독립으로 적용 | 13 |
| BCE (이진 교차 엔트로피) | 맞음/틀림 두 가지 중 하나를 맞히는 문제의 손실. 번호 45개를 각각 이진분류로 취급 | 18 |
| 기준선 | 아무것도 학습 안 하고 번호당 6/45 확률만 내놓았을 때의 손실 0.3927. 이보다 나아야 의미 있음 | 18 |
| 과적합 | 학습 데이터를 외워서 새 데이터에서는 성능이 안 나오는 상태 | 20 |
| Optuna | 하이퍼파라미터 조합을 자동으로 탐색하는 도구. 층 수 등을 덮어쓸 수 있음 | 20 |
| AdamW | 가중치를 갱신하는 최적화 방법 (한 줄만 언급) | 12 |
| 기대 적중 0.8개 | 6개를 무작위로 골라도 평균 6×6/45 = 0.8개가 맞음 | 20 |

# 추가 용어: PPT에 없지만 알아야 할 개념

발표 질의응답에서 나올 수 있는 개념을 세 묶음으로 더했습니다. 슬라이드에 없는 내용이라 슬라이드 번호 대신 "왜 중요한가"를 적었습니다.

## 6. 어텐션 관련 빠진 개념

| 용어 | 쉬운 설명 | 왜 중요한가 |
| --- | --- | --- |
| 토큰 | 모델이 처리하는 입력의 최소 단위. 글자, 단어 조각, 또는 로또의 한 회차 | 어텐션이 "토큰끼리" 섞는 연산이라 모든 설명의 기본 단위 |
| 어텐션 가중치 (어텐션 맵) | softmax 결과인 토큰 간 비율 표. 행이 하나의 쿼리, 열이 키 | 모델이 어디를 봤는지 시각화하는 근거. 단, 그 자체가 설명은 아님 |
| 컨텍스트 벡터 | 가중치로 V를 섞어 얻은 결과 벡터 | seq2seq의 c 하나와 달리 토큰마다 새로 만들어진다는 점이 핵심 차이 |
| 정렬 (alignment) | 번역에서 출력 단어가 입력의 어느 단어에 대응하는지 | 초기 어텐션이 해결하려던 문제. 어텐션 가중치가 정렬처럼 보이는 이유 |
| 크로스 어텐션 | Q는 한쪽, K와 V는 다른 쪽에서 가져오는 어텐션 | 슬라이드의 인코더-디코더 어텐션의 일반 이름 |
| 인과적 마스크 (causal mask) | 자기 이후 위치를 못 보게 하는 삼각형 모양 마스크 | 디코더가 정답을 미리 보지 못하게 하는 장치. GPT류의 기본 |
| 패딩 마스크 | 길이를 맞추려고 채운 빈 토큰을 무시하게 하는 마스크 | 배치 학습에서 실제로 늘 쓰이는 마스크. 로또는 길이가 고정이라 불필요 |
| 소프트 / 하드 어텐션 | 소프트는 전체에 비율을 주는 방식(미분 가능), 하드는 하나를 골라 쓰는 방식 | 트랜스포머는 소프트라서 역전파로 바로 학습 가능 |
| 로짓 (logit) | softmax나 sigmoid를 거치기 전의 원점수 | 코드의 BCEWithLogitsLoss, next\_logits의 의미 |

## 7. 구조·학습·추론 관련 빠진 개념

| 용어 | 쉬운 설명 | 왜 중요한가 |
| --- | --- | --- |
| 토크나이저 / 어휘 | 문장을 토큰으로 쪼개는 규칙과 토큰 목록. 논문은 서브워드(BPE, word-piece) 사용 | 임베딩 행렬 크기와 번역 성능에 직접 영향. 로또는 번호 45개가 곧 어휘 |
| 자기회귀 (autoregressive) | 이미 만든 출력을 다음 입력으로 써서 한 토큰씩 생성 | 디코더가 마스크가 필요한 이유. 학습은 병렬, 추론은 순차 |
| 교사 강제 (teacher forcing) | 학습할 때 모델 출력 대신 정답을 다음 입력으로 넣는 방식 | 마스크드 셀프 어텐션 덕에 학습은 한 번에 병렬로 가능 |
| 빔 서치 | 추론 때 후보 문장을 여러 개 유지하며 가장 좋은 것을 찾는 방법. 논문은 빔 4 | 논문의 BLEU 수치가 나온 추론 설정 |
| 레이블 스무딩 | 정답에 확률 1 대신 0.9쯤을 주고 나머지에 나눠 주는 기법. 논문은 0.1 | 확신 과잉을 줄여 BLEU를 올림. 손실 값은 오히려 나빠 보임 |
| 학습률 워밍업 | 학습 초기에 학습률을 서서히 올렸다가 줄이는 스케줄. 논문은 4,000 스텝 | 트랜스포머가 처음 학습에서 불안정해지는 것을 막는 핵심 요령 |
| 드롭아웃 | 학습 중 일부 값을 무작위로 꺼서 과적합을 줄이는 기법. 논문 0.1 | 로또 코드 DROPOUT=0.10과 같은 개념 |
| 역전파 / 기울기 소실 | 손실을 거꾸로 전달해 가중치를 고치는 과정 / 깊은 층에서 그 신호가 0에 가까워지는 문제 | 잔차 연결과 LayerNorm이 필요한 이유 |
| 학습률, 에폭 | 한 번에 고치는 크기 / 데이터를 몇 바퀴 돌았는지 | 로또 노트북 Optuna 탐색 대상 (LR, 150 에폭) |
| 하이퍼파라미터 | 학습으로 정해지지 않고 사람이 정하는 값 (층 수, 헤드 수, d\_ff 등) | 파라미터와 구분해서 말해야 함 |
| 체크포인트 | 학습 도중 저장한 모델 가중치 | 논문은 마지막 체크포인트 여러 개를 평균해 성능을 올림 |

## 8. 트랜스포머 이후의 발전 (질의응답용)

| 용어 | 쉬운 설명 | 왜 중요한가 |
| --- | --- | --- |
| 인코더 전용 / 디코더 전용 | 인코더만 쓰면 BERT류(이해에 강함), 디코더만 쓰면 GPT류(생성에 강함) | 로또 모델이 인코더 전용이라는 위치를 설명할 때 필요 |
| 사전학습 / 파인튜닝 | 대규모 데이터로 먼저 학습한 뒤 특정 작업에 맞게 추가 학습 | 트랜스포머가 번역을 넘어 범용 모델의 뼈대가 된 방식 |
| 스케일링 법칙 | 모델·데이터·계산을 키울수록 성능이 규칙적으로 좋아진다는 관찰 | 로또 모델(약 82만 파라미터, 샘플 수십 개)이 왜 너무 작은 실험인지 설명 |
| 컨텍스트 윈도우 | 모델이 한 번에 볼 수 있는 최대 토큰 수 | 어텐션이 n의 제곱이라 길어질수록 비용이 크게 늘는 한계 |
| 효율적 어텐션 (희소·선형 등) | 모든 쌍을 보지 않고 일부만 보거나 계산을 줄이는 변형 | 논문 Table 1의 "제한된 셀프 어텐션"의 후속 연구 |
| FlashAttention | 어텐션 결과는 같은데 메모리 접근을 줄여 더 빠르게 계산하는 구현 | 수학이 아니라 구현이 성능을 좌우한다는 사례 |
| KV 캐시 | 생성 중 이미 계산한 K와 V를 저장해 두고 재사용 | 추론 속도와 메모리의 핵심 |
| MQA / GQA | 여러 헤드가 K와 V를 공유해 KV 캐시를 줄이는 방식 | 멀티헤드의 비용을 줄이는 실전 변형 |
