[2 / 18] 한 장으로 보기: 세 겹 구조
제목: 세 논문은 서로를 감싸는 세 겹이다
세 논문을 하나의 그림으로 보면 서로를 감싸는 구조입니다. 가장 안쪽의 CoT는 한 번의 생각입니다. ReAct는 그 생각을 Thought로 쓰고, 행동과 관찰을 번갈아 하며 한 번의 시도를 진행합니다. Reflexion은 시도가 끝나면 평가자가 성공과 실패를 판정하고, 실패하면 원인을 반성문으로 써서 다음 시도에 넘깁니다. 바깥 겹일수록 더 긴 시간 범위의 피드백을 다룹니다. 단, 진화 계보는 아닙니다. 세 논문은 2022년에서 2023년 사이에 거의 함께 나왔고, Reflexion의 코딩 실험처럼 안쪽 층이 ReAct가 아닌 경우도 있습니다.

[3 / 18] 1. Chain-of-Thought (CoT)
제목: CoT: 답 앞에 풀이를 쓰게 한다
CoT의 구조는 한 줄짜리 사슬입니다. 프롬프트에 풀이가 담긴 예시 8개와 질문을 넣으면, 모델이 그 형식을 따라 Thought 1, Thought 2처럼 중간 단계를 차례로 쓰고, 마지막에 답을 냅니다. 각 단계는 앞 단계의 결과를 문장에서 이어받습니다. 표준 프롬프팅은 이 사슬 없이 질문에서 곧바로 답을 냅니다. 뒤에 나올 ReAct와 Reflexion은 이 사슬에 고리를 더합니다. ReAct는 외부 관찰이 다음 생각으로 돌아오는 고리, Reflexion은 실패한 시도가 다음 시도로 돌아오는 고리입니다. 핵심 발견은 세 가지입니다. 첫째, 약 1000억 파라미터 이상에서만 효과가 나는 창발적 능력입니다. 둘째, 어려운 문제일수록 이득이 큽니다. GSM8K에서 PaLM 540B는 예시 8개만으로 최고 성능을 냈습니다. 셋째, ablation에서 수식만 쓰거나, 같은 길이의 점만 출력하거나, 답을 먼저 쓰게 하면 효과가 없었습니다. 계산량이 아니라 자연어 중간 단계가 답 앞에 있다는 점이 중요합니다.

[4 / 18] 2. ReAct: 생각과 행동
제목: ReAct: 생각과 행동을 번갈아 한다
ReAct는 CoT의 생각에 행동을 더합니다. 형식적으로는 에이전트의 행동 공간에 언어 공간을 추가한 것이고, 생각은 환경을 바꾸지 않고 맥락만 갱신합니다. 루프는 Thought, Action, 외부 환경, Observation 순서로 돌고, 정보가 충분하면 finish 행동으로 답을 냅니다. 행동은 Wikipedia의 search, lookup, finish 세 가지뿐입니다. 오른쪽은 HotpotQA 오류 분석입니다. CoT 실패의 56%가 환각인데 ReAct는 0%입니다. 대신 ReAct는 같은 행동을 반복하는 루프 같은 추론 오류와 검색 실패가 늘었습니다. 저자들은 이를 사실성과 유연성의 트레이드오프라고 부르고, 그래서 ReAct와 CoT-SC를 결합하는 방식을 제안합니다. 의사결정 과제에서는 ALFWorld 71%로 행동만 하는 Act의 45%를 크게 앞섰습니다.

[5 / 18] 3. Reflexion: 언어적 반성
제목: Reflexion: 실패를 글로 반성하고 다시 시도한다
Reflexion은 시도와 시도 사이에서 배웁니다. Actor가 ReAct나 CoT로 시도하면 Evaluator가 성공과 실패를 판정합니다. 실패하면 자기 성찰 모델이 무엇이 왜 틀렸는지를 글로 쓰고, 이를 장기 메모리에 쌓아 다음 시도의 프롬프트에 넣습니다. 가중치는 전혀 바뀌지 않습니다. 결과로 HumanEval pass@1 91%로 당시 GPT-4의 80%를 넘었고, ALFWorld에서는 134개 중 130개를 완료했습니다. 오른쪽 ablation이 중요합니다. 단위 테스트 없이 반성만 하면 오히려 0.52로 떨어지고, 테스트만 있고 반성이 없으면 기준선과 같습니다. 둘이 함께 있어야 0.68로 오릅니다. 그리고 MBPP Python에서는 스스로 만든 테스트가 틀린 코드를 통과시키는 거짓 양성이 16%나 되어 GPT-4보다 낮았습니다. 평가 신호의 품질이 Reflexion의 상한이라는 뜻입니다.

[6 / 18] 같은 질문, 세 가지 방식 비교
제목: “John Lanchester와 Alan Dean Foster의 공통 직업은?”
세 방법을 같은 질문 하나로 비교해 보겠습니다. 두 작가의 공통 직업을 묻는 HotpotQA 질문입니다. CoT는 두 사람의 직업을 내부 지식으로 떠올린 뒤 한 번에 답하는데, 공통이 아닌 시나리오 작가까지 답에 넣어 틀립니다. 이 흐름은 Reflexion 논문 부록 D.2의 첫 번째 시도 그대로입니다. 가운데 ReAct 열은 논문에 실린 예시가 아니라 설명을 위해 구성한 흐름입니다. 두 사람을 각각 검색하고, 관찰한 결과끼리 비교해 답합니다. 오른쪽 Reflexion은 부록 D.2의 두 번째 시도까지입니다. 첫 시도가 오답 판정을 받자, 두 사람의 직업이 같다고 잘못 가정했다는 반성문을 쓰고, 다음 시도에서 소설가라는 정답을 냅니다. 같은 모델이라도 외부 근거를 가져오느냐, 실패를 다음 시도로 넘기느냐에 따라 결과가 달라진다는 점을 보여 줍니다.

[7 / 18] 세 방법 비교 매트릭스
제목: 한 겹씩 더할 때마다 약점의 종류가 바뀐다
세 방법을 같은 기준으로 놓으면, 한 겹을 더할 때마다 약점의 종류가 바뀝니다. CoT는 단순하고 싸지만 내부 지식만 써서 환각으로 실패합니다. ReAct는 외부 도구로 환각을 없애지만, 형식 제약 때문에 같은 행동을 반복하는 루프나 검색 실패로 틀립니다. 실제로 HotpotQA에서는 CoT가 29.4로 ReAct 27.4보다 약간 높았습니다. Reflexion은 여러 시도에 걸쳐 개선하지만, 평가 신호가 약하면 틀린 교훈을 쌓습니다. 그래서 어느 한쪽이 우월하다기보다 결합이 가장 좋습니다. ReAct 논문에서도 ReAct가 막히면 CoT-SC로 넘어가는 방식이 HotpotQA 최고 점수를 냈습니다.

[11 / 18] 4. 8B 재현 실험 설계
제목: 논문 설정 그대로, 모델만 8B로 바꿨다
여기부터는 직접 재현한 실험입니다. 원칙은 하나였습니다. 논문과 공식 코드의 프롬프트, 예시, 루프, 평가 방식을 그대로 쓰고, 모델만 바꿨습니다. CoT는 논문 Table 20의 수학 예시 8개, ReAct는 공식 저장소의 지시문과 예시 6개, 세 가지 행동, 최대 7스텝, Reflexion은 공식 저장소의 성찰 프롬프트와 정확 일치 평가자, 최근 반성 3개를 썼습니다. 바꾼 것은 두 가지입니다. 모델은 PaLM-540B나 GPT 대신 로컬에서 돌리는 Llama 3.1 8B이고, Wikipedia는 웹 페이지를 긁는 대신 API로 접속하되 돌려주는 내용의 규칙은 논문 코드와 같게 했습니다. 그리고 통신 실패나 형식 오류 같은 실행 오류는 막아서 기록했지만, 모델이 틀린 답을 내는 것은 고치지 않았습니다. 틀린 답에 맞춰 보정 장치를 붙이면 그 결과가 논문 방법의 효과인지 보정의 효과인지 구분할 수 없기 때문입니다. 규모는 작습니다. 수학 8문제, HotpotQA 5문제입니다.

첫 번째 결과는 CoT입니다. 같은 예시 8개를 쓰되 Standard는 예시에 답만 있고, CoT는 풀이까지 있습니다. 8B 모델에서 Standard는 8문제 중 2문제, CoT는 6문제를 맞혔습니다. 논문의 PaLM 540B도 GSM8K에서 17.9에서 56.9로 크게 올랐으니 방향은 같습니다. 다만 논문은 약 1000억 파라미터 이하에서는 효과가 없다고 보고했는데, 여기서는 8B에서도 효과가 났습니다. 두 가지를 감안해야 합니다. 첫째, 8문제는 너무 적어서 우연일 수 있습니다. 둘째, 이것은 제 해석인데, 2022년의 작은 모델과 달리 요즘 모델은 학습 단계에서 풀이 데이터를 많이 봤을 가능성이 큽니다. 그래서 창발 크기 자체가 내려왔다고 단정할 수는 없습니다. CoT가 틀린 두 문제는 집을 고쳐 판 수익 계산과 다운로드 재시작 문제였는데, 둘 다 계산 실수가 아니라 문제의 뜻을 잘못 읽은 경우였습니다.

[14 / 18] 사례 1: 거짓 양성과 근거 비교
제목: CoT의 정답 3개는 모두 틀린 사실 위에 서 있었다
CoT가 맞힌 세 문제를 풀이까지 열어 보면 셋 다 사실 오류가 있습니다. Chanoff 문제에서는 협업한 제독을 Bobby Ray Inman이라고 지어냈는데 실제 협업자는 William Crowe입니다. 그래도 대통령 이름은 맞았습니다. James Worthy는 2월 30일생이라는, 존재하지 않는 날짜를 썼습니다. 6파운더 문제는 어뢰를 막으려 도입됐다고 했지만 위키 원문은 어뢰정 같은 작고 빠른 배를 막으려 했다고 씁니다. 정확 일치 채점은 답만 보기 때문에 셋 다 정답으로 셉니다. ReAct 논문은 이것을 거짓 양성이라고 부르고, 성공 사례 중 CoT 14퍼센트, ReAct 6퍼센트로 보고했습니다. 오른쪽은 같은 Chanoff 질문의 ReAct 궤적입니다. 검색 결과에서 Crowe를 찾고, Crowe 문서에서 Clinton 정부의 대사였다는 문장을 읽고 답합니다. 정답률은 같아도, 근거를 확인할 수 있다는 점이 ReAct의 실제 가치입니다.

[15 / 18] 사례 2: ReAct 실패 유형 분석
제목: 근거를 보고도 같은 행동을 반복하고, 맞는 답을 다르게 적었다
ReAct가 틀린 방식은 두 가지였고, 둘 다 논문의 오류 분석에 있는 유형입니다. 왼쪽은 반복 루프입니다. 첫 검색에서 Irene Jacob 문서에 이미 Beyond the Clouds와 U.S. Marshals가 연도와 함께 나왔습니다. 질문의 Stuart Bird는 철자가 틀린 이름이고 실제 감독은 Stuart Baird입니다. 모델은 이 연결을 못 하고 없는 이름을 계속 검색하고, 같은 lookup을 반복하다 7스텝을 다 썼습니다. 논문에서도 ReAct 실패의 47퍼센트가 이런 반복을 포함한 추론 오류였습니다. 오른쪽은 표기 불일치입니다. 공동 제작자 세 명을 모두 적어서 사실로는 맞지만, 정답 표기가 한 명이라 정확 일치에서 오답이 됩니다. 논문에서도 ReAct 실패의 29퍼센트가 이 유형이었습니다. 표의 세 번째 실패는 Wikipedia 통신이 한 번 실패한 뒤 같은 lookup을 반복한 경우여서 따로 표시했습니다.
