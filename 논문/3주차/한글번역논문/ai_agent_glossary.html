AI AGENT 핵심 용어집

단순한 챗봇을 넘어 스스로 생각하고(CoT), 도구를 쓰며(ReAct), 실수로부터 배우는(Reflexion) 자율 에이전트(Autonomous Agent)의 핵심 이론과 기술 용어를 알기 쉽게 해설합니다.

🔍
🤖 1. 에이전트 기본 개념 (Foundations)
AI 에이전트 AI Agent
기초 개념
💡 비유로 이해하기
단순한 LLM(챗봇)이 "말만 유창하게 하는 자문위원"이라면, AI 에이전트는 "스스로 계획을 세우고, 인터넷을 검색하고, 엑셀을 켜서 작업을 끝마치는 행동력 있는 비서"입니다.
대규모 언어 모델(LLM)을 두뇌로 삼아, 사용자의 목표(Goal)를 달성하기 위해 인식(Perception) → 추론(Reasoning) → 행동(Action) → 관찰(Observation)의 피드백 루프를 자율적으로 반복 수행하는 지능형 시스템입니다.
창발적 능력 Emergent Ability
모델 특성
💡 비유로 이해하기
물이 99℃까지는 액체 상태이다가 100℃가 되는 순간 갑자기 수증기로 비등하듯, 모델이 일정 크기(보통 1,000억 파라미터 이상)를 넘어서는 순간 이전에는 전혀 못 하던 고난도 추론 능력이 갑자기 생겨나는 현상입니다.
소형 모델에서는 아무리 유도해도 나타나지 않던 성능 향상이, 모델 파라미터가 임계점(Scale threshold)을 넘어서면서 비선형적으로 폭발하는 현상입니다. CoT 논문(Wei et al.)에서 100B 이상의 PaLM 모델에서 CoT 효과가 창발함을 확인했습니다.
관련 논문: CoT 논문 섹션 3.2
인컨텍스트 학습 In-Context Learning (ICL)
프롬프팅
💡 비유로 이해하기
직원에게 장기 교육 훈련(파인튜닝)을 시키지 않고, "이런 식으로 일하면 돼"라며 책상 위에 샘플 보고서 3장을 얹어주는 것(프롬프트 예시)과 같습니다.
신경망의 가중치(Weights)를 역전파(Backpropagation)로 업데이트하지 않고, 프롬프트 입력창(Context window) 안에 몇 가지 예시(Exemplars)를 제공함으로써 모델이 즉석에서 패턴을 파악하여 작업을 수행하도록 유도하는 학습 방식입니다.
🧠 2. 추론 및 프롬프팅 기법 (Reasoning & Prompting)
생각의 사슬 Chain-of-Thought (CoT)
추론 혁신
💡 비유로 이해하기
수학 문제를 풀 때 주관식 답만 곧바로 찍지 않고, 연습장에 1단계, 2단계, 3단계 풀이 과정을 차근차근 적어가며 최종 답을 구하는 것과 같습니다.
복잡한 문제를 하위 문제들로 분해하여 최종 결론에 이르기까지 일련의 중간 자연어 추론 단계를 명시적으로 생성하는 프롬프팅 기법입니다. 다음 토큰을 생성할 때 이전의 추론 단계들이 인과적 어텐션(Causal attention) 맥락으로 작용하여 계산 정확도를 획기적으로 높입니다.
관련 논문: CoT 논문 전문
추론 트레이스 Reasoning Traces (사고 자취)
내부 추론
💡 비유로 이해하기
탐정이 사건을 해결하며 다이어리에 남긴 생각의 흐름과 추리 노트입니다.
ReAct에서 에이전트가 외부 행동(Action)을 취하기 전후에 생성하는 언어적 추론 텍스트(Thought)의 전체 흐름입니다. 행동의 목적을 정의하고 관찰된 외부 사실을 해석하는 인지적 다리 역할을 합니다.
관련 논문: ReAct 논문 섹션 2
제로샷 생각의 사슬 Zero-shot CoT ("Let's think step by step")
프롬프트 기법
💡 비유로 이해하기
당황한 상대방에게 "자, 침착하고 한 단계씩 천천히 생각해 보자"라고 한마디 건네는 마법의 주문입니다.
퓨샷 예시를 하나도 주지 않고도, 질문 뒤에 "Let's think step by step"이라는 한 문장만 덧붙이면 모델이 자발적으로 중간 사고 과정을 출력하도록 만드는 기법입니다 (Kojima et al., 2022).
자기 일관성 Self-Consistency (CoT-SC)
앙상블/검증
💡 비유로 이해하기
한 사람의 의견만 듣지 않고 여러 전문가에게 독립적으로 문제를 풀게 한 뒤 가장 많이 나온 답(다수결 투표)을 최종 정답으로 선택하는 방법입니다.
동일한 프롬프트에 대해 Temperature를 높여 여러 추론 경로를 샘플링한 후, 가장 빈도가 높은 결론(Majority vote)을 최종 답안으로 선택하는 디코딩 전략입니다. ReAct 논문에서 ReAct와 상호보완 앙상블로 최고 성능을 달성했습니다.
관련 논문: ReAct 논문 섹션 3.3
스크래치패드 Scratchpad
연산 버퍼
💡 비유로 이해하기
복잡한 암산을 할 때 옆에 두고 마구 끄적이는 낙서장/연습장입니다.
언어 모델이 최종 결과를 내기 전에 중간 연산 상태(예: 긴 알고리즘 실행 추적, 코드 변수 상태 등)를 텍스트 버퍼 형태로 출력할 수 있도록 허용하는 기법으로, CoT의 전신이 된 메커니즘입니다 (Nye et al., 2021).
🦾 3. 행동 및 도구 상호작용 (Action, Tool & Grounding)
리액트 ReAct (Reasoning + Acting)
에이전트 패러다임
💡 비유로 이해하기
생각만 하고 행동하지 않는 학자(CoT)와 생각 없이 버튼만 마구잡이로 누르는 기계(Act-only)를 합쳐, "생각하고 → 행동하고 → 관찰하고 → 다시 생각하는 똑똑한 실행가"를 만든 것입니다.
언어 모델이 Thought(추론 계획)과 Action(도구 실행)을 번갈아 생성하고, 환경으로부터 Observation(결과 관찰)을 입력받아 다음 결정을 내리는 상호작용적 에이전트 프레임워크입니다.
관련 논문: ReAct 논문 전문
인터리브드 / 교차 생성 Interleaved Generation
실행 구조
💡 비유로 이해하기
샌드위치처럼 빵(생각) - 햄(행동) - 치즈(관찰) - 빵(생각)... 순서로 다른 층들을 차곡차곡 교차해서 쌓아 올리는 방식입니다.
생각(Thought)과 행동(Action)을 한 번에 몰아서 출력하는 것이 아니라, `Thought 1 → Action 1 → Observation 1 → Thought 2 → Action 2...`와 같이 교차적으로 생성하고 실행하는 순차 구조입니다.
관련 논문: ReAct 논문 공식화
상태 추적 State Tracking
진행 관리
💡 비유로 이해하기
체스 게임에서 "현재 말들이 판 위에 어떻게 놓여있고, 내가 몇 번째 수까지 두었는가"를 머릿속에 정확히 업데이트하고 있는 것입니다.
다단계 작업을 수행하는 동안 이전 행동들이 환경에 어떤 변화를 가져왔는지, 남은 하위 목표가 무엇인지 에이전트의 컨텍스트 안에서 지속적으로 갱신하고 추적하는 기능입니다. ReAct는 Thought를 통해 이를 달성합니다.
에이전트 궤적 Trajectory (τ)
실행 기록
💡 비유로 이해하기
비행기의 블랙박스 기록이나 사건 현장의 CCTV 녹화본처럼, "에이전트가 무슨 생각을 했고, 어떤 도구를 썼으며, 화면에 무엇이 떴는지" 처음부터 끝까지 기록된 전체 타임라인입니다.
에이전트가 문제를 해결하는 동안 발생한 모든 상태, 생각, 행동, 관찰의 순차적 시계열 기록 τ = (o1, a1, o2, a2, …, oT)입니다. Reflexion 에이전트는 이 궤적 전체를 검토하여 실패 원인을 분석합니다.
그라운딩 Grounding (현실 접지)
외부 연동
💡 비유로 이해하기
탁상공론만 하던 사람이 실제 현장에 나가 두 눈으로 실태를 확인하고 팩트를 발 디딜 땅(Ground)에 단단히 고정시키는 것입니다.
언어 모델의 내부 추상적 표현이나 생성 텍스트를 실제 물리적 환경, 데이터베이스의 정확한 수치, 최신 웹 검색 결과 등 검증 가능한 현실 세계의 실체와 일치시키는 과정입니다. ReAct는 외부 API 관찰을 통해 환각을 억제합니다.
행동 공간과 관찰 공간 Action Space (A) & Observation Space (O)
수학적 모델
💡 비유로 이해하기
게임기 패드에 있는 버튼들의 종류(조이스틱, A버튼, B버튼 = 행동 공간)와 게임기 모니터 화면에 출력되는 영상(관찰 공간)입니다.
에이전트가 취할 수 있는 모든 유효 조작 명령어들의 집합 A과 환경이 이에 반응하여 반환하는 모든 감각/텍스트 출력의 집합 O입니다. ReAct는 여기에 언어 공간 L(생각)을 행동 공간의 일부로 확장했습니다.
도구 호출 Tool Calling / Function Calling
API 연동
💡 비유로 이해하기
계산이 필요할 때 머리로만 끙끙대지 않고 계산기 앱을 실행하고, 날씨를 모르면 기상청 웹사이트 API를 호출하는 능력입니다.
언어 모델이 텍스트로 정해진 포맷(예: JSON, 함수 시그니처)의 호출 명령을 출력하면, 시스템이 이를 가로채 실제 외부 프로그램(계산기, 검색엔진, Python 인터프리터 등)을 실행하고 그 결과를 다시 모델의 입력으로 넣어주는 기능입니다.
🪞 4. 기억, 반성 및 메타인지 (Reflexion & Memory)
리플렉션 Reflexion
자기반성 에이전트
💡 비유로 이해하기
시험에서 오답을 냈을 때, 채점 결과를 보고 "아, 내가 이 공식에서 마이너스 부호를 빠뜨렸구나. 다음번엔 부호를 꼭 검토하자"라고 '오답 노트'를 적어두고 다음 시험에 대비하는 우등생의 학습법입니다.
가중치를 업데이트하지 않고, 실패한 궤적에 대해 자연어로 된 자기비판(Self-reflection)을 생성하여 장기 기억 버퍼에 저장하고, 후속 시도(Trial)에서 이를 프롬프트로 재참조하여 실수를 스스로 바로잡는 에이전트 아키텍처입니다.
관련 논문: Reflexion 논문 전문
메타인지 Metacognition (자각과 자기평가)
고차 인지
💡 비유로 이해하기
"내가 무엇을 알고 무엇을 모르는지", "내 논리가 어디서 허점이 있었는지"를 한 걸음 물러서서 객관적으로 내려다보는 상위 1% 인지 능력입니다.
자신의 사고 과정 자체를 대상화하여 관찰하고 검토하는 능력입니다. Reflexion의 Self-Reflection 모듈은 실패한 궤적을 제3자 입장에서 평가하여 "내가 왜 틀렸는지"를 분석합니다.
언어적 강화학습 Verbal Reinforcement Learning
학습 이론
💡 비유로 이해하기
선수가 실수했을 때 말없이 점수만 깎는(-10점) 대신, 코치가 다가와서 "방금 스윙할 때 팔꿈치가 너무 들렸어. 다음엔 팔꿈치를 붙여봐"라고 구체적인 말(Verbal feedback)로 교정해주는 방식입니다.
전통적인 강화학습(RL)이 수치형 스칼라 보상(R ∈ ℝ)과 그래디언트 역전파를 통해 신경망 가중치를 학습시켰던 것과 달리, 풍부한 의미 정보를 담은 자연어 피드백 신호를 보상으로 사용하여 모델의 행동 정책을 인컨텍스트로 최적화하는 기법입니다.
관련 논문: Reflexion 논문 섹션 2
행동자-평가자-반성자 분업 구조 Actor-Evaluator-Self-Reflection Triad
아키텍처 모듈
💡 비유로 이해하기
직접 연기하는 배우(Actor), 연기를 채점하는 심사위원(Evaluator), 그리고 "다음 무대에선 이 감정선을 보완하자"고 피드백을 주는 연기 지도자(Self-Reflection)의 3인 1조 팀플레이입니다.
Reflexion의 핵심 3대 모듈:
  • Actor: 환경과 상호작용하여 행동 궤적을 산출하는 역할
  • Evaluator: 결과물의 정답 여부나 유닛 테스트 통과 여부를 검증하고 점수를 매기는 역할
  • Self-Reflection: 실패 원인을 진단하고 다음 시도에 적용할 구체적 개선 조언을 텍스트로 생성하는 역할
관련 논문: Reflexion 모듈 상세
에이전트 메모리 시스템 Working Memory & Episodic Memory
기억 구조
💡 비유로 이해하기
컴퓨터의 RAM(작업 메모리: 지금 당장 열려있는 창)과 하드디스크(에피소드 기억: 지난번 프로젝트의 오답 노트와 노하우 파일)의 관계입니다.
  • 단기/작업 기억(Working Memory): 현재 진행 중인 세션 내의 최근 대화 및 궤적(τt). 컨텍스트 윈도우 크기에 제한을 받음.
  • 장기/에피소드 기억(Episodic Memory): 이전 시도나 과거 상호작용에서 얻은 교훈, 반성 텍스트(srt), 또는 벡터 DB에 임베딩되어 영구 보관되는 경험 데이터베이스.
🛡️ 5. 지식 아키텍처 및 안전성 (Architecture & Safety)
파라메트릭 지식 vs 비(非)파라메트릭 지식 Parametric vs Non-Parametric Knowledge
지식 표현
💡 비유로 이해하기

  • 파라메트릭 지식(Parametric): 모델 사전학습 시 수천억 개의 신경망 가중치(파라미터) 속에 굳어진 정적 지식. 업데이트가 불가능하고 환각이 발생할 수 있음 (CoT가 주로 의존).
  • 비파라메트릭 지식(Non-parametric): 위키피디아, 벡터 DB, 외부 웹사이트 등 외부 소스로부터 실행 시점에 동적으로 주입되는 지식 (ReAct가 활용).
